# 픽셀 캐릭터 제작 기법 조사와 이미지 생성 계획

현재 제작 논의는 [Vault의 캐릭터 비율과 픽셀 아트 제작](../../Assets/Documentation/RoguelikeDesign/07%20Unity%20기술/캐릭터%20비율과%20픽셀%20아트%20제작.md)과 [캐릭터와 무기 분리 제작](../../Assets/Documentation/RoguelikeDesign/07%20Unity%20기술/캐릭터와%20무기%20분리%20제작.md)에서 갱신한다. 이 문서는 상세 기법 조사 기록이다.

조사일: 2026-10-07 (한국 시간)  
상태: 논의용 조사 메모. 디자인·해상도·방향 수·전투 수치는 미확정.  
범위: 공개된 작가 본인 튜토리얼과 Aseprite 공식 문서, 현재 Hero V2의 구조를 바탕으로 한 제작 제안.

2026-10-08 갱신: [공격 표현을 기준으로 한 비율 재설계](action-first-character-proportions-2026-10-08.md)를 우선한다. 인체 등신, 32×64 규격, 실제 높이 32/40px를 출발 조건으로 제한하지 않는다. 강조할 공격 부위와 화면 점유율을 먼저 정한다.

이번 작업의 결과는 조사와 제작 계획이다. 새로운 이미지 생성, 애니메이션 제작, Unity 구현 및 비교 실험을 수행한 결과가 아니다. 아래의 ‘프로젝트 적용’과 수치 후보는 자료를 토대로 한 제안이며, 사용자 확정 사항으로 취급하지 않는다.

## 1. 현재 프로젝트에서 출발할 지점

이전 검토에서 확인한 V2는 64×64 캔버스에 실제 캐릭터 높이가 약 32픽셀이고, 4방향마다 대기 4장·걷기 6장·공격 6장을 사용한다. 원본은 7레이어이지만, 게임 출력에서는 머리·몸통·다리·망토가 합쳐지고 팔과 무기가 함께 출력된다.

- `Assets/Art/Characters/HeroV2/README.md`: 원본·출력 규격.
- `Assets/Art/Characters/HeroV2/GenerateHeroV2.lua`: 도형과 관절 좌표로 포즈를 만들고 출력하는 현재 생성기.
- `Assets/Scripts/Training/TrainingHeroAnimationSet.cs`: 방향별 프레임 수가 고정된 재생 데이터.
- `Assets/Scripts/Training/TrainingPlayerView.cs`: 공격 중 걷기 표시를 대체하는 현재 재생 구조.
- `Screenshots/HeroV2/FourDirections.png`, `AttackKeyposes.png`, `InGame.png`: 이번 논의에서 살펴본 이미지.

현재 생성기는 포즈와 레이어를 빠르게 구성하는 데 유용하다. 다만 참고 일러스트의 매력을 원·선·사각형 배치만으로 옮기면, 머리 실루엣·관절의 겹침·옷의 면·재질 표현을 섬세하게 통제하기 어렵다. 이 부분은 현재 결과에 대한 판단이다.

우선순위 제안은 ‘실루엣과 비율 → 단순한 몸의 동작 → 팔·무기의 연결 → 색과 명암 → 장식과 효과’다. 프레임 수와 이미지 크기 증가는 앞 단계의 품질을 확인한 뒤 결정한다.

## 2. 조사한 기법과 사용할 위치

아래 설명은 작가들의 방법을 요약한 것이다. 절대 규칙으로 보지 않고, 우리 게임에서의 사용 범위를 오른쪽 열에 제안했다.

| 기법 | 자료에서 확인한 요점 | 프로젝트 적용 제안 |
| --- | --- | --- |
| 큰 색면으로 스케치하기 | 같은 색의 연결된 픽셀 덩어리인 클러스터로 큰 형태부터 잡고 점차 다듬는다. 외딴 픽셀은 의도한 강조에도 쓸 수 있다. [Saint11: Cluster Sketching](https://saint11.art/pixel_art_articles/article2/) | 머리·가슴·다리·무기를 먼저 큰 덩어리로 읽히게 만든다. 버클·눈·금속 반짝임은 나중에 추가한다. |
| 실루엣과 볼륨 | 얇고 경직된 형상은 입체감이 약해지며, 불필요한 유사 색을 줄이면 읽기 쉬워질 수 있다. [Derek Yu: Common Mistakes](https://www.derekyu.com/makegames/pixelart2.html) | 검은 실루엣만으로 얼굴 방향, 무기 종류와 공격 자세를 구분할 수 있는지 본다. 팔과 몸 사이에 읽을 수 있는 공간을 확보한다. |
| 윤곽선 정리 | 의도하지 않은 선 길이의 급변과 튀어나온 픽셀을 정리한다. 모든 계단 모양이 오류인 것은 아니다. [Derek Yu: Basics](https://www.derekyu.com/makegames/pixelart.html) | 칼날·머리 외곽·어깨를 우선 정리한다. 캐릭터를 단순한 직각 도형으로 바꾸는 방식의 과도한 정리는 피한다. |
| 선택적 외곽선 | 부위와 빛에 따라 외곽선 색을 조절하여 내부가 잘게 끊어져 보이는 문제를 줄인다. [Derek Yu: Basics](https://www.derekyu.com/makegames/pixelart.html) | 외곽은 어두운 유채색을 후보로 두고, 얼굴·팔의 내부 경계는 재질의 그림자색으로 표현한다. 밝고 어두운 바닥에서 함께 비교한다. |
| 팔레트와 색상 이동 | 밝기뿐 아니라 색상·채도의 관계를 조절해 색상 단계를 구성한다. 작가의 수식이나 색 수가 공통 정답은 아니다. [SLYNYRD: Color Palettes](https://www.slynyrd.com/blog/2018/1/10/pixelblog-1-color-palettes) | 피부·천·금속의 명암 단계를 공유 팔레트에 기록한다. 같은 색상에 검정만 섞는 방식과 색상도 이동시키는 방식을 비교한다. |
| 명암과 재질 | 가장자리부터 안쪽으로 밝아지는 일률적인 명암은 형태를 흐리게 만들 수 있다. 반짝이는 표면은 집중된 하이라이트로 표현할 수 있다. [Derek Yu: Common Mistakes](https://www.derekyu.com/makegames/pixelart2.html), [Saint11: Glossary](https://saint11.art/blog/glossary/) | 천은 넓고 차분한 면, 칼날은 큰 밝기 차이와 좁은 반사면으로 구분한다. 얼굴과 칼날의 밝기가 서로 경쟁하는지 확인한다. |
| 밴딩과 수동 안티앨리어싱 | 중간색을 배치해 곡선을 부드럽게 만들 수 있지만 과하면 흐려지고 색 띠가 강조된다. [Saint11: Anti-Alias and Banding](https://saint11.art/pixel_art_articles/article5/) | 내부 곡선에만 제한적으로 비교한다. 수동 중간색 배치와 Unity의 Bilinear 필터를 별개로 취급한다. 투명 경계의 반투명 테두리는 배경별로 검사한다. |
| 디더링 | 색을 패턴으로 섞어 명암·질감을 표현한다. 과하면 노이즈가 된다. [Saint11: Glossary](https://saint11.art/blog/glossary/) | 작은 주인공의 피부·옷에는 우선 적용하지 않고, 넓은 환경 재질이나 큰 초상화에서 필요성을 판단한다. |
| 작은 움직임의 표현 | 픽셀보다 작게 움직이는 듯한 미세 애니메이션은 정교한 작업이 필요하다. [Saint11: <1 Pixel Movement](https://www.patreon.com/saint11/posts/1-pixel-movement-7652033) | 대기 동작의 가슴·어깨·머리카락 일부를 시험한다. 무작위 밝기 변화가 ‘호흡’으로 보인다고 가정하지 않고 반복 재생으로 확인한다. |
| 핵심 포즈와 시간 배분 | 공격을 준비·빠른 궤적·팔로스루·회수 등으로 나누고, 무기마다 유지 시간을 달리한다. [SLYNYRD: Attack Animation](https://www.slynyrd.com/blog/2025/5/23/pixelblog-56-top-down-character-attack-animation) | 대검의 무게는 몸의 회전과 검의 지연으로 표현한다. 타격 시점과 조작 반응성을 함께 보고 준비 시간을 조절한다. |
| 방향별 일관성 | 같은 자리에서 방향 그림을 순환해 보면 나란히 놓았을 때 놓친 비율 오류를 찾을 수 있다. 비대칭 장비는 단순 반전으로 보존되지 않는다. [SLYNYRD: Top Down Character](https://www.slynyrd.com/blog/2025/3/24/pixelblog-55-top-down-character-animation) | 발 기준점을 고정한 회전 미리보기를 만든다. 주손·옷 여밈·머리 가르마가 바뀌는지 확인한다. |
| 움직임에서 디테일 정리 | 기본 몸 위에 장비를 더하고, 재생 중 깜빡이는 디테일은 단순화할 수 있다. [SLYNYRD: Animation Part 3](https://www.slynyrd.com/blog/2025/10/2/pixelblog-58-top-down-character-animation-part-3) | 정지 확대 화면과 정상 속도 게임 화면을 함께 본다. 망토·버클·칼날 하이라이트를 각각 켜고 끄며 산만함의 원인을 찾는다. |

픽셀 크기·팔레트·표현 방식은 게임 월드 안에서 일관되게 유지하는 편이 좋다. UI는 별도의 표현 영역으로 설계할 수 있다는 Saint11의 접근을 참고한다. Kenney UI 때문에 캐릭터의 등신과 색 수까지 똑같이 제한할 필요는 없지만, 한 화면에서의 조화는 확인해야 한다. [Saint11: Consistency](https://saint11.art/blog/consistency/)

## 3. 이미지 생성과 제작 방식 비교

이 표의 평가는 자료를 바탕으로 한 프로젝트용 판단이다. 생성 모델 간 품질 비교나 실측 성능 결과가 아니다.

| 방식 | 잘 맞는 용도 | 확인하거나 보완할 점 | 제안 |
| --- | --- | --- | --- |
| 이미지 생성으로 디자인 후보 → Aseprite에서 픽셀 원본 제작 | 외형 탐색, 실루엣·색·무기 조합 비교 | 실제 작은 크기로 옮길 때 특징을 선택하고 픽셀을 정리해야 함 | 우선 추천 |
| 선택한 픽셀 기준 그림을 참조해 방향·포즈 후보 생성 | 새 각도나 핵심 포즈의 초안 | 신체 크기, 손, 장식, 팔레트, 픽셀 격자와 기준점의 일관성을 매번 확인 | 제한된 포즈부터 시험 |
| Aseprite에서 프레임별 직접 제작 | 정확한 픽셀 제어, 움직임 연결, 부위별 원본 보존 | 숙련도와 편집 시간이 필요 | 최종 정리의 기준 |
| 단순한 3D 인체·무기로 동작 참고 생성 → 픽셀로 정리 | 대각선, 무기 원근, 양손 파지, 복잡한 회전 | 모델링·리깅 준비가 필요하고 출력만으로 최종 픽셀 표현이 완성되지 않음 | 방향 작업이 병목일 때 후보 |
| 좌표·도형·회전으로 절차적 생성 | 인체 초안, 포즈 가이드, 기준점, 시트 배치 | 미세한 실루엣과 명암을 계속 수식으로 보정하면 관리가 어려워짐 | 보조 도구로 사용 |

3D 참고의 구체적인 사례로 Saint11은 거친 형태를 회전시켜 참고를 만들고, Aseprite에서 작은 크기와 색으로 줄인 뒤 다시 그린다. 우리 프로젝트에서는 검의 원근과 손잡이 연결을 이해하기 위한 선택지로 해석한다. 캐릭터 전체를 즉시 3D로 전환할 근거는 아니다. [Saint11: Using 3D Models as Reference](https://saint11.art/blog/3d-ref/)

큰 이미지의 축소에는 정보 손실이 있다. 정수 배율로 확대된 진짜 픽셀 원본을 복원하는 작업과, 큰 일러스트를 작은 픽셀 아트로 변환하는 작업을 구분한다. 후자는 윤곽과 색면을 새로 판단해야 한다. [Saint11: Scaling Pixel Art](https://saint11.art/blog/scaling/)

## 4. 제안하는 실제 제작 순서

### A. 제작 기준을 먼저 작성

- 시점: 현재 게임에 맞는 탑다운 3/4 시점 후보. 정면을 보는 3/4 방향과 위에서 보는 투영을 구분하여 적는다.
- 화면: 현재 설정을 기록하되, 캐릭터·공격·적이 함께 보이는 점유율을 먼저 비교한다. 320×180을 고정 조건으로 두지 않는다.
- 픽셀 밀도: 현재 32 PPU는 비교 기준의 하나다. 선택한 화면 점유율과 필요한 디테일에 맞춰 환경과 함께 다시 정할 수 있다.
- 비율: 얼굴 강조 / 손과 무기 공간 확보 / 전신 동작 강조 후보를 비교한다. 인체 등신은 필수 조건이 아니다.
- 세계관 의상: 기존 판타지 모험가 / 현대의 탑 공략자 / 중장갑 전사도 미확정이다.
- 광원 방향, 팔레트, 외곽선, 주손, 발 기준점, 무기 크기 기준을 한 장에 기록한다.

### B. 디자인 후보를 한 개체씩 생성

동일한 자세·시점·배경 조건으로 세 가지 후보를 만들고, 각 후보의 차이는 비율이나 의상 실루엣처럼 비교 가능한 항목으로 제한한다. 투명 배경이 필요한 출력은 실제 알파 투명도를 요청한다. 체크무늬가 그림에 포함된 상태를 투명 출력으로 취급하지 않는다.

처음부터 여러 방향과 수십 장의 애니메이션이 든 완성 시트를 요청하면 어느 부분에서 비율·정체성이 바뀌었는지 수정하기 복잡하다. 한 포즈의 기준 그림을 선정한 뒤 범위를 넓히는 순서를 제안한다. 이는 이번 제작 전략이며 모든 모델의 실패율에 대한 주장이나 시험 결과는 아니다.

### C. 실제 픽셀 크기에서 기준 그림을 확정

몸의 비율과 화면 점유율을 고른 뒤 필요한 실제 픽셀 높이를 비교한다. 32px / 40px에 한정하지 않는다. 셀은 투명 여백을 포함한 작업 공간이며 캐릭터 자체의 높이를 뜻하지 않는다. 칼날이 잘리면 셀 여백을 늘리고, 캐릭터를 함께 확대하지 않는다.

생성 도구에 적은 ‘32px’, ‘16색’, ‘같은 위치’는 희망 조건이다. 출력이 그 조건을 정확히 지켰다는 보장으로 사용하지 않는다. 실제 크기, 격자, 색상, 알파와 발 위치를 확인한 뒤 픽셀 원본을 만든다. 큰 이미지에 작은 칸을 씌우는 작업만으로 완료 처리하지 않는다.

팔레트는 기본 캐릭터 12~20색 정도를 첫 비교 범위로 제안한다. 이는 하드웨어 제한이나 확정 규격이 아니다. 색 수보다 각 색이 하는 역할, 면의 구분, 배경 대비를 우선한다. 효과의 색과 반투명도는 별도 규칙으로 관리할 수 있다.

### D. 장식이 적은 몸으로 대표 동작 완성

선택한 과장 비율의 정면·측면·대각선 몸을 만들고, 제자리 대검 공격과 이동 중 공격을 비교한다. 발의 접지, 골반 이동, 어깨 회전, 주손·보조손 위치, 칼끝의 이동 경로를 먼저 확인한다. 실제 사람의 팔다리 길이를 강제하지 않는다. 이후 의상·머리·망토를 얹는다.

대기 4장·걷기 6장·공격 6~8장은 작은 시험의 출발점으로만 둔다. 반복된 프레임으로 수를 채우지 않는다. 참고 자료의 검·망치 시간 값을 우리 게임의 대검 밸런스로 그대로 채택하지 않는다.

### E. 선택한 캐릭터를 참조하여 한 항목씩 수정

선택한 기준 그림을 항상 참조하고, ‘무기 길이만 변경’, ‘뒤 방향만 제작’, ‘준비 자세만 변경’처럼 수정 단위를 제한한다. 매번 머리·키·의상·색·주손의 유지 조건을 반복한다. 수정 출력은 별도 버전으로 보관한다.

방향은 4방향과 8방향을 비교한다. 8방향도 연속 조준의 모든 각도를 표현하지는 않는다. 실제 공격 방향과 보이는 무기가 어긋나는 정도를 게임 안에서 확인한다. 무기 그림은 각도별 원본과 연속 회전의 장단점을 비교하며, Pixel Perfect 설정이 임의 회전의 형태를 자동으로 정리해 준다고 가정하지 않는다. [Saint11: Consistency](https://saint11.art/blog/consistency/)

### F. Aseprite 편집 원본에서 내보내기

최종 편집 원본은 `.aseprite`, 게임용 결과는 PNG와 애니메이션 메타데이터로 관리한다. 생성기는 편집 원본을 덮어쓰는 기능과 내보내기 기능을 분리하는 방향을 제안한다. 기존 스크립트의 실제 수정은 후속 구현 과제다.

Aseprite는 태그로 동작 범위를 구분하고, CLI로 태그·레이어와 JSON 정보를 출력할 수 있다. 내보내기 시 빈 레이어를 생략하더라도 프레임 참조가 밀리지 않도록 메타데이터를 기준으로 연결해야 한다. [Aseprite: Tags](https://www.aseprite.org/docs/tags/), [Aseprite: CLI](https://www.aseprite.org/docs/cli/)

## 5. 부위 분리와 애니메이션 구조에 대한 판단

‘편집 레이어’, ‘게임에서 교체할 부품’, ‘독립 재생할 동작’을 각각 설계한다. 머리카락을 편집 레이어로 나눴다고 반드시 별도 게임 렌더러가 필요한 것은 아니다.

| 단위 | 편집 원본 | 게임에서 필요한 기능 |
| --- | --- | --- |
| 상체·머리 | 수정 편의를 위해 레이어 분리 | 조준·공격에 맞춘 포즈 묶음으로 합칠 수 있음 |
| 골반·다리 | 독립 레이어와 접지 기준 | 전진·후진·옆걸음과 공격 중 이동 |
| 팔·손 | 무기와 분리하여 양손 위치 확인 | 무기 계열별 포즈, 몸과 무기의 앞뒤 겹침 |
| 무기 | 손잡이 기준점, 칼끝 가이드 | 외형 교체, 공격 자세, 방향별 표시 |
| 망토·장식 | 몸의 동작을 확인하며 별도 편집 | 필요한 경우 지연 동작이나 교체 |
| 그림자·검기 | 각각 분리 | 접지 표현, 공격 가독성, 효과 끄기 비교 |

동작은 전체 인체를 보며 설계한 뒤 분리해서 출력한다. 상·하체를 별개로 생성하여 임의로 합치면 허리와 팔 연결이 어긋날 수 있으므로, 공통 골반 기준과 함께 쓸 수 있는 자세 조합을 정한다. 제자리 공격과 이동 공격은 하체의 역할이 다르다.

완성된 합성 PNG에서 가려진 손·팔·검의 픽셀은 복원되어 있지 않다. 이미지 생성으로 부품을 다시 만들더라도 가려진 부분의 모양을 별도로 검토해야 한다. ‘레이어로 분리해 달라’는 프롬프트만으로 편집 가능한 Aseprite 레이어가 전달됐다고 판단하지 않는다.

프레임 재생 데이터에는 동작 이름, 방향, 시간, 공통 기준점, 손 위치, 무기 앞뒤 순서가 필요하다. Aseprite Slice의 이름·피벗과 JSON 출력을 기준점 전달에 활용할 수 있지만 Unity에서 읽는 연결부는 별도 구현 대상이다. [Aseprite: Slices](https://www.aseprite.org/docs/slices/)

## 6. 생성용 프롬프트 초안

아래는 다음 제작 때 선택한 디자인으로 채워 사용할 초안이다. 이번 조사에서 실행하지 않았다. 작가 이름 대신 필요한 형태·명암·픽셀 특성을 명시한다.

### 기준 캐릭터 후보

```text
용도: 탑다운 2D 액션 로그라이크의 플레이어 캐릭터 디자인 후보.
개체: [논의에서 선택한 정체성·의상], [선택한 머리·몸·손의 배분], [선택한 주손].
시점: 게임의 고정된 탑다운 3/4 투영. 전신이 잘리지 않는 [선택한 방향]의 중립 자세.
형태: 작은 게임 화면에서 머리·몸통·양다리·팔의 경계가 읽히는 실루엣.
색과 면: [선택한 팔레트], 큰 색면, 재질마다 읽히는 명암 단계, 절제된 장식.
무기: [선택한 계열과 길이 비율], 실제로 손이 잡는 손잡이, 몸과 구분되는 칼날.
출력: 한 캐릭터, 실제 투명 배경, 문구·격자선 없는 이미지.
제약: 렌즈 효과, 부드러운 블러, 외곽의 빛 번짐, 불필요한 작은 점 질감 제외.
검토 목적: 선택한 게임 화면 점유율과 이후 정할 실제 픽셀 높이에서 공격 부위가 읽히는 디자인.
```

마지막 줄은 디자인을 평가할 조건이다. 생성 이미지의 실제 출력 해상도를 보장하는 옵션이 아니다.

### 포즈 하나를 수정하는 요청

```text
입력 1: 선택한 캐릭터 기준 그림. 외형·팔레트·비율의 기준.
입력 2: 선택한 과장 비율의 포즈 가이드. 동작과 관절 위치의 기준.
변경: [방향]을 향하는 대검 공격의 [준비/타격/팔로스루/회수] 포즈 하나.
유지: 인물 정체성, 머리 크기, 몸통 길이, 의상, 주손, 시점, 빛, 픽셀 표현.
동작: [골반·어깨·주손·보조손·검끝의 의도한 위치와 힘의 방향].
출력: 캐릭터 전체가 보이는 한 포즈, 실제 투명 배경.
검기: 이번에는 몸과 칼날을 평가할 수 있도록 제외.
```

팔레트 변경과 동작 변경을 한 번에 섞지 않고, 선택한 기준에서 한 가지씩 수정한다. 생성 결과의 정확도는 아래 기준으로 확인한다.

## 7. 후속 제작의 확인 기준

이 목록은 수행 예정인 확인 항목이며, 이번 조사에서 통과한 검사 결과가 아니다.

### 정지 이미지

- 실제 게임 크기와 정수 배율 확대에서 모두 형태가 읽히는가.
- 검은 실루엣에서도 방향·무기 종류·준비와 타격 자세가 구분되는가.
- 회색조에서 얼굴·몸·무기·배경의 중요도가 구분되는가.
- 흰색·어두운색·실제 바닥색 위에서 투명 테두리가 어색하지 않은가.
- 캐릭터, 적, 환경의 픽셀 밀도와 디테일 수준이 맞는가.
- 검의 크기, 양손 간격과 팔 길이가 서로 납득되는가.

### 애니메이션

- 같은 발 기준점에서 방향을 순환할 때 키·몸통 폭·손이 튀지 않는가.
- 정상 속도에서 하이라이트·장식이 깜빡이지 않는가.
- 이동 중 공격할 때 다리와 상체의 동작이 연결되는가.
- 준비부터 타격까지 무기 궤적이 이어지며 손에서 분리되지 않는가.
- 검기를 꺼도 힘을 모으고 휘두르고 회수하는 흐름이 보이는가.
- 무기와 팔이 몸 뒤·앞으로 넘어가는 순서가 자연스러운가.
- 게임의 공격속도가 바뀌어도 필요한 포즈가 읽히고, 취소 시 잘못된 효과가 남지 않는가.

### 데이터와 게임 연결

- 출력 크기·색상·알파·프레임 수·태그 범위·시간·피벗이 의도와 맞는가.
- 빈 효과 프레임도 동작 타임라인의 위치를 유지하는가.
- 피격 판정과 이동 충돌은 발 기준 논리 좌표를 따르는가.
- 보이는 공격 범위와 실제 판정 범위가 납득할 만큼 맞는가.
- 아트 편집만으로 공격력·사거리·유효 시간이 바뀌지 않으며, 확정된 전투 시간에 시각 동작을 연결하는가.
- 재생성과 내보내기가 수동 편집 원본을 예기치 않게 덮어쓰지 않는가.

## 8. 다음 논의와 작은 제작 실험

먼저 캐릭터 정체성과 비율을 정한다. 그다음 아래의 작은 실험으로 제작 방식을 선택하는 것을 제안한다.

1. 같은 시점과 자세의 실루엣 3안. 비교할 차이를 기록한다.
2. 선택안의 화면 점유율과 이후 필요한 실제 픽셀 높이를 비교. 환경과 함께 본다.
3. 정면·측면·대각선의 과장된 몸 비율과 대검 핵심 포즈.
4. 정상 속도와 느린 속도의 공격 1회, 검기 켜기·끄기 비교.
5. 같은 공격을 제자리와 이동 중에 재생하는 합성 시험.
6. 만족한 구조를 기준으로 방향과 장비 수를 늘린다.

약 3등신과 기존 해상도는 재설계의 기본 조건에서 제외한다. 정체성, 방향 수, 무기 길이는 여전히 미확정이다. 전체 시트 생성 전에 기준 캐릭터와 한 번의 공격이 마음에 드는지 확인하는 것이 다음 결정 지점이다.

## 9. 참고 자료의 범위

핵심 참고는 Derek Yu의 기본·실수 교정 튜토리얼, Saint11의 클러스터·명암·스케일링·3D 참고 글, SLYNYRD의 색상과 탑다운 애니메이션 연재, Aseprite 공식 문서다. 각 절의 링크는 해당 설명을 뒷받침하는 원문이다.

교재의 무기 수치와 예제 프레임 수는 특정 작가의 예시이며 프로젝트 표준이 아니다. 인터넷 예제의 이미지나 유료 원본 파일은 프로젝트에 가져오지 않았다. 자료는 기법 연구에 사용했으며, 모델·도구의 자동 생성 품질은 아직 비교하지 않았다.
