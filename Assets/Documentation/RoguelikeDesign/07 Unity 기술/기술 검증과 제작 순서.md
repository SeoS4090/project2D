# 기술 검증과 제작 순서

## 첫 기술 프로토타입

사용자 결정으로 첫 제작은 훈련장 기반 전투 테스트 환경으로 한다. [[07 Unity 기술/훈련장 기반 기술 프로토타입]]에서 공통 게임 코드·시험 도구·초기화·측정의 역할을 정리한다. 완성형 전투 프레임워크를 한 번에 만들기보다 훈련장에 기능을 단계적으로 붙인다. Unity 프로젝트 생성·코드 구현·시각 자료 제작은 후속 작업이며 아래 체크는 아직 수행하지 않았다.

| 순서 | 제작 범위 | 확인할 결과 |
| --- | --- | --- |
| 1 | Unity 기준 버전·URP 2D·카메라·훈련장 골격·공통 Actor 생성·시험 초기화 | 발 좌표·PPU·정렬·충돌·인스턴스 수명 |
| 2 | 걷기·전방향 조준·충전 대시·공통 게임 시간 | 정지·입력 예약·병행 상태의 관찰 가능 |
| 3 | 대검 한 타격→연격, 허수아비·분리 WeaponView·Sprite 슬래시·판정 Gizmo·피해 기록 | 대시·밀려남 중 궤적·판정·속도 배율 일치 |
| 4 | 일반 적과 강공격 정예 1종, 슈퍼아머 표시·예고·피격 플래시 | 상태 시작/종료·범위·외곽선·중첩 가독성 |
| 5 | 원거리 발사·장탄·재장전, 검과 방패/패링 중 하나 | 공통 틀에 다른 행동과 독립 투사체 연결 |
| 6 | 훈련장 빌드/외형 교체·신화 양식·효과 한 가지·풀 반복 시험 | 리소스·논리 출처·쿨타임·시험 초기화와 측정 |

훈련장 다음에는 실제 방 전환·보상·해금·저장/로드의 통합 시나리오를 수행한다. 훈련장 재현만으로 실전 흐름의 검증을 완료하지 않는다. 각 단계의 실제 전투 시험은 [[05 검증과 확장/프로토타입 범위와 검증]]을 따른다. 기술 표시 검사를 게임 규칙 검증 완료로 대체하지 않는다.

## 제작자가 보는 디버그 정보

Actor ID/세대, 실행 ID·타격 순번·단계·정규화 진행, 현재/고정 조준, 이동 채널, 자원과 예약, 적중 대상, root, 상태와 표시 키를 화면 또는 로그에서 관찰한다. Gizmo는 논리 원점·활성 HitShape·차폐·이동 궤적·예고 원본을 표시한다. 애니메이션이 한 프레임 생략돼도 사건과 판정 시각을 추적할 수 있어야 한다.

## 데이터 연결 후보

기존 Weapon·AttackStep·WeaponAction·MotionProfile·EnemyArchetype·Resource·ImpactProfile·StatusProfile 정의를 우선 재사용한다. 아래는 Unity 표현의 참조 후보이며 기존 게임데이터 명세를 확정 변경한 것은 아니다. 실제 Excel 행과 코드 타입은 아직 없다.

| 후보 정의 | 주요 참조와 의미 |
| --- | --- |
| ActorVisual | visual ID, Prefab Resource ID, 몸체 방향 세트·소켓 정의·상태 표시 프로필 |
| WeaponVisual | visual ID, Sprite/Prefab Resource ID, 소켓 기준·전후 표시, 신화 양식 리소스 |
| ActionVisual | visual ID, 기존 motion_id와 연결, 준비/실행/후딜의 정규화 곡선·프레임·연출 큐 |
| StatusVisual | 표시 ID, 실제 상태 키와 면역 종류, outline·아이콘·플래시·부착 VFX·우선순위 |
| Resource 매핑 | 기존 Resource ID에서 Sprite·Material·Prefab·음향 에셋으로 연결, 경로·타입 확인 |

타격 범위·기간·배율은 기존 전투 정의의 원본을 읽고 연출 테이블에 별도 피해 시간·범위를 복제하지 않는다. 장식의 독립 수명과 행동에 맞춰 늘어나는 수명은 구분한다. 각 큐는 타격/단계의 정규화 시각에 연결하며 절대 시각 고정이 필요한 입력·보호 기간은 기존 규칙을 유지한다. 런타임 실행/적중/root/재생 핸들은 정적 Excel의 콘텐츠 ID가 아니다.

PPU·기준 해상도·아트 방향 수·최대 대상 규모·플랫폼은 단순 전투 밸런스 행으로 취급하지 않는다. 아트·렌더링 설정과 기기 목표를 기술 프로필로 결정한다. 실제 공격 값·콘텐츠 수와 변형은 이후 Excel에서 관리한다.

## 이후 기술 범위

초기 이후에는 방 생성·Tilemap/장애물·적 경로·마을 화면·플레이어용 훈련장 해금/과제와 프리셋·입력 재설정·HUD·체크포인트·리소스 로딩·오디오를 기존 기획과 연결한다. Addressables·외부 애니메이션 도구·ECS·커스텀 렌더 패스 등은 해당 요구가 확인될 때 선택한다. 최초부터 모든 확장 기반을 구축하는 일정으로 잡지 않는다.

## 기술 검토 질문

T01 아트 방향·몸체/무기 제작 방식, T02 외곽선 범위·라이팅과 상태 합성, T03 대상 기기·아트 스케일·성능 목표의 현재 선택 조건은 [[06 결정과 기록/현재 검토할 기획 질문]]에서 관리한다. 추천 후보를 사용자의 최종 결정으로 표현하지 않는다.

## 실제 검증할 항목

- [ ] 공격속도와 다양한 프레임률에서 사건·연출·판정의 진행이 일치한다.
- [ ] 대시·공격·밀려남 병행, 기절·사망·준비 취소에서 화면이 상태와 일치한다.
- [ ] 렌더 프레임 또는 애니메이션 프레임을 건너뛰어도 비용·적중이 누락/중복되지 않는다.
- [ ] 뒤 방향·긴 무기·좁은 벽·여러 캐릭터의 가림이 조작을 오해하게 하지 않는다.
- [ ] Sprite Atlas·Outline·Sprite Lit·Pixel Perfect 조합에서 결과를 확인한다.
- [ ] 필수 예고·아이콘과 장식 VFX의 동시 부하에서 가독성이 유지된다.
- [ ] 풀 재대여·방 전환·저장 로드에 이전 객체의 지연 사건과 표시가 남지 않는다.
- [ ] 같은 데이터 변경을 Excel 원본·Unity 변환물·리소스 매핑에 추적할 수 있다.
- [ ] 대상 기기에서 CPU·GPU·GC·draw/batch·풀 고갈·메모리를 측정한다. 아직 목표 수치와 결과를 채우지 않는다.
