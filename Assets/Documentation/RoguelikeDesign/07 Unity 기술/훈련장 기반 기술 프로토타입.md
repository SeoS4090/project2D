# 훈련장 기반 기술 프로토타입

## 사용자 결정과 범위

첫 제작은 훈련장으로 한다. 캐릭터·무기·전투·시각효과를 한 공간에서 반복 시험하는 것을 개발의 출발점으로 삼는다. Unity 6.3 LTS `6000.3.18f1` + URP 2D 기준을 유지한다. 아래 도구 구성과 상세 제작 단계는 이 방향을 구현하기 위한 추천 초안이며 실제 제작·실행 검증은 아직 없다.

플레이어용 훈련장의 해금·과제·영구 상태 격리·측정 규칙은 [[04 마을과 성장/런과 훈련장 보강 기준#R03 훈련장 해금·과제·불러오기|R03]]을 따른다. 개발용 전체 콘텐츠 선택은 내부 테스트에서만 제공하는 별도 도구다. 플레이어에게 미해금 콘텐츠를 기본 제공하는 결정으로 해석하지 않는다.

## 공통 게임 코드 위의 시험 환경

TrainingSession이 시험 설정·생성·초기화·측정·상황 전환을 관리한다. ActorFactory·ActorRuntime·행동 시간·판정·피해·상태·VFX는 실전과 같은 모듈을 사용한다. 훈련장 전용 피해 계산이나 전용 대시 처리로 분기하지 않는다. 실전으로 옮길 때는 방과 콘텐츠 설정을 연결한다.

개발 패널은 데이터 ID로 무기·표적·시나리오를 선택하고 공개된 시험 명령으로 실행한다. 진행 중인 공격의 내부 상태나 공유 정의 에셋을 임의로 덮어쓰지 않는다. 장비·빌드 편집은 안전한 정지/초기화 경계에서 기존 안전 편집 계약을 따른다. 측정이 시작된 뒤 조건이 바뀌면 기존 측정을 종료·표시하고 새 측정으로 구분한다.

개발용 시험 세션은 영구 재화·발견·런 기록을 쓰는 서비스와 격리한다. HP·마나·장탄·충전은 기본 시험에서 실제 소비·회복 규칙을 따른다. 영구 재화를 소비하지 않는다는 R03을 전투 자원 무한으로 해석하지 않는다. 자원 무한·무적 같은 개발 보조 옵션은 별도 표시하고 일반 규칙 검증에 사용한 결과와 구분한다.

## 단계적으로 붙일 기능

| 단계 | 훈련장 구성 | 시험할 내용 |
| --- | --- | --- |
| 첫 골격 | 빈 공간·벽·카메라·플레이어 생성·초기화 버튼 | 발 좌표·정렬·이동·조준·대시·벽 충돌 |
| 첫 전투 | 기본 대검·허수아비·무기 그림·슬래시·피해 기록 | 연격·공백·공격속도·판정·실제 피해 사건 |
| 적 대응 | 일반 적·강공격 정예·행동 켜기/끄기 | 예고·슈퍼아머·경직·피격·대시 무적 |
| 무기 확장 | 단검·창·검과 방패·원거리 순차 추가 | 패링·방어·찌르기·탄 소비·재장전 |
| 빌드 시험 | 시험용 카드/양식/신성 선택·상태 조합 | 데이터 연결·효과 연쇄·외형·표시 합성 |
| 부하·재현 | 다수 적·투사체·저/고 프레임 조건·조건 프리셋 | 성능·중복 적중·풀 재사용·재현 가능한 비교 |

첫 골격부터 모든 무기·대장간 UI·프리셋 저장을 완성할 필요는 없다. 전체 콘텐츠 시험이 가능한 플랫폼으로 확장하되 첫 성공 기준은 플레이어가 실제로 움직이고 대검으로 허수아비를 공격하며 결과를 확인하는 것이다.

## 권장 도구 구성

- 무기·표적·적 행동·환경 시나리오 선택과 시험 시작/초기화.
- 실제 피해 이벤트 기반 총 피해·최대 피해·DPS·출처별 집계. 최초에는 총 피해와 사건 로그부터 붙이고 R03의 측정 시작·종료 규칙으로 확장한다.
- 공격 단계·고정 조준·자원 예약·대시 충전·상태 키·적중 ID·root·셰이더 표시 키 확인.
- 판정·피격 영역·벽 차폐·논리 원점·예고 범위를 보이는 Gizmo/디버그 표시.
- 동시 상태, 준비/실행 중 피격, 대시 중 공격, 연속 패링 등을 반복하는 시험 시나리오.

측정과 시나리오에는 데이터 버전·무기/빌드 ID·대상 방어 조건·시간 구간·보조 옵션·프리셋/RNG 조건을 남겨 비교한다. 카메라·바디 프레임·VFX가 다른 결과를 보여도 실제 전투 사건 기록을 기준으로 원인을 추적한다.

## 초기화 계약의 추천

초기화는 시험 종료 경계에서 실행한다. 입력 예약·행동·투사체·상태·root·예고·잔상·측정·지연 콜백을 정리하고 새 시험 세대 ID를 만든다. 기존 R03의 HP·마나·충전 등의 시작 상태와 선택한 프리셋으로 다시 생성한다. 이전 세대 사건이 새 시험 표적에 적용되지 않게 한다. 불러오기와 초기화는 실제 플레이 검증 대상이다.

## 훈련장 검증과 통합 검증

훈련장에서 전투·표현·상태·장비·연쇄·충돌의 대부분을 검증한다. 방 전환·저장·죽음은 개발용 시나리오로 일부 재현할 수 있다. 실제 던전 생성·적 배치·보상/정산·해금·방 이동·체크포인트/재실행·실전 카메라/가림은 실제 게임 흐름에서도 확인한다. 훈련장에서 통과했다고 이 통합 검증을 완료 처리하지 않는다.

## 미실시 확인 항목

- [ ] 같은 정의·피해 사건·행동 모듈을 훈련장과 실전 어댑터가 사용한다.
- [ ] 기본 시험은 실제 전투 자원 규칙을 따르고 개발 보조 옵션이 식별된다.
- [ ] 초기화·반복 생성 후 이전 적중·투사체·셰이더 상태가 남지 않는다.
- [ ] 측정에 공백·이동·장전이 포함되고 자동 효과와 치명타가 중복 집계되지 않는다.
- [ ] 개발 패널은 영구 해금·재화·런 기록을 변경하지 않는다.
- [ ] 프리셋·데이터 버전·난수 조건으로 시험을 다시 실행할 수 있다.


## Scribble Dungeons 훈련장 타일 교체 — 2026-10-08

현재 적용 기준은 [[07 Unity 기술/Scribble Dungeons 타일 용도와 Tiled 적용]]이다. 아래는 최초 시도 기록이다. 당시 기록의 64 PPU는 실제 임포트 확인이 빠진 의도값으로, UI 자동 임포터가 16 PPU로 덮어쓴 것이 후속 조사에서 확인됐다. 바닥 포함 벽 회전과 레이어 혼용도 수정했다. 현재는 원본 시트·60px 배치 간격·투명 벽·TMX 명시적 충돌을 사용하므로 아래 초기 칸 수와 충돌 범위 유지 안내를 현재 기준으로 적용하지 않는다.

사용자가 추가한 Art/Kenney/scribble-dungeons 이미지로 훈련장을 교체하도록 요청했다. project2D의 TrainingGround 배경을 64px 바닥·벽·모서리 이미지로 변경했다. 내부 299칸과 외곽 76칸을 편집 가능한 두 Tilemap으로 구성하고 시작·표적 표시 대비를 조정했다. 원본 PNG·CC0 라이선스와 기존 벽 충돌 범위·카메라·캐릭터·허수아비·전투 입력은 유지한다. 타일 임포트는 64 PPU, 한 칸 1월드 단위이며 캐릭터 32 PPU를 변경하지 않았다. 이 배율은 현재 훈련장 적용값이고 T03 전체 제작 규격의 결정은 아니다.

Game > Training Ground > Apply Scribble Dungeon 메뉴로 열린 훈련장에 다시 적용하고, 훈련장 재생성에도 연결했다. 생성 Tile 에셋은 Assets/Art/Runtime/TrainingDungeon/Tiles에 있다. 실제 WASD 이동으로 네 벽의 충돌 차단과 Tilemap 구성을 확인한 7개 검사, 새 맵에서 연격·충전 회전 베기 21개 검사를 통과했다. 씬 재적용 시 환경 중복이 없는 것도 확인했다. Screenshots/TrainingDungeon/Verification.md, RuntimeValidation.json, Applied.png, Gameplay.png에 근거를 보관했다. 전체 던전 생성·방 전환·저장 검증과 T01–T03은 후속이다. [[07 Unity 기술/마네킹 모션 제작과 검증]]
