# 공통 리그 애니메이션 실험과 전환

## 패키지 이관 — 2026-10-13

리그 세 스크립트·공유 모션 40개·마스크·기본 재질은 Packages/com.projectar.character-rig로 meta 보존 이동했다. [[07 Unity 기술/캐릭터 패키지 분리와 재사용]]에서 실제 배포와 검증을 확인한다. 아래 날짜별 실험의 이전 파일 경로·결과는 당시 기록이며 이번 이관 후 기존 훈련장 회귀 완료를 뜻하지 않는다.

## 현행 구현 정리 — 2026-10-11

사용자가 캐릭터 조작·렌더링 확정 후 이전 코드와 프리팹 정리를 요청했다. 현재 경로는 **TrainingPlayerController → TrainingPlayerView → CommonCharacterRig → AzureVanguard.prefab**이다. 조작·충돌·전투 수치는 유지하고, 쓰이지 않는 렌더 인자와 시트 재생 분기를 제거했다.

- 훈련장은 AzureVanguard 프리팹을 직접 참조한다. 이전 비활성 시트 조립 컴포넌트와 렌더러 6개를 제거했다.
- 공통 40개 클립·마스크·재질은 GUID를 유지해 `Assets/Art/Characters/SharedRig/`로 옮겼다. `SharedRigBuilder`는 공통 모션만 생성한다. 씬 재생성·아틀라스 빌드도 현재 캐릭터를 사용한다.
- 초기 Frames/HeroV2/ActionBlockout/MannequinMotion/Assembly, 옛 설치 도구·Character Maker·프레임 카탈로그/공급자, blue-tunic/bronze-armor 프리팹, 비교 창·씬·입력 및 관련 검증 도구를 Unity 프로젝트에서 퇴역시켰다.
- F6 검토는 idle/walk/attack/attack_reverse/attack_heavy/charge/spin/dash 8개를 실제 클립 길이와 샘플률로 재생한다. F7 모션, F8 방향, F9 정지, F10 속도, 마침표는 한 샘플 전진이다. 피격·기절·사망 시트 폴백은 제거했고 해당 공통 모션은 후속이다.
- 기존 JSON 발행·저장/로드 계약은 설계에 남아 있지만 옛 제작 창은 현재 사용하지 않는다. 공통 리그용 제작자·카탈로그 구현 완료를 뜻하지 않는다.

보관 위치는 프로젝트 루트 `CharacterAuthoring/Archive/2026-10-11-character-cleanup/`이다. ZIP은 변경 전 1,011개 파일과 메타를 보존하고 manifest에 해시와 퇴역 목록을 기록한다. 공유 원본을 포함한 보관 수이며 삭제 파일 수가 아니다. 이전 원본은 별도 복사본에서 복구·비교한다. Azure 제작의 그림자 공급 원본도 `CharacterAuthoring/AzureVanguard/shadow-source.aseprite`로 독립시켰다.

### 정리 후 실행 검증

Unity 6000.3.18f1 재컴파일 오류/경고 0. 구조·미리보기 84개, Azure 외형 10개, Play 입력·전투·검토 26개 통과. 15,624 자세 최대 양손 오차 0.000007645 논리 px. 씬·프리팹 Missing Script 0, 퇴역 GUID 497개 잔존 참조 0, 시험 구간 런타임 오류/예외 0. 아틀라스 재생성도 통과했다. 재로드 시 무효 Playable과 남은 클립 캐시가 충돌하는 문제를 수정했다. 초기 영웅 원본과 프레임 생성/내보내기 스크립트·메타 6개도 Supplemental에 추가 보관했다. 허수아비 원본은 현행 자산으로 유지했다.

현재 재실행 도구는 `Tools/Art/ValidateCharacterCleanup.cs`, `ValidateAzureVanguard.cs`, `ValidateCommonRigCombat.cs`, `ValidateRetiredCharacterFiles.py`다. 결과는 `Screenshots/CharacterCleanup/`와 `Screenshots/AzureVanguard/Validation.json`이다. 독립 플레이어 빌드·다수 Actor 성능 시험은 이번에 수행하지 않았다.

이하 rig-lab-0.1/0.2와 2026-10-10 외형 제작 내용은 당시 구현·검증 기록이다. 그 안의 보존·폴백·이전 도구 실행 안내는 현행 지침이 아니다. Obsidian이 실행 중이지 않아 프로젝트 Markdown을 파일 편집으로 갱신하고 문서 점검 스크립트를 사용했다.


## 연속 조준과 훈련장 적용 — rig-lab-0.2

2026-10-10 “후속작업 진행” 요청으로 연속 조준과 실제 훈련장 전투 연결을 구현했다. 현재 제작 규칙은 [[07 Unity 기술/캐릭터 제작과 조립 구조#연속 조준과 양손 연결 — CH13]]이다. 아래 rig-lab-0.1 본문은 2026-10-09 첫 실험 기록이며 당시의 “런타임 IK 없음/훈련장 미교체/4방향만 지원”은 현재 상태가 아니다.

### 현재 사용법과 구현

- TrainingGround 씬을 Play하면 공통 리그가 기본 캐릭터 표현이다. 기존 이동·마우스 조준·좌클릭 콤보·우클릭 차지/회전 공격·대시 입력을 그대로 사용한다.
- Game → Characters → Common Rig → Open Comparison에서 **연속 조준**을 켜고 **조준 각도 0–360**을 조절한다. 대기·걷기·베기·역베기·강베기·차지·회전 공격과 독립 하체 보행/대시를 비교한다. 연속 조준을 끄면 이전 4방향 클립 비교로 돌아간다.
- 상체 모션 7종×4방향과 하체 3종×4방향, 총 40개 Transform 클립을 생성한다. 연속 조준 경로는 오른쪽 기준 클립을 공유하고 무기 궤적/양팔만 조준에 맞게 보정한다. 4방향 비교 자료는 유지한다.
- TrainingPlayerView가 기존 컨트롤러의 구간 시간과 고정 공격 방향을 읽는다. TrainingPlayerController의 판정·마나·이동 규칙은 이번 작업에서 수정하지 않았다.
- 기존 CharacterAppearance 시트 조립 컴포넌트는 훈련장에서 비활성화했다. 기존 프레임 에셋/참조와 제작 창은 보존되어 있으므로 메모리 절감·카탈로그 이관 완료를 주장하지 않는다. 새 표현은 프리팹의 직접 참조이며 기존 JSON 제작 창에서 발행한 외형이 새 리그로 자동 적용되는 상태가 아니다.
- F6 모션 검토의 지원 동작은 공통 리그로 재생한다. 피격·기절·사망 등 미이관 동작은 기존 시트 미리보기로 표시한다. 이 경로는 전투를 멈춘 아트 검토이며 새 상태 모션을 구현한 것으로 세지 않는다.

Unity 6000.3.18f1에서 컴파일 오류/경고 0. 연속 리그 검사 20개, 어댑터/비교 UI 검사 9개, 실제 Play 전투 회귀 24개가 통과했다.

### 남은 범위

CH13의 공통 규격 연속 조준·손/소매·방향 경계·가림과 제작 책임은 검증/정리했다. 피격·기절·사망의 공통 리그 모션, 제작자 카탈로그/JSON/로드 수명의 리그 이관, 별도 체형/그립, 최종 아트·상태 효과·밀집 전투 가독성, 성능/실제 텍스처 상주량과 독립 빌드 실행은 후속이다. 이번 실행은 Editor Play 검증이다.

최종 로그 점검에서 기존 최소 HUD의 제거된 조작 안내·차지 표시·미니맵·텍스트 참조 예외를 발견해 TrainingHudView/TrainingGroundHud의 선택 항목을 null 검사했다. 최종 전투 회귀 24개에는 시험 구간 런타임 오류/예외 0건 검사가 포함된다. Unity 생성 씬/프리팹의 빈 YAML 필드 공백은 직접 수정하지 않았다.

Obsidian 프로세스가 없는 환경임을 확인하여 프로젝트 Markdown을 일반 파일 도구로 수정했다. 개인 Vault와 SPUM 원본은 수정하지 않았다.

## 요청과 결론

사용자가 SPUM식 공통 애니메이션과 시트 재생의 차이를 지적하고, 같은 리그에 외형 두 세트를 끼워 걷기/대검 공격을 재사용하는 시험의 진행을 요청했다. 실제 AnimationClip·Animator·Playables를 사용하는 비교 실험을 구현했다. **같은 관절 규격이면 외형 그림을 바꿔도 같은 모션을 재사용할 수 있음**을 확인했다.

새 제작 방향은 [[07 Unity 기술/캐릭터 제작과 조립 구조#체형·모션과 제작 방식 — CH03 및 T01]]을 따른다. 이 실험은 모든 전투 모션의 교체나 최종 캐릭터 디자인 완료가 아니다. 기존 TrainingGround와 프레임 기반 제작 창은 비교용으로 보존했다.

## 직접 확인하는 방법

- Unity 메뉴 **Game → Characters → Common Rig → Open Comparison**: 두 외형을 나란히 보고 상체 동작·조준 방향·이동 방향·하체 보행/대시·정수 보정·정지/진행도를 바꾼다.
- **Open Play Lab**: CommonRigLab 씬을 열고 Play한다. 다른 씬에 저장하지 않은 편집이 있으면 열기를 중단한다.
- Play 입력: 1 대기, 2 걷기, 3 대검 베기, 방향키 상체 방향, WASD 하체 방향, Tab 보행 켜기/끄기, 왼쪽 Shift 하체 대시, Space 일시 정지/재개.
- 두 화면은 이동/공격 애니메이션 비교용이며 실제 Actor 이동·타격·마나·런/개인 저장을 호출하지 않는다.

## 무엇이 달라졌는가

| 항목 | 실험 구현 |
| --- | --- |
| 외형 | 푸른 튜닉·청동 갑옷, 실루엣/장식과 대검 너비가 다른 두 세트 |
| 그림 | 외형당 파츠 종류 8개×방향 4개 = 32개 정적 Sprite 참조 |
| 모션 | 상체 대기/걷기/베기와 하체 대기/걷기/대시, 각 4방향 = 공유 클립 24개 |
| 계층 | Upper에 머리·몸통·주/보조 팔 2관절·무기/그립, Lower에 양다리 |
| 재생 | Animator 출력에 상체/하체 마스크를 둔 AnimationLayerMixerPlayable, 외부 시간이 클립 샘플을 결정 |
| 외형 선택 | 외형 또는 방향을 바꿀 때만 Sprite 선택; 매 애니메이션 갱신에는 Transform만 변함 |
| 양손 | 손 그림은 무기 그립에 붙고 팔 끝은 같은 그립에 닿도록 공통 관절 곡선 작성 |
| 픽셀 | 32 PPU·Point·mip 없음·비압축, 시험 씬은 URP PixelPerfectCamera 320×180 기준 UpscaleRenderTexture |
| Atlas | 정적 파츠를 공유 Atlas V2에 포장, 회전/Tight 없음·padding 4·최대 1024 |

PNG에 여러 파츠가 들어 있어도 애니메이션 시트라는 뜻은 아니다. 이번 PNG의 행은 머리/몸통/팔 등의 **파츠 종류**, 열은 **방향**이다. 시간을 따라 다음 셀을 재생하지 않는다. 클립에는 Sprite 교체 곡선이 없다.

팔의 곡선은 에디터 제작 보조 계산으로 생성했다. 고정 길이 8px+8px인 두 관절에서 작성한 그립 경로를 풀고 일반 Transform 곡선으로 저장한다. 플레이어에서 IK를 계산하거나 손·무기 길이를 늘려 맞추지 않는다. 생성 후 .anim은 Unity Animation 창에서 볼 수 있는 실제 에셋이다. Generate Experiment 재실행은 생성 자료를 덮어쓰므로 수동 수정할 아트/클립은 별도 원본으로 분리해야 한다.

Unity 6000.3.18f1에서 스크립트 컴파일 오류/경고 0. 정적/샘플/렌더 검사 15개, 실제 Play 입력 검사 10개를 통과했다.

## 확정한 경계와 후속

CH12의 비교 조건은 충족했다. 공통 호환 리그의 Transform 모션을 기본으로 하고 방향·원근/특수 실루엣만 정적 그림으로 보완한다. 외형마다 432개 모션 그림을 만드는 방식은 기본 파이프라인으로 확장하지 않는다.

**이번 실험은 4방향 조준이다.** 기존 게임의 연속 마우스 조준을 그대로 표현하는 구현은 아니다. CH13에서 연속 조준 오프셋과 양손 연결의 규칙을 확정한 뒤 실제 전투로 이관한다. 새 리그가 모든 조준 각도를 이미 지원한다고 말하지 않는다.

후속 구현은 CH13, 역베기/강베기/모으기/회전/피격/기절/사망의 공통 클립, 제작자 카탈로그/저장 공급자의 리그 파츠 연결, 기존 TrainingPlayerView 어댑터 교체, 전투 회귀와 다수 Actor 성능 시험이다. 기존 프레임 시험 코드를 지금 삭제하지 않는다. 데이터/저장/로더 계약은 재사용하고 프레임 배열 전제의 표현·임포트만 이관한다.

## 상세 SD 외형 제작 — Azure Vanguard / 2026-10-10

사용자의 고퀄리티 SD 캐릭터 시트/게임 적용 요청에 따라 금발·청록 눈·푸른 제복·은색 견갑·금색 테두리의 대검 모험가를 제작했다. 작업용 이름은 Azure Vanguard / 청람의 선봉이다. 명칭과 디자인은 이번 제작 판단이며 사용자 최종 아트 승인이나 게임 설정 확정으로 취급하지 않는다.

내장 image_gen으로 4방향 턴어라운드와 분리 파츠를 생성하고 몸통의 중복 견갑/소매를 보정했다. 원본은 프로젝트 루트 CharacterAuthoring/AzureVanguard/azure-vanguard-source-v1.png, 프롬프트 전문은 같은 폴더 generation-prompts.md다. 생성 결과는 일러스트형 SD 아트이며 수작업 저해상도 픽셀 클러스터 제작으로 표현하지 않는다. SPUM 원본은 사용/수정하지 않았다.

Aseprite에서 원본의 실측 영역을 분리·정규화하고 8레이어×4방향 편집 파일과 정적 파츠 시트를 만들었다. 실제 게임은 정적 파츠를 공통 클립으로 움직인다. 이미지에 전신이 모여 있는 원본/확인용 시트와 런타임 애니메이션 프레임을 혼동하지 않는다.

- Assets/Art/Characters/AzureVanguard/azure-vanguard.aseprite: 편집 원본.
- 같은 폴더 azure-vanguard-parts.png: 머리/몸통/상완/전완/손/다리/무기/그림자, 4방향 32개 Sprite.
- AzureVanguard.asset / AzureVanguard.prefab: 공통 외형/독립 캐릭터. 기존 SharedMotions.asset을 그대로 공유한다.
- AzureVanguard.spriteatlasv2: 기존 빌드 전 생성기에 연결한 전용 콘텐츠 묶음. 최대 1024·Point·mipmap 없음·비압축·회전/Tight 없음이다. 실제 빌드 페이지/상주 메모리 측정은 미실시다.
- Tools/Art/PrepareAzureVanguard.lua 및 ImportAzureVanguard.cs: 원본 분리·Sprite 피벗/안정 ID·에셋 생성·훈련장 연결 절차.

아트 텍스처는 128 PPU로 32-unit 공통 리그의 4배 밀도를 쓴다. 캐릭터 월드 크기·팔 길이·그립 간격·전투 수치는 바꾸지 않았다. SpriteRect는 빈 여백을 줄이고 기존 피벗의 실제 좌표를 보존한다. 새 씬/인스턴스에서 첫 샘플 이전 외형을 교체할 때 렌더러 참조를 준비하도록 CommonCharacterRig.SetAppearance도 보강했다.

TrainingGround의 공통 리그 외형을 새 캐릭터로 교체했다. 7모션×72조준각×31시점, 15,624 샘플의 양손 최대 오차는 0.000007645 논리 px였다. 외형 검사 10개와 실제 Play 전투 24개가 통과했고, 전투 시험 중 오류/예외는 0건이었다. 결과는 Screenshots/AzureVanguard/Validation.json 및 CombatValidation.json이다.

같은 폴더 CharacterSheet.png는 실제 리그에서 렌더한 대기/보행/베기/회전 4행×4방향 확인용 시트, AzureVanguard-motion.gif는 관찰용 느린 확대 재생, Training.png는 실제 훈련장 화면이다. 확인용 PNG는 선형 렌더 readback을 sRGB로 변환하여 게임 화면과 색을 맞췄다.

이번 범위는 상세 외형 한 종 제작/연결이다. 피격·기절·사망의 공통 리그 모션, 제작자 JSON 카탈로그 이관, 출하 아트 승인, 다른 해상도/효과/다수 Actor 가독성·독립 빌드는 후속이다. Obsidian이 실행되지 않아 프로젝트 Markdown을 파일 도구로 갱신했다.
