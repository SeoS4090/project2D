# 캐릭터 제작과 조립 구조

## 구현 현황 — 2026-10-11

사용자가 조작·렌더링 구조를 확정하고 이전 구현 정리를 요청했다. 공통 리그 전용 표현과 AzureVanguard 직접 프리팹 참조로 정리했다. 이전 시트·조립/발행 도구·비교 프리팹은 보관본으로 이동했으며 현행 게임과 제작 도구에서 읽지 않는다. 구조 계약의 변경이 아닌 구현 정리이고, 제작자 카탈로그/저장·로드 계약의 공통 리그 이관은 여전히 후속이다. 현재 파일·검증·보관 위치는 [[07 Unity 기술/공통 리그 애니메이션 실험과 전환#현행 구현 정리 — 2026-10-11]]를 따른다.


## 목적과 결정 경계

사용자 직접 결정은 SPUM 비교를 바탕으로 새 구조를 기획하고, 제작자용 조립부터 시작하여 추후 플레이어 외형 변경으로 확장하는 것이다. 2026-10-09 “기획서의 의문점이 없을 때까지 계속 수정” 요청에 따라 CH02–CH10과 종속 기술 선택 T01–T03을 설계 위임으로 결정했다. 아래 세부 선택은 사용자의 개별 발언이 아니라 위임에 따른 설계 판단이다.

이 문서는 제작자 조립, 런타임 생성·장착·수명, 플레이어 외형 변경, 데이터 발행·저장·관리의 현재 계약이다. CH12 공통 리그와 CH13 연속 조준의 시험을 완료하고 훈련장 전투 표현에 연결했다. 실제 콘텐츠·상태 모션·제작자 카탈로그 이관·아트 완성도·성능 측정은 별도 후속이다. 전체 게임 구현 완료를 뜻하지 않는다.

기존 이동/조준 분리, 준비 추적/실행 방향 고정, 대시와 공격 병행, 전투 상태가 판정·비용을 결정하는 원칙을 유지한다. 주무기는 런 중 교체하지 않는다. 외형 변경으로 장비·태그·자원·피격 영역을 바꾸지 않는다. [[02 전투/기본 전투 원칙]] · [[03 빌드와 무기/덱과 성장 보강 기준]] · [[04 마을과 성장/런과 훈련장 보강 기준]]

## 공통 리그 애니메이션 재검토 — CH12

사용자가 SPUM처럼 모션을 공통으로 사용하는 방식의 확인과 비교 실험 진행을 요청했다. 같은 리그에서 서로 다른 외형 둘의 걷기/대검 공격·4방향·상하체 분리·양손 연결을 실행했다. [[07 Unity 기술/공통 리그 애니메이션 실험과 전환]]에 15개 샘플/렌더 검사와 실제 Play 입력 10개의 근거를 기록했다.

**결정:** 공통 피벗 리그와 Transform AnimationClip을 기본 제작 방식으로 삼는다. 외형은 방향별 정적 파츠를 교체하고 특수 실루엣이 필요한 곳만 그림을 보완한다. 이는 사용자의 공통 애니메이션 의도에 따른 구현/설계 판단이며 최종 아트 품질을 뜻하지 않는다. 기존 시트 방식의 추가 확장은 중단한다. CH12 이후의 연속 조준/양손 표현은 아래 CH13 기준을 따른다.

### 로컬 원본 확인

SPUM 무료판의 Clip 폴더에 있는 애니메이션 10개 모두 m_PPtrCurves가 비어 있고 m_Sprite 교체 곡선이 없다. 몸/머리/팔/발/무기 피벗의 위치·회전·일부 크기 곡선을 재생한다. UnitSave의 고정 계층을 NormalAnimator가 움직이고, SPUM_Manager/SPUM_SpriteList가 그 계층의 SpriteRenderer에 외형을 끼운다. 이는 파츠를 피벗으로 움직이는 방식이며, 메시 변형/가중치 기반 스키닝을 확인했다는 뜻은 아니다.

반면 assembly-0.1의 VisualPiece.frames는 포즈별 Sprite 배열이고 CharacterAppearance.Render은 프레임 인덱스로 Sprite를 교체한다. 파츠/로딩은 공통화했지만 의상 모션 그림까지 공유하는 구조가 아니다. 현재 432개 포즈 슬롯을 참조하며 명시적 그림 재사용은 가능해도, 새 파츠가 자동으로 공통 관절 운동을 따라가지는 않는다.

### 재검토 제안과 완료 조건

제안은 **공통 피벗 리그 + 공통 동작 클립 + 방향/특수 포즈에 필요한 소수 파츠 그림**을 기본으로 시험하는 것이다. 옷/장비 파츠는 규격화된 피벗에 연결하며 AnimationClip이 매 프레임 외형 Sprite를 덮어쓰지 않도록 표현과 외형 선택을 분리한다. 공통 모션이라고 모든 체형·무기가 무조건 같은 클립을 쓰는 것은 아니다. 호환 체형/무기 계열 안에서 공유한다.

4방향(특히 뒤보기), 상체 조준과 하체 이동 분리, 대시 중 공격, 대검 양손 파지와 앞뒤 순서는 자체 설계가 필요하다. SPUM의 좌우 반전만 그대로 적용하면 현재 게임 요구를 충족하지 않는다. 공격의 준비/유효/회수 시간과 피해는 전투 상태가 계속 소유한다.

또한 현재 규칙의 “실시간 비정수 회전 금지”는 SPUM식 피벗 회전과 충돌한다. Point 필터나 Pixel Perfect 카메라가 회전한 픽셀의 계단 모양을 원천적으로 없애지는 않는다. 16각 그림 강제보다 **회전 허용 범위·정수 위치 보정·방향별 교체 그림·특수 포즈만 별도 그림**의 조합을 실제 화면으로 비교한 뒤 결정한다.

완료 조건은 동일 리그에서 걷기와 대검 공격 하나를 외형 두 세트에 적용하고, 4방향/반대 이동/양손 연결/픽셀 가독성을 비교하여 공통 리그와 프레임 그림의 경계를 확정하는 것이다. 이 요청에서는 소스 확인까지 했으며 새 리그 시험은 아직 실행하지 않았다. 검사·카탈로그·초안 저장·공유 로더·Atlas 분할은 유지 가능한 부분이고, frames 배열/프레임 임포터/표현 어댑터는 교체 후보로 구분한다.

## 제작자 우선과 플레이어 확장 — CH01 결정

최초 도구는 Unity Editor 제작 창이다. 체형/프리셋, 슬롯별 파츠, 색 영역, 방향/동작 미리보기, 검사 결과, 초안 저장·검증·발행을 제공한다. 신규/복제 → 초안 편집 → 방향·동작 확인 → 검사 → 발행 순서다. 플레이어 화면은 이후 동일한 조립 기능에 선택 정책과 개인 저장을 연결한다.

공통 검증·조립·표현은 UnityEditor API와 분리한다. 제작 도구만 원본 임포트·에셋 생성·프리셋 발행을 호출한다. 플레이어는 출하된 카탈로그를 읽고 개인 선택만 저장한다. 제작자는 미완성 초안을 보관할 수 있지만 필수 검사를 우회해 발행할 수 없다.

~~~mermaid
flowchart LR
    E[제작자 화면] --> EP[제작 정책]
    P[플레이어 화면] --> PP[해금과 장소 정책]
    EP --> D[편집 초안]
    PP --> D
    D --> V[공통 호환 검사]
    V --> A[공통 조립과 미리보기]
    A --> ES[제작자 프리셋 발행]
    A --> PS[개인 선택 확정]
    ES --> C[게임 카탈로그]
    C --> R[게임 표현]
    PS --> R
    G[이동과 전투 상태] --> R
    G --> H[판정과 비용]
~~~

저장 경로는 호출 주체로 제한한다. 두 화면이 같은 허용 조합을 선택하면 같은 그림을 만든다. UI가 선택을 숨기는 것과 확정 시 권한 검사는 별개이며, 확정 시 최신 해금·장비·카탈로그 상태를 다시 검사한다.

## 외형과 실제 장비 — CH02

의상은 능력치가 없는 외형이다. 피부/눈 색, 머리카락, 수염, 머리 장식, 상의, 하의, 등 장식을 플레이어 외형 대상으로 삼는다. 기본 몸체와 손/발 구조는 체형에 속하며 플레이어가 삭제하거나 크기를 조절하지 못한다. 이 구조를 위해 새로운 방어구 능력치 슬롯을 추가하지 않는다.

주무기·방패·보조 무기는 실제 Weapon/WeaponAction 정의가 선택한다. 플레이어 의상 화면에서는 읽기 전용이다. 검을 창처럼 보이게 하는 독립 무기 스킨은 초기 플레이어 기능에 넣지 않는다. 장인 양식은 현재 무기 표현 프로필을 바꾸고 신성은 별도 권능 효과를 제공한다. 둘을 의상 팔레트로 덮어쓰지 않는다.

제작자는 무기를 시험용으로 선택할 수 있다. NPC의 장식용 무기는 별도 decorative 역할이며 공격·방어 능력을 만들지 않는다. 실제 전투 장비로 사용하려면 논리 장비와 대응하는 프로필이 필요하다. 같은 외형의 복제는 실제 장비·해금을 복제하지 않는다.

런 중 주무기 교체 금지는 유지한다. 장인 강화로 같은 무기 표현이 바뀌면 기존 강화 확정 사건을 따른다. 장비 전환용 필수 표현을 미리 준비하고 로드 실패 시 해당 선택 확정을 보류한다. 이미 저장된 논리 장비를 복원할 때 시각 로드 실패를 이유로 장비나 비용을 롤백하지 않고 CH06 복구를 적용한다.

## 체형·모션과 제작 방식 — CH03 및 T01

최초 사람형은 SD 규격과 32 PPU를 유지하며 **공통 피벗 리그 + 공유 Transform AnimationClip + 방향별 정적 파츠**로 제작한다. 리그 ID/호환 버전이 같은 외형은 관절 길이·부착점·계층 경로를 공유한다. 외형마다 걷기/공격 프레임 그림 전체를 다시 만드는 것을 기본 절차로 두지 않는다. 새 체형이나 그립 규격은 별도 리그/호환 프로필로 분리한다.

상체는 머리·몸통·팔·양손·무기, 하체는 다리로 분리하고 별도 마스크/클립을 재생한다. 동작 클립은 외형 Sprite를 덮어쓰지 않고 Transform만 다룬다. 외형/방향 전환 때 선택한 파츠는 동작 재생 중 유지된다. 방향/원근·휘어짐·특수 실루엣처럼 강체 회전으로 충분하지 않은 부분은 명시적 그림/포즈 변형으로 보완한다. 모든 체형/무기 계열이 하나의 클립으로 해결된다고 가정하지 않는다.

몸 방향은 |x|>|y|일 때 좌/우, 그 외 위/아래이며 동률은 수직이다. 표현 어댑터는 영벡터에서 마지막 유효 방향, 최초는 아래를 쓴다. 논리 조준/판정은 연속 벡터이며 실행 중 고정 방향을 유지한다. 4방향 그림 선택과 연속 조준 표현은 분리하고 아래 CH13의 공통 궤적과 팔 보정을 적용한다.

실시간 회전의 일괄 금지와 무기 16각 그림의 선행 강제는 기본 제작 규칙에서 해제한다. 공통 피벗의 회전을 허용하고 Point·정수 출력 해상도·표현 루트 보정을 함께 평가한다. 회전의 계단 모양은 남는다. 16각/특수 그림은 필요한 파츠의 보완 선택이다. rig-lab-0.1은 에디터에서 팔 곡선을 만들었고, rig-lab-0.2는 연속 조준을 위해 아래 CH13의 제한된 런타임 두 관절 보정을 추가했다.

상체 조준/공격과 하체 실제 이동/대시의 독립, 생명/제어 상태 우선, 전투의 준비/유효/회수 정규화 시간, 0초 구간 생략 원칙은 유지한다. AnimationClip/AnimationEvent가 피해·마나·장비 상태를 결정하지 않는다. 실행 이후 현재 마우스로 공격 방향을 바꾸지 않는다. 초기 실험 클립의 .6/.8초는 기술 시연 길이이며 전투 수치 원본이 아니다.

필수 동작은 대기·보행·대시·피격·기절·사망과 실제 무기 행동이다. 없는 동작을 대기로 덮어 발행하지 않는다. 현재 공통 리그는 훈련장의 대기/보행/베기/역베기/강베기/차지/회전/하체 대시에 연결했다. 피격·기절·사망과 정식 카탈로그 발행은 후속이다. 양손/소매는 리그 부착과 소켓 오차 검사를 받고 실제 그립이 맞지 않는 파츠를 늘리거나 크기를 자동 보정하지 않는다.

### 연속 조준과 양손 연결 — CH13

2026-10-10 후속 작업 요청과 기존 설계 위임에 따라 **방향별 몸 그림 + 기준 방향 공통 클립 + 연속 무기 회전 + 고정 길이 팔 보정**을 선택했다. 몸 전체를 조준 각도로 눕히거나 모든 조준각의 프레임 그림을 추가하는 방식은 사용하지 않는다.

- 모션 제작자는 기준 방향의 무기 위치·회전 궤적과 준비/유효/회수 구간을 만든다. 다른 외형도 같은 곡선을 읽는다.
- 리그는 어깨·팔 길이·양손 그립을 소유한다. 무기 궤적을 어깨 중심 주위로 조준 각도만큼 회전한 뒤 고정 길이 두 관절을 풀어 손에 연결한다. 손 그림은 몸 외형 소유지만 Transform은 무기 그립의 자식이다. 무기 크기나 팔 길이를 늘리지 않는다.
- 현재 시험 규격은 팔 8+8 원본 px, 어깨 중심 (0,17), 좌우 어깨 x=±4, 그립 간격 5px다. 양손 중점의 9.4px 범위가 모든 각도에서 도달 가능한 보수적 영역이다. 런타임은 범위 밖 궤적을 이 영역으로 제한하지만 제작 검사는 보정량이 발생하는 원본을 수정 대상으로 본다. 현재 작성한 일곱 모션의 검사 보정량은 0이다. 이는 체형 시험 규격이며 전투 수치가 아니다.
- 방향 경계에서는 몸 그림만 전환하고 무기 기준 클립은 전환하지 않는다. 가림은 무기 중점이 어깨 중심보다 위면 몸 뒤, 아래면 앞을 쓰므로 회전 공격도 앞뒤가 바뀐다. 특수 가림/변형이 필요한 새 파츠는 아트 제작자가 별도 그림·프로필을 만든다.
- 전투 어댑터는 준비 동안 추적한 방향과 실행/회복에 고정된 방향을 읽는다. 전투의 구간 진행도를 클립의 준비 0–0.32, 유효 0.32–0.70, 회복 0.70–1에 대응시킨다. 이 값은 현재 클립의 저작 구간이며 공격 지속시간 원본이 아니다. 하체 이동/대시는 독립적으로 재생한다.
- 표준 공통 리그/공통 그립에만 적용한다. 새 체형이나 그립 간격은 호환 프로필과 도달성·가림 검사가 필요하다. 최종 픽셀 가독성·상태 효과·다수 Actor 부하는 별도 검증한다.

## 소켓과 가림 — CH05

원본 좌표는 좌상단 원점, x 오른쪽/y 아래, 단위는 원본 픽셀이다. Unity 로컬 좌표는 ((x-footX)/PPU, (footY-y)/PPU)다. 원본 각도는 오른쪽 0도·시계방향 양수이며 런타임 각도로 변환 시 부호를 바꾼다. 단위 변환은 임포터 한 곳에서 수행한다. 논리 이동은 반올림하지 않고 표시 기준점만 픽셀 격자에 맞춘다.

주손 소켓과 무기 그립을 맞춰 배치한다. 보조손은 해당 pose/grip_profile의 두 번째 잡는 위치를 따른다. 주손·보조손 그림은 몸 쪽에 속한다. 그립 매핑 후 손과 손잡이의 오차가 원본 1px를 넘으면 발행을 막는다. 허용 범위를 벗어난 무기는 새 grip_profile과 대응 손 포즈를 제작한다. 손만 늘리거나 무기 크기를 자동 변경하지 않는다. 총구/칼끝은 시각 검증용이며 판정 원점은 논리 데이터가 결정한다.

| 슬롯 종류 | 점유와 교체 | 필수 여부 |
| --- | --- | --- |
| 기본 체형/몸 | 프로필 소유, 의상 화면 읽기 전용 | 필수 |
| 머리카락·수염·머리 장식·등 장식 | 슬롯별 한 파츠, 명시적 비움 허용 | 선택 |

| 주무기·보조 장비 | 논리 장비가 점유, 계열별 보조 슬롯 정책 | 해당 전투 정의에 필요하면 필수 |

한 파츠는 여러 렌더 조각을 가질 수 있다. 초기 복수 슬롯 의상은 지원하지 않고 상하의 세트는 두 Part ID를 묶은 프리셋으로 제공한다. 파츠 숨김은 전체 슬롯 삭제가 아니라 hair_front/hair_back/beard 같은 공개된 hide_group에만 적용한다. 초기 허용 관계는 머리 장식→머리카락/수염, 상의→기본 몸통/팔, 하의→기본 다리다. 무기/손/필수 몸체 전체를 숨기거나 역방향·순환 숨김을 지정하면 발행 실패다.

체형/버전 확인 → 점유 확인 → 필수 슬롯 채움 → 가림 계산 → 포즈 순서 계산으로 처리한다. 숨김은 매 조합에서 다시 계산한다. 투구 해제 시 기존 머리 선택이 복구된다. 장착 후보가 점유/그립 조건을 어기면 초안에 거부 이유를 표시하고 자동으로 다른 장비를 빼지 않는다.

포즈는 렌더 조각을 등 장식/뒤다리/뒤팔·뒤손·뒤무기/몸통/머리/앞다리/앞무기/앞손/앞장식 밴드에 배치한다. 밴드 내부의 순서도 정수로 명시하고 동률은 slot ID·piece ID 순으로 고정한다. 손이 무기보다 뒤로 가야 하는 포즈는 해당 밴드의 명시적 순서를 사용한다. 모든 포즈의 필요한 조각과 순서가 없으면 발행을 막는다. 해부학적 왼손과 카메라 기준 앞손을 혼동하지 않는다.

Actor 내부는 SortingGroup, Actor 간은 발 Y의 내림 깊이(아래쪽이 앞)와 고유 Actor ID 동률 규칙을 쓴다. 지면 그림자·위험 예고·독립 투사체는 별도 월드 계층이다. 긴 무기가 다른 Actor와 완벽히 교차 가림되는 것은 초기 범위 밖이며 판정과 예고가 가림으로 오해되지 않는지 시험한다.

## 원본·발행·데이터 계약 — CH04

아트 원본은 Aseprite, 포즈·소켓 명세는 원본과 함께 버전 관리하는 JSON, 제작자 외형 초안은 JSON으로 관리한다. 체형/파츠/모션/프리셋을 검증해 읽기 전용 Unity ScriptableObject 카탈로그를 생성한다. 카탈로그와 생성 Sprite는 파생 산출물로 수동 수정하지 않는다. 공통 Actor Prefab과 별도 Weapon Prefab은 조립 골격이며 외형 조합 원본이 아니다. 캐릭터별 모든 리소스를 복제하는 Prefab 양산을 하지 않는다.

Excel은 콘텐츠 ID·역할·해금 연결·가중치·기존 전투 수치를 소유한다. 아트 JSON은 호환·좌표·포즈·레이어를 소유한다. 한 필드를 양쪽에서 수동 작성하지 않는다. 임포트 결과는 버전 있는 ResourceCatalog를 통해 Resource ID를 Unity 참조에 매핑한다. 저장 파일에 경로·GUID·GameObject 참조를 넣지 않는다. 기존 MotionProfile은 전투 시간/이동 계약이며 순수 표현 VisualMotionSet과 구분한다.

| 데이터 | 필수 내용 | 검증과 읽는 시점 |
| --- | --- | --- |
| BodyProfile | body_id, compatibility_version, PPU, foot_origin, direction_rule, slot/hide_group 정의, 기본 의상/안전 프리셋 | 임포트·조립, 양수 PPU·필수 슬롯과 폴백 존재 |
| Part | part_id, revision, slot, supported_rig_versions, attachment/piece/direction_resource, 선택 pose_variant, palette_regions, hide_groups | 임포트·장착, ID 중복·빈 참조·순환 금지 |
| WeaponVisual | weapon_visual_id, family_id, rig_id, grip_profile_id, 부착/선택 variant 매핑, 장인 양식별 대응 | 장비 해석·조립, 논리 무기 계열과 일치 |
| VisualMotionSet | set_id, rig_version, action_key, phase/clip 키, upper/lower 마스크, 소켓과 가림 규칙 | 상태 재생, 모든 필수 행동·방향 지원 |
| AppearanceDraft | schema_version, draft_id, base_recipe_id/revision, body_id, 슬롯별 inherit/select/empty, palette 선택 | 편집, 선택 ID 검증; 필수 슬롯 empty 금지 |
| PublishedRecipe | recipe_id/revision, catalog_version, 해석된 최종 part/revision·색, body/motion 참조, dependency_hash | 발행·게임 생성, 미해결 inherit 없음 |
| AppearanceProfile | schema_version, profile_revision, base_recipe_id/revision, 최종 선택 part/revision·색, content_version | 개인 저장·복원, 승인된 버전 이행 필수 |
| VisualUnlock | part_id, unlock_key 또는 기본 제공, player_visible | 목록·확정, 영구 해금 상태에서 판정 |
| MigrationMap | from/to schema/content, old/new ID/revision, 사유 | 로드, 순환·다중 대상 금지, 각 버전 단계 순차 이행 |

ID는 유형 접두사+불변 키로 발급하고 이름 변경으로 재발급하지 않는다. ID 재사용을 금지한다. 발행 리비전은 불변이며 기존 발행본 수정은 새 리비전이다. 파일 경로 이동은 Resource 매핑만 변경한다. body compatibility 변경은 별도 버전, 파츠 픽셀/포즈 변경은 새 part revision이다. display_name은 로컬라이즈 키이며 식별에 쓰지 않는다. 실제 콘텐츠 목록과 값은 Excel/아트 제작 단계에서 채운다.

발행은 새 카탈로그를 별도 경로에 완성 → 모든 참조/필수 폴백/포즈/원본 해시 검사 → 일치하는 승인 미리보기 기록 확인 → 현재 카탈로그 포인터 교체 순서다. 실패하면 기존 발행본을 유지한다. 검토한 의존 해시가 달라지면 승인 상태를 무효화한다. 동시에 같은 초안을 편집한 경우 base_revision 비교로 덮어쓰기를 거부하고 다른 초안으로 저장하게 한다.

안전 프리셋·필수 모션·실제 장비 프로필은 게임 출하 검사에서 필수다. 출하 카탈로그는 미완성 초안과 도구 의존성을 포함하지 않는다. 리소스 로드는 IVisualResourceProvider 경계로 묶고 최초 구현은 빌드에 포함한 카탈로그 참조를 사용한다. 별도 다운로드·원격 카탈로그는 초기 범위에 넣지 않는다. 로더 교체가 저장 ID나 조립 입력을 바꾸지 않아야 한다.

## Atlas·로딩·메모리 — CH11

2026-10-09 사용자의 로딩 방식 질문과 보강 후 구현 요청에 따라, 초기 방식은 **파츠 조립 + 공유 SpriteAtlas V2 + 내장 카탈로그**로 결정한다. 캐릭터 전체를 미리 합성한 시트를 조합마다 생성하지 않는다. Atlas는 텍스처 포장이고 파츠 합성이 아니므로 Renderer 수나 드로우콜 하나를 보장하지 않는다.

| 리소스 묶음 | 초기 자료 | 분할 기준 |
| --- | --- | --- |
| 공통 체형 | 몸·손·다리·그림자 | 같은 체형의 함께 쓰는 기본 모션 |
| 의상/장식 | 출하 의상 묶음 | 같은 콘텐츠 묶음·지역·사용 수명 |
| 무기 | 대검 계열 | 무기 계열과 함께 쓰는 변형 |

하나의 거대한 전역 Atlas나 캐릭터별 복제 Atlas를 만들지 않는다. 최대 페이지 2048, Point·mipmap 없음·비압축·회전/Tight 없음·padding 4를 첫 설정으로 사용한다. 페이지 수가 늘면 실제 메모리를 기록하고 조정한다. RGBA32 2048×2048 한 페이지는 mip 없는 원시 픽셀만 약 16 MiB다. 작은 Sprite 하나를 선택해도 그 픽셀이 있는 텍스처 페이지의 비용이 발생하며, 다중 페이지의 실제 상주 범위는 빌드에서 측정한다.

제작 파이프라인이 Atlas를 생성하고 빌드 직전 동일 설정을 재검사한다. 런타임은 카탈로그의 안정 Sprite 참조를 사용하고 매 프레임 GetSprite로 복제하지 않는다. 생성 시 검증한 프리셋의 파츠 핸들을 대여하고, 준비된 렌더 트리를 한 번에 교체한다. 같은 카탈로그의 같은 리소스는 Actor들이 공유한다.

초기 내장 공급자의 마지막 핸들 반환은 캐시의 **논리 대여 해제**다. 카탈로그/씬의 직접 참조가 살아 있으면 Unity 텍스처가 자동 언로드된다고 주장하지 않는다. 파츠 교체 때마다 Resources.UnloadUnusedAssets를 호출하지 않는다. 지역별 실제 언로드가 필요한 규모에서는 IVisualResourceProvider 아래를 Addressables/번들 소유권으로 교체하고, 사용 중 핸들과 카탈로그 수명을 함께 관리한다. 현재 단계는 원격 다운로드나 스트리밍 구현이 아니다.

전체 캐릭터 bake는 측정 후 고정 외형 군집에만 검토한다. 독립 상하체·무기 표현과 장착 변경을 유지해야 하므로 초기 플레이어 경로에는 사용하지 않는다. 썸네일 bake는 게임 표현과 별도다.

### 구현 단계와 기존 자료의 경계

첫 구현은 도입 순서 1–3의 제작자/훈련장 수직 연결이다. 기존 마네킹의 프레임 파츠를 명시적 훈련 프로필로 이관하여 저장·조립·교체·공유·발행 검사를 실행한다. 기존 자료에는 16각 팔/손/소매와 독립 의상 원본이 없으므로 이를 지원한다고 기록하지 않는다. 훈련 프리셋 저장과 정식 출하 발행을 구분하고, 출하는 CH03·CH05의 필수 자료가 없으면 차단한다. 기존 무기를 색만 바꾼 것은 CV01의 두 무기 완료로 세지 않는다.

아트 미완성을 검증 우회로 해결하지 않는다. 이후 각도/그립 자료·실제 의상 둘을 작성한 뒤 동일 카탈로그 경계에 연결하여 CV01–CV04를 완료한다. 플레이어 화면·개인 저장과 무작위 생성은 도입 순서 5–6의 후속 기능이다. 현재 구현/실행 결과는 [[07 Unity 기술/캐릭터 조립 구현과 검증]]에서 별도로 관리한다.

## 조립과 실패 처리 — CH06

기본 프리셋 → 허용 외형 선택 → 논리 장비/양식 표현 → 호환 검사 → 숨김/포즈 계산 → 리소스 준비 → 비활성 조립 → 최종 상태 적용 → 표시 순서다. 렌더러 자체가 능력치나 장비 소유권을 수정할 수 없다. 그림을 추가했다고 공격 가능한 Actor가 생기지 않는다.

| 상황 | 처리 | 보존할 것 |
| --- | --- | --- |
| 편집 중 비호환·미해금 선택 | 이유와 관련 슬롯 표시, 확정 금지 | 직전 유효 초안·적용 외형 |
| 필수 모션/방향 누락 | 발행 실패, 런타임에서는 안전 프리셋+동일 계열 필수 모션 복구 | 논리 행동·비용·시간 |
| 개인 장식 리소스 누락 | CH07 대체 맵, 없으면 선택 장식 생략/기본 의상 | 원래 선택을 복구 기록에 보존 |
| 실제 무기 표현 누락 | 같은 실제 계열의 기본 표현으로 대체, 양식 장식만 생략 가능 | 장비 ID·성능·태그, 계열 식별 |
| 안전 프리셋/계열 기본 모션도 없음 | 플레이어/필수 적 생성과 방 진입 중단, 재시도/마을 복귀 안내 | 기존 체크포인트; 적을 조용히 제거해 방 완료시키지 않음 |
| 비동기 교체 중 취소·더 최신 요청 | actor_generation+request_revision 불일치 결과 폐기, 참조 반환 | 최신 요청 또는 기존 적용 |
| 재사용/사망 뒤 로드 완료 | 세대 불일치 결과 적용 금지 | 새 인스턴스와 전투 상태 |
| 장식 VFX 로드/풀 대여 실패 | 장식 생략, 아이콘 등 필수 의미 표시 유지 | 실제 전투 사건 |

동일 요청은 동시에 하나만 준비한다. 요청 세대·카탈로그 버전·장비 리비전이 바뀌면 재검증하며, 이전 요청의 결과는 활성화하지 않는다. 부분 조립 객체는 숨긴 상태로 정리한다. 로더는 공유 참조를 소유하고 Actor는 대여 핸들만 반환한다. 호출자 취소 후 공유 로드가 끝나도 취소된 대상에 붙이지 않는다.

기존 Actor의 교체 준비가 실패하면 기존 표현을 유지하고 새 변경을 확정하지 않는다. 이미 활성화된 필수 표현마저 소실되고 안전 표현도 불가능하면 전투 진행을 정지한 오류 복구 화면으로 전환한다. 보이지 않는 상태로 피해를 계속 진행시키지 않는다. 초기 조립 완료 전 입력·전투·방 등록을 활성화하지 않는다. 기존 Actor 교체는 다음 표현 갱신 경계에서 한 번에 전환한다. 매 공격마다 무기 Prefab을 생성하지 않는다. 풀 반환은 요청 취소 → 이벤트 구독 해제 → 종속 VFX/장비 반환 → 색/숨김/포즈/상태 초기화 → 리소스 핸들 반환 순서다. 논리 HP·장탄·쿨타임 초기화는 세션 책임이다.

진행 없는 로드는 실제 시간 10초에서 실패로 전환하고 자동 무한 재시도하지 않는다. 재시도는 새 요청 ID로 시작한다. 이 값은 첫 기술 타임아웃이며 전투 시간이 아니다. 캐시 키는 Resource ID+리비전+카탈로그 버전이고, 카탈로그 교체 중 기존 Actor는 해당 버전 핸들을 유지한다. 공유 항목은 마지막 참조 반환 후 해제한다.

## 미리보기·확정·저장 — CH07

미리보기는 적용 외형의 사본이며 전투·피해·영구 저장을 호출하지 않는다. 기본값 상속/select/empty는 편집 의도이고, 발행·개인 확정에서는 최종 ID/리비전·팔레트 값을 완전히 해석해 저장한다. 프리셋 개정으로 이미 저장한 개인 외형이 자동으로 달라지지 않는다. 기본값으로 되돌리기는 현재 프리셋을 새 초안에 불러오는 명시적 조작이다.

| 저장 범위 | 내용 | 변경 시점 |
| --- | --- | --- |
| 제작자 초안 | 편집 의도·기준 리비전·진단 | 초안 저장, 게임 배포와 무관 |
| 제작자 발행 | 최종 조합·의존 해시·발행 리비전 | 발행 성공 |
| 개인 외형 | 최종 선택·체형·팔레트·버전 | 마을 화면의 확인 성공 |
| 런 외형 | 출발 시 개인 외형 스냅샷, 실제 런 장비는 기존 런 저장 | 출발/기존 체크포인트 |
| 훈련장 | 임시 조합, 저장 시 훈련 전용 프리셋 영역 | 시험 중, 영구 외형·해금 불변 |

개인 확정은 정책/호환 재검사 → 리소스 준비와 비활성 조립 → profile_revision 비교 잠금 → 새 스냅샷을 임시 파일에 기록·읽기 확인 → 같은 저장 볼륨에서 이전 파일 백업을 둔 원자적 교체 → 포인터 갱신과 준비한 그림 활성화 → 성공 안내 순서다. 단일 저장 서비스가 직렬화하며 외형 화면만의 임의 파일 저장을 하지 않는다. 지원 저장 환경은 현재 Windows 로컬 파일이다.

저장 교체가 커밋 지점이다. 그 이전의 오류는 새 조립을 폐기하고 기존 저장·외형을 유지한다. 커밋 이후 활성화 오류는 “저장됨, 표시 재시도”로 알리고 커밋된 외형에서 재조립한다. 저장 이전 상태라고 거짓 안내하거나 이미 성공한 저장을 임의 롤백하지 않는다. 프로세스 종료가 커밋 전이면 이전 저장, 후이면 새 저장을 로드한다. 출발/화면 종료는 커밋 구간이 끝날 때까지 대기하고 중복 확인은 동일 요청 ID로 한 번만 처리한다.

로드는 스키마/내용 해시 검증 → 구버전 순차 이행 → ID 대체 맵 → 해금/호환 재검사다. 의상 ID 삭제 시 같은 슬롯·체형의 명시적 대체, 없으면 기본 의상/장식 없음으로 복구한다. 변경 전 저장은 백업하고 원래 선택을 recovery_entries에 남겨 복구 안내를 한 번 표시한다. 버전이 더 새로운 저장은 덮어쓰지 않고 호환 버전 실행 안내와 종료를 제공한다. 마을 복구 화면은 저장이 금지된 기본 외형 미리보기로만 열 수 있으며 해당 파일을 새 기본 저장으로 교체하지 않는다. 현재/백업 모두 손상되면 명시적 복구 안내 뒤 기본 외형만 사용하며 다른 영구 데이터 초기화는 별도 기존 저장 정책을 따른다.

런 스냅샷도 외형 이행을 적용하되 진행·무기·재화는 바꾸지 않는다. 지원 중 저장에서 참조하는 리비전은 카탈로그에 유지하거나 MigrationMap으로 치환한 뒤에만 제거한다. 정상 게임에서 해금은 영구 누적이다. 마이그레이션/콘텐츠 회수로 권한을 잃은 선택은 기본 외형으로 복구하고 기록을 남긴다. 상충한 두 저장은 최신 메모리 상태에 강제 병합하지 않고 화면을 다시 불러오게 한다.

외형 복구는 원본 파일을 즉시 덮어쓰지 않는다. 마을의 다음 정상 확정에서 이행본을 저장하며 recovery_entries를 함께 보관한다. 세션 중 안내 확인은 메모리에 유지하고 정상 저장 시 복구 버전과 기록한다. 체형 ID가 사라졌다면 MigrationMap의 새 체형 기본 의상으로 재검증하고, 맵이 없으면 Actor 정의의 안전 프로필로 복구한다. 안전 프로필마저 없으면 CH06의 진입 중단을 적용한다. 다른 체형을 임의로 대입하여 논리 캐릭터·피격 영역·장비 계열을 바꾸지 않는다.

## 다양성과 후보 생성 — CH08

최초 제작 도구는 수동 프리셋을 기준으로 한다. 이후 제작자용 제한 무작위 생성도 동일 검사와 발행을 통과해야 한다. 플레이어 최초 화면에는 무작위 버튼을 제공하지 않는다. 생성 파츠 수가 곧 유효한 캐릭터 수라는 계산을 하지 않는다.

생성 순서는 체형/역할 고정 → 논리 장비 고정 → 상의 → 하의 → 머리카락 → 수염 → 머리 장식 → 등 장식 → 팔레트다. 출하 가능·체형/모션 호환·역할/세력·해금 컨텍스트·현재 슬롯 제약을 순서대로 필터링한다. 후보를 ID순 정렬하고 seed와 생성 알고리즘 버전을 기록한 별도 외형 RNG를 사용한다. 전투/보상 RNG를 소비하지 않는다.

막다른 조합은 유한 후보 목록의 결정적 역추적으로 되돌린다. 작업 상한은 최초 256개 조합 평가이며 넘으면 승인 기본 프리셋과 진단을 반환한다. 상한은 도구 처리 한계이고 콘텐츠 수가 아니다. 선택 슬롯 후보 없음은 비움, 필수 슬롯 없음은 기본 프리셋이다. 최종 선택 ID를 저장하므로 후보 추가 후에도 저장 외형은 재현된다. seed 재생성은 동일 카탈로그/알고리즘 버전에서만 같은 결과를 보장한다.

## 색·상태·가독성 — CH09 및 T02

색 영역은 피부·눈·머리·의상 주색/보조색으로 명시한다. 플레이어는 파츠가 지원하는 출하 팔레트만 고른다. 임의 RGB·투명도·발광 강도 입력은 제공하지 않는다. 무기 양식·신성의 색을 개인 의상 팔레트로 덮어쓰지 않는다.

기본 팔레트 → 실제 장비/장인 양식 → 월드 조명 → 몸/의상 피격 플래시 → 상태 표식 → 사망 페이드 순서로 책임을 나눈다. 피격은 몸/의상 명도 채널만 잠시 변경하고 상태 아이콘·위험 경계·무기 식별을 덮지 않는다. 독/감속은 아이콘과 제한 부착 효과로 표시해 전신색 경쟁을 피한다. 대시 무적은 잔상/밝기, 피격 보호는 다른 패턴의 아이콘, 경직 면역은 고정 방패형 아이콘으로 구별한다. 사망 후 제어 상태 아이콘은 제거하고 죽음 연출만 진행한다.

초기 조립 구조에서는 상태 외곽선을 사용하지 않는다. 단일 Body만 감싸면 다중 의상의 의미와 어긋나고 파츠별 외곽선은 내부 경계를 만들기 때문이다. 경직 면역은 조명과 무관한 아이콘+준비 자세로 전달한다. 전체 합성 실루엣 외곽선은 새 요구가 있을 때 별도 버전으로 도입하며 현재 발행에 요구하지 않는다. T02는 이 초기 범위와 채널 분리로 종료한다.

상태 표시 관리자는 최종 상태 스냅샷을 읽으며 공유 머티리얼을 Actor별로 수정하지 않는다. 한 상태 부여원이 끝나도 남은 부여원이 있으면 표식을 유지한다. 장식 VFX의 품질을 낮추더라도 필수 상태/위험 의미는 제거하지 않는다. 종료 시 저장 팔레트에서 복구하며 마지막으로 덮어쓴 색을 임의 역산하지 않는다.

## 플레이어 외형 변경 정책 — CH10

후속 플레이어 기능은 안전한 마을의 외형 변경 화면에서만 영구 적용한다. 런 진행 중·이어하기 대기 중에는 영구 변경을 막고 현재 런 종료 후 사용하도록 안내한다. 훈련장은 해금된 외형만 미리 시험하고 훈련 전용 프리셋으로 저장할 수 있다. 마을 외형으로 직접 승격하는 버튼은 제공하지 않는다.

노출 슬롯은 CH02의 의상/장식과 허용 색 영역이다. 체형·몸 크기·무기·방패·무기 색·장인 양식은 읽기 전용이다. 초기 개인 변경은 무료이며 소모품·영구 재화·런 재화를 소비하지 않는다. 의상은 기본 제공 또는 영구 해금 키로 구분하고 조건 충족 사실은 기존 해금 서비스가 소유한다. 구매·유료 변경·능력치 의상은 지원하지 않는다.

슬롯 선택 → 후보/잠금 사유 확인 → 미리보기 → 확인 또는 취소를 제공한다. 잠긴 항목은 이유를 보여 주되 장착할 수 없다. 화면 닫기와 취소는 초안을 버린다. 기본값 복구도 초안에만 적용하며 확인 전에는 저장하지 않는다. 확정 중 버튼은 중복 제출하지 못하게 하고 출발을 잠시 보류한다. 저장 실패는 재시도/취소를, 최신 조건 변경은 화면 갱신을 안내한다.

## 게임 적용과 측정 기준 — T03

첫 적용은 Windows 10/11 x64, 키보드/마우스, Unity 6.3 LTS·URP 2D다. 기준 시험 화면은 1920×1080이며 960×540 논리 표시를 정수 2배로 평가한다. 1280×720은 960×540을 정수 1배로 중앙 표시하고 남는 영역을 여백으로 둔다. UI는 별도 출력 해상도 기준으로 읽히게 한다. 첫 체형의 48px 몸은 1080p에서 96px가 기준이다. 이는 새 구조 시험 프로필이며 현재 씬 카메라를 이번 문서 작업으로 변경한 것은 아니다.

원본은 Point 필터·mipmap 없음·비압축·Full Rect와 정수 픽셀 pivot을 사용한다. 초기 아틀라스는 회전/Tight packing을 사용하지 않고 여백 4px를 확보한다. Full Rect가 원본 밖 여백을 자동 생성한다고 가정하지 않으며 상태 외곽선은 현재 사용하지 않는다. 원본 PPU/정수 표시·미러와 실제 파츠/아이콘 셰이더의 아틀라스 UV를 검사한다. 임의 비정수 확대를 기본으로 하지 않는다. 비교는 새 프로필 사본에서만 수행하고 현재 아트를 일괄 재생성하지 않는다. 화면 점유율 시험이 실패하면 버전 있는 기술 프로필을 개정한다. 종족의 최종 디자인은 콘텐츠 제작이며 조립 규칙의 미해결 질문으로 남기지 않는다.

측정 기준 장치는 최초 구현 검증을 실행하는 Windows 개발 PC로 고정하고 CPU·GPU·RAM·드라이버·빌드 버전·전원 설정을 결과에 기록한다. 이 장치를 제품 최소 사양으로 공표하지 않는다. 냉간 로드와 예열 후 60초 구간을 구분하고 단일 캐릭터, 화면 내 30체, 부하 60체, 외형 100회 교체를 같은 경로로 측정한다. 수량은 시험 부하이며 게임의 적 수 상한이 아니다.

초기 수용 목표는 예열 30체에서 전체 프레임 CPU/GPU 각각 p95 16.7ms 이하, 캐릭터 표현 CPU p95 2ms 이하, 표현 갱신의 정상 프레임 관리 힙 할당 0B다. 교체/로드 할당은 별도 기록한다. 메모리는 100회 교체 후 참조 수가 기준으로 복귀하고 강제 회수 뒤 지속 증가하지 않아야 한다. 드로우콜/텍스처/로드 지연은 원자료를 기록한다. 실패하면 배치·아틀라스·파츠 수·캐시를 조정하고 같은 시험을 재수행한다. 실제 측정 결과는 아직 없다.

## 도입 순서와 확장 규칙

1. 원본/ID/카탈로그 스키마와 검증기, 안전 프리셋을 만든다.
2. 수동 제작자 조립·미리보기·초안/발행을 구현한다.
3. 공통 조립기와 별도 Weapon Prefab을 훈련장 표현에 연결한다. 기존 전투 컨트롤러는 교체하지 않는다.
4. 같은 계열 무기 둘과 의상 조합으로 소켓/가림/재임포트·기존 전투 회귀를 확인한다.
5. 플레이어 정책·화면·개인 저장을 연결하고 CV13–CV16을 수행한다.
6. 다른 무기 계열·NPC/적 프리셋·제작자 무작위 생성·다른 체형을 각 계약의 유효 자료로 추가한다.

2026-10-09 후속 요청으로 이 순서의 구현을 시작한다. 아트 스타일·콘텐츠 숫자를 채우는 작업은 구조 결정과 별개다. 신규 계열이 기존 행동/소켓으로 표현되지 않으면 스키마/정책을 버전으로 확장하고 마이그레이션·시험을 추가한다. 협동·모드·원격 배포·실전 자유 무기 교체는 초기 범위 밖이다.

## 검토 종료와 근거

CH01은 사용자 직접 결정, CH02–CH10·T01–T03은 해결 위임에 따른 설계 결정이다. [[06 결정과 기록/기획 검토 완료 기록]]에 질문별 완료 조건·답변·근거를 연결한다. CH12는 기본 모션 제작 방식을 공통 리그로, CH13은 연속 조준을 공통 궤적과 팔 보정으로 결정하고 시험했다. 이전 결정은 당시 기록으로 보존한다. 전체 콘텐츠·성능·출하 검증과 혼동하지 않는다.

SPUM 무료판 1.02의 파츠 조립·공통 모션·제작 흐름에서 아이디어를 얻었다. 다른 버전 기능이나 라이선스를 이 문서에서 판정하지 않으며 SPUM 소스·에셋을 직접 이식하지 않는다. 자체 아트와 기존 마네킹을 사용한다. 정적 비교 근거는 SPUM 프로젝트의 SPUM_Manager.cs, SPUM_SpriteList.cs, SPUM_Prefabs.cs, UnitSave.prefab, Animation/Clip와 project2D의 TrainingPlayerView.cs, TrainingHeroAnimationSet.cs, TrainingMannequinInstaller.cs, MannequinMotion.json이다.

현재 게임에는 기존 마네킹 자료를 사용하는 새 카탈로그·조립기·제작 창의 훈련 구현이 연결되었다. 구현/검증과 남은 범위는 [[07 Unity 기술/캐릭터 조립 구현과 검증]]을 따른다. 플레이어 외형 화면·이행 기능과 정식 16각 아트는 미구현이다. 이전 시험 결과는 [[07 Unity 기술/마네킹 모션 제작과 검증]]에 보존하며 새 구조의 통과 근거로 사용하지 않는다. Obsidian 실행이 확인되지 않아 프로젝트 기획 폴더를 일반 파일 도구로 편집했다.
