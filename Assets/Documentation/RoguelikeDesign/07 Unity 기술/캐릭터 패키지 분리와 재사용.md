# 캐릭터 패키지 분리와 재사용

## 실제 패키지 생성 — 0.1.0 / 2026-10-13

사용자의 실제 생성 요청에 따라 `Packages/com.projectar.character-rig`를 구현 원본으로 만들었다. Runtime 세 스크립트와 SharedRig 기본 에셋을 meta 보존 이동했고 Editor 어셈블리·공통 임포터·경로 지정 생성기·선택 샘플을 분리했다. 훈련장 연결은 프로젝트 도구에 남기고 특정 캐릭터 강제 빌드 처리를 제거했다. 기존 게임데이터 변경분은 보존했다.

배포 파일(프로젝트 루트 기준):

- `Artifacts/CharacterRig/0.1.0/com.projectar.character-rig-0.1.0.tgz`: Unity 설치용.
- `Artifacts/CharacterRig/0.1.0/character-authoring-0.1.0.zip`: tgz·패키지 소스·Aseprite·생성 원본·Lua·설명·검증 기록.
- 같은 폴더 `release-manifest.json`, `validation-report.json`: 해시·의존 검사·실행 결과와 미실시 범위.
- 재배포 생성기: `Tools/CharacterPackage/build_release.py`, 검사 재현 안내: 같은 폴더 README.md.

설치: Package Manager의 Install package from tarball에서 tgz 선택 → Samples의 Azure Vanguard Import → Tools/Character Rig/Open Azure Preview Scene → Play. 자세한 제작/API 안내는 패키지 Documentation~/authoring.md를 따른다. tgz와 ZIP의 PackageSource를 동시에 설치하지 않는다.

| 검증 | 실제 결과 |
| --- | --- |
| 빈 Unity 6000.3.18f1 프로젝트 tgz 설치 | 성공 |
| 샘플 없이 독립 어셈블리 컴파일·Windows x64 Player 빌드 | 성공 |

| Disable/Enable·외형 재연결·graph 재생성 | 통과 |
| 출력 경로 제한·불완전 모션 거부 | 통과 |
| 모션 재생성 GUID·32 Sprite 재임포트 local ID 유지 | 통과 |
| 임포터 활성 씬 유지·독립 Prefab 생성 | 통과 |
| Aseprite 경로 지정 재생성 | 성공, 파츠 PNG SHA256 동일 |
| 외부 에셋 GUID·코어→선택 샘플 역참조·ZIP 해시 | 문제 없음 |

패키지의 실행 코드·에셋은 실제 설치해 검사한 tarball과 최종 배포본이 동일함을 확인했다. 최종 아카이브에는 이후 추가한 검증 설명이 포함된다. Player 빌드는 실제 화면·입력 플레이 검증과 다르다. URP 조명, 업데이트/제거 왕복, 다수 캐릭터 성능은 미실시다.

**기존 Project2D 실행 검증은 미실시:** 실행 중 Editor가 프로젝트를 점유하지만 CLI 연결 목록에 나타나지 않아 별도 배치 검증을 실행하지 못했다. Editor는 강제 종료하지 않았다. 실제 프로젝트 재컴파일/훈련장 전투 회귀는 후속이며 파일 GUID 보존만으로 완료 처리하지 않는다. 현재 프로젝트의 명시적 Azure 임포터와 Atlas 메뉴는 새 공통 API를 호출한다.

최초 배포 범위는 리그 표현/제작 API다. 커스터마이징 UI·카탈로그·저장/로드와 피격/기절/사망 모션은 포함하지 않는다. 아래 조사 기록의 미실시 상태와 옛 경로는 제작 이전 상태다.

## 조사 결과와 범위

**UPM 패키지를 원본으로 관리하고, 설치용 `.tgz`와 제작 원본을 포함한 선택 ZIP을 같은 버전에서 배포하는 방식을 추천한다.** 최초 범위는 현재 구현된 4방향 SD 공통 리그·연속 조준·양손 연결·공통 모션과 제작 도구다. 게임 전체 캐릭터 시스템이나 완성된 커스터마이징 도구로 부르지 않는다.

사용자의 다른 프로젝트 재사용을 위한 구성 조사 요청에 따른 제안이다. 이번에는 소스·에셋 경로·현재 기획과 Unity 공식 문서를 확인했다. 코드 이동, 패키지 생성, 새 프로젝트 설치 및 빌드는 수행하지 않았다. 기존 캐릭터 기획 계약을 변경하거나 패키지 방식을 사용자 채택으로 처리하지 않는다.

현재 원본은 Unity 6000.3.18f1이다. 다른 Unity 버전·렌더 파이프라인 지원은 별도 시험 전에는 보장하지 않는다. 기존 훈련장의 검증 결과는 패키지 독립성 검증을 대신하지 않는다.

## 형식 선택

| 형식 | 역할 | 판단 |
| --- | --- | --- |
| UPM + `.tgz` 또는 Git 버전 참조 | 코드·의존성·버전을 함께 설치하고 업데이트 | 주 배포 형식 추천 |
| `.unitypackage` | 에셋을 Assets에 가져오는 일회성 전달 | 요청이 있을 때 같은 원본에서 추가 생성. 별도 코드 원본으로 관리하지 않음 |
| `.zip` | Aseprite 원본·제작 스크립트·설명·설치용 tgz 전달 | 제작 키트 보조 배포. 일반 ZIP 자체를 UPM 설치 파일로 안내하지 않음 |

UPM은 Runtime/Editor 어셈블리, Samples~, Documentation~를 나누는 공식 구성을 사용한다. Editor라는 폴더명만으로 패키지 코드의 Editor 전용 컴파일이 보장되지 않으므로 asmdef 플랫폼 제한이 필요하다. [Unity 패키지 구성](https://docs.unity.com/en-us/engine/6000.0/manual/packages-list/cus-pkg-development/cus-layout)

설치용 tarball을 선택할 수 있고, ZIP에 담은 로컬 패키지는 압축 해제 후 package.json으로 연결할 수 있다. 반복 사용 시 각 프로젝트가 검증된 버전을 고정하도록 한다. [Unity 패키지 공유](https://docs.unity.com/en-us/engine/6000.0/manual/packages-list/cus-pkg-development/cus-share), [로컬 패키지 경로](https://docs.unity.com/en-us/engine/6000.3/manual/packages-list/dependencies-lp/upm-localpath)

## 그대로 압축하면 생기는 문제

1. **자동 빌드의 특정 캐릭터 의존:** CharacterAtlasBuilder.OnPreprocessBuild는 항상 AzureVanguard를 생성한다. 고정 경로에서 Sprite가 32개가 아니면 BuildFailedException을 발생시키고 전역 Sprite Packer 설정까지 바꾼다. 샘플 미설치 상태에서도 일반 빌드가 가능하도록 바꿔야 한다.
2. **패키지 쓰기 경로:** SharedRigBuilder와 임포터는 Assets/Art/Characters/...를 고정한다. 배포 패키지 안의 기본 에셋은 읽기 전용으로 취급하고, 생성 결과는 사용자가 지정한 Assets/Characters/...로 저장한다. 기존 파일 갱신은 선택한 대상에 한정하고 미리 변경 목록을 제시한다.
3. **임포트와 씬 설치의 결합:** ImportAzureVanguard.Main은 에셋 생성 후 TrainingGround 씬을 열고 TrainingPlayerView를 찾아 외형을 바꾸고 저장한다. 범용 임포터는 결과 에셋만 반환하고 어떤 씬도 자동으로 열거나 저장하지 않아야 한다.
4. **암묵적 컴파일 의존:** 현재 조사한 캐릭터 코드에는 asmdef가 없다. Runtime, Editor, 샘플, Tests를 명시적으로 분리하여 패키지에서 Assembly-CSharp의 Training 타입을 참조하지 못하게 한다.
5. **고정 제작 레시피:** Lua는 특정 이미지의 실측 행 좌표와 4열×8행을 전제한다. 임의의 생성 이미지를 자동 분해하는 범용 제작기로 소개하면 안 된다. 파츠 이름·영역·피벗·밀도 설정으로 명시한다.
6. **검사의 빈틈:** CommonRigAppearance.IsValid는 8종 배열의 4방향 Sprite를 검사하지만, CommonRigMotions에는 모든 Clip/Mask/길이/방향 및 enum 유효성을 검사하는 통합 검사가 없다. 잘못된 입력을 인덱스 예외나 NullReference로 받기 전에 오류 위치를 알려야 한다.

## 제안 디렉터리

명칭은 가칭이다. 실제 배포 전에 조직 식별자와 패키지 이름을 고정한다.

```text
  README.md / CHANGELOG.md / LICENSE.md / Third Party Notices.md
  Runtime/
    ProjectAr.CharacterRig.asmdef

  Editor/

  Samples~/AzureVanguard/
    Art/                     # PNG·외형·Prefab·Atlas
    MotionPreview/           # 전투/HUD 없이 움직임을 확인하는 예제
  Tests/Editor/              # Editor 전용 테스트 asmdef
  Tests/Runtime/             # 테스트 전용 asmdef

    getting-started.md / authoring.md / rig-contract.md / migration.md

  Packages/com.projectar.character-rig-0.1.0.tgz

  Tools/Aseprite/            # Lua와 실행 안내. 실행 파일 미포함
  README.md / manifest.json # 파일 목록·해시·패키지 버전·검증 환경
```

package.json에 샘플 경로를 등록한다. 샘플 코드도 자체 asmdef를 두고 Runtime만 참조한다. 테스트 의존성은 테스트 어셈블리에서 격리한다. Sprite Editor API를 쓰는 Editor 임포터에는 실제 사용 의존성을 선언한다. 현재 lock에는 com.unity.2d.sprite 1.0.0이 간접 설치되어 있으므로 새 프로젝트에서는 그 우연한 설치에 의존하지 않는다.

Runtime은 현재 UnityEngine Animation/Playables/SpriteRenderer를 사용한다. URP API 직접 참조는 발견하지 않았다. 다만 생성기는 Sprites/Default 재질을 만들므로 URP 2D 조명 대응과 Built-in 호환은 각각 재질/렌더 시험이 필요하다. 재질은 호출자가 제공할 수 있게 유지하며 최초 지원 범위는 실제 검증한 조합으로만 적는다.

## 생성·실행·관리 계약

**제작 시 생성:** 원본 그림 → Aseprite 파츠 준비 → Unity Sprite 등록 → CommonRigAppearance → 공통 모션 참조 → 독립 Prefab → 검사 순서다. 공통 모션은 리그별로 공유하며 캐릭터마다 복제하지 않는다. 이미지 생성 프롬프트는 제작 기록으로 제공하고 특정 이미지 생성 서비스나 계정을 패키지 필수 요소로 삼지 않는다.

**런타임 생성:** 게임이 완성된 Prefab을 Instantiate하거나 GameObject에 CommonCharacterRig를 추가하고 Initialize(motions, appearance, material)를 호출한다. 이동·조준·전투 상태는 게임이 소유하며 어댑터가 SampleContinuous에 모션 enum, 방향, 재생 시간을 전달한다. 리그는 피해·마나·장비·입력을 결정하지 않는다. 현재 TrainingPlayerView의 준비/유효/회수 매핑(.32/.70)은 프로젝트 전투 어댑터에 남긴다. 범용 API를 만들면 긴 bool 인수보다 작은 Pose 입력 구조로 묶되 기존 API의 점진적 이관을 지원한다.

**수명:** Instantiate/풀 반환은 호출 프로젝트 책임, PlayableGraph는 리그 책임이다. 현재 OnDisable에서 graph를 해제한다. 비활성화/재활성화·외형 변경·도메인 재로드에서 손실과 누수를 검사한 뒤 풀 사용 지원을 표기한다. 첫 버전에 별도 전역 CharacterManager나 Addressables 로더를 추가할 필요는 없다.

**ID와 호환성:** 게임 콘텐츠 선택에는 기존 int/typed ID·enum 규칙을 적용하고 프로젝트 어댑터가 실제 외형/모션 에셋으로 해석한다. 패키지 내부 연결은 Unity 에셋 참조를 우선한다. rig.sd-cutout.v1은 콘텐츠 행 ID가 아니라 호환 규격 표식이므로 일괄 숫자 치환하지 않는다. 리그 경로·방향 순서(아래/위/좌/우)·32 논리 PPU·8+8px 팔·5px 그립 규격을 한 계약에서 관리한다. Azure 텍스처의 128 PPU와 논리 PPU는 구분한다. 첫 버전은 이 규격을 고정하고 모든 체형을 위한 설정을 미리 늘리지 않는다.

**확장 경계:** 현재 Appearance는 무기 Sprite 배열도 함께 가진다. 독립 장비/무기 외형 교체 모듈이 완성됐다고 보지 않는다. 피격·기절·사망 모션, 제작자 카탈로그, 플레이어 외형 저장/로드는 기존 후속 작업이며 첫 패키지의 기능 목록에 넣지 않는다.

**버전과 원본:** 처음에는 저장소 내 한 패키지를 개발 원본으로 관리하고 Project2D도 같은 패키지를 사용한다. 원래 Assets 코드와 패키지 복사본을 동시에 유지하지 않는다. 소비 프로젝트에서는 버전/태그를 고정하고 수정이 필요하면 원본에 반영해 새 버전을 배포한다. 버그 수정·호환 기능 추가·호환성 파괴를 구분해 CHANGELOG와 이관 안내를 남긴다. 배포 태그를 나중에 다른 내용으로 덮어쓰지 않는다.

**GUID:** 기존 스크립트·Clip·Mask·외형·Prefab의 meta를 보존한 이동 계획을 만든다. 같은 GUID를 가진 원본과 설치 사본을 한 프로젝트에 함께 두지 않는다. 이름/namespace/어셈블리를 바꿀 때는 직렬화 참조와 필요한 타입 이관을 검사한다. 샘플이 패키지 기본 모션을 참조하게 하고, Runtime이 Samples~를 역참조하지 않게 한다.

## 분리 작업 순서와 완료 조건

1. **원본 목록 고정:** 파일·meta·참조 대상·출처를 기록하고 기존 작업 변경분을 보존한다. 현재 Azure 원본 문서에는 image_gen 생성과 자체 그림자 재사용이 기록되어 있다. 코드/아트 배포 조건은 별도로 명시하고 제3자 에셋 및 Aseprite 실행 파일을 묶지 않는다.
2. **생성기 순수화:** 경로 인수화, 씬 설치 분리, 특정 샘플 빌드 강제 제거, 리그/Clip 검사 추가. Import/Preview는 유저가 지정한 에셋만 변경한다.
3. **패키지로 이동:** meta 보존, Runtime/Editor asmdef, 공유 기본 에셋과 샘플 분리. 기존 Training 어댑터가 패키지를 호출하도록 연결한다.
4. **제작 키트 구성:** 스크립트 입력/출력·원본 밀도·레이어/피벗 규격·실행 순서 문서화. 새 외형 추가 예제를 기존 에셋 덮어쓰기 없이 재현한다.
5. **독립 검증 후 배포:** 아래 항목을 통과한 동일 원본에서 tgz와 ZIP을 생성한다. 설치, 사용, 업그레이드, 제거 및 문제 복구 안내를 함께 제공한다.
