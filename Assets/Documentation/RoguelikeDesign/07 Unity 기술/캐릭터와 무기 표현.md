# 캐릭터와 무기 표현

## 최신 제작 논의 — 2026-10-08

사용자가 제안한 별도 이미지 생성·별도 Prefab 장착 방식을 [[07 Unity 기술/캐릭터와 무기 분리 제작]]에 정리했다. 비율과 해상도 재검토는 [[07 Unity 기술/캐릭터 비율과 픽셀 아트 제작]]을 따른다. 아래 계층은 책임 구분 초안이며 실제 구현의 완료 상태와 구분한다. 현재 Hero V2는 팔과 무기가 같은 이미지에 포함된 중간 구현으로, 새로운 장착 구조와 T01의 방향·회전·포즈 합성 선택은 후속이다.

## 공통 캐릭터 구조의 추천

캐릭터·적은 공통 ActorRuntime과 표현 골격을 사용하고 입력 또는 AI, 정의 데이터, 시각 리소스를 바꾼다. 아래는 Prefab의 책임 구분 초안이며 실제 생성한 Unity 오브젝트는 아니다.

```text
ActorRoot — ActorRuntime, ActorMotor, 발 위치 기준
├─ CollisionRoot — 벽·이동 충돌, 피격 영역
├─ VisualRoot — ActorView, SortingGroup
│  ├─ Shadow — 바닥 기준, 또는 별도 Ground 계층
│  ├─ Body — 몸체 SpriteRenderer와 프레임 재생
│  ├─ BackWeapon — 몸 뒤 무기 표현
│  ├─ FrontWeapon — 몸 앞 무기 표현
│  └─ Attachments — 손·발사구·장식의 표현 소켓
└─ OverheadView — HP·상태 아이콘 표시
```

게임 좌표·이동 Collider는 ActorRoot를 따른다. 바운스·피격 흔들림·기울이기·스쿼시는 VisualRoot 또는 Body에만 적용한다. 그림이 흔들려도 공격 범위나 발 좌표는 바뀌지 않는다. Attachment는 그림을 붙이는 위치다. 피해·투사체 원점은 타격 데이터와 논리 자세에서 계산하고 임의 아트 소켓 편집만으로 사거리나 차폐 규칙이 바뀌지 않게 한다. 총구와 논리 발사 원점의 연결은 제작 검증 대상이다.

## 생성과 장착

ActorDefinition/EnemyArchetype과 시작 장비 ID를 ActorFactory에 넘긴다. Factory는 공통 논리 상태를 만들고 ActorVisual 정의의 Prefab을 붙인다. 장착은 WeaponRuntime과 WeaponView로 나누어 실행 규칙과 그림을 함께 바인딩한다. 특수행동 모듈은 방어·모아치기·재장전·패링처럼 지원하는 동작을 합성하며 무기 종류마다 Actor 전체를 복사하지 않는다.

무기 성장 시 공격 정의·스탯 변경과 양식·스킨·VFX의 변경을 같은 안전 편집 계약에서 적용한다. 헤파이스토스 양식·룬 양식은 기본 무기 소켓과 동작을 재사용할 수 있다. 신화 양식의 큰 장식이 피격·사거리의 증가를 자동으로 의미하지 않게 한다. 신성이나 무기의 외형 교체도 기존 쿨타임 그룹·자원·세대 ID를 초기화하지 않는다.

## 방향과 무기 동작

논리 조준은 전방향 연속 벡터다. 몸체 그림의 4/8방향 수는 별도의 아트 선택 T01이다. 기존 4방향+연속 회전 제안은 비교 후보로 남기고, 별도 생성한 캐릭터·무기의 연결을 기준으로 연속 회전·각도별 그림·상하체 합성 범위를 비교한다. 표현 방향을 줄여도 실제 조준·판정 방향을 함께 양자화하지 않는다. 자세한 제작 순서는 [[07 Unity 기술/캐릭터와 무기 분리 제작]]을 따른다.

무기 그림은 WeaponVisual과 ActionVisual의 자세 곡선을 이용해 준비 자세→휘두르기/찌르기→회수로 진행한다. 타격 순번마다 궤적·손 위치·몸 앞뒤 표시를 달리할 수 있다. 실행 시 고정한 조준 방향을 기준으로 로컬 궤적을 적용한다. 행동 단계를 관찰해 표시하므로 준비 중 조준 갱신과 실행 고정이 일치한다.

| 무기 | 표현 후보 | 판정과의 연결 |
| --- | --- | --- |
| 대검 | 큰 호의 회전·몸체 반동·굵은 슬래시 | 정한 범위·활성 구간으로 판정, 그림 크기만으로 범위 변경 금지 |
| 단검 | 짧고 빠른 교차 궤적·패링 자세 | 타격마다 실행 ID/적중 단위 분리 |
| 창 | 방향 축의 찌르기·회수 | 전방 논리 범위와 찌르기 방향 일치 |
| 검과 방패 | 공격 무기와 전방 방패 표시 | 방어각·유효 구간을 상태에서 읽음 |
| 활·석궁 | 조준·발사·장전 프레임, 발사 섬광 | 발사 사건으로 투사체 생성, 애니메이션만으로 탄 소비 금지 |

연속 방향의 저해상도 Sprite 회전은 픽셀 흔들림이 생길 수 있다. Pixel Perfect Camera만으로 임의 회전이 모두 정갈해진다고 가정하지 않는다. 연속 회전·각도별 제작 Sprite·큰 원본 후 픽셀화 방식을 T01에서 비교한다. 게임 이동은 연속 좌표로 유지하고 표시만 조정한다. PPU·기준 해상도·필터링·회전 품질을 함께 시험한다. [Unity Pixel Perfect 안내](https://docs.unity.com/en-us/engine/6000.3/manual/unity2d/2d-urp/2d-pixelperfect)

## 깊이와 가림

발 좌표 Y를 기준으로 Actor 그룹의 깊이를 정하고 같은 Actor 내부의 몸·무기는 로컬 순서로 제어한다. 서로 다른 Actor의 몸과 무기 파츠가 섞이지 않도록 SortingGroup을 사용한다. 지면 그림자·위험 예고·독립 투사체·큰 광역 VFX는 Actor 그룹 밖에서 각자 월드 위치로 정렬한다. 긴 무기의 외부 Actor와의 완전한 기하학 가림은 그룹 정렬만으로 해결되지 않으므로 필요한 콘텐츠에서 별도 검증한다. [Unity SortingGroup](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/Rendering.SortingGroup.html)

## 제작 확인

- [ ] 이동·대시·밀려남 중 공격 단계와 궤적이 끊기지 않는다.
- [ ] 몸체 방향·무기 방향·논리 판정이 전방향 조준에서 이해 가능하다.
- [ ] 몸체·무기·손 소켓·발사 위치가 방향별로 연결되고 다른 Actor와 정렬된다.
- [ ] 연격·공격속도 변화·준비 취소·사망에서 프레임 이벤트 누락으로 피해가 달라지지 않는다.
- [ ] 무기/양식 교체와 풀 재사용 시 이전 Sprite·VFX·쿨타임이 잘못 남거나 초기화되지 않는다.
