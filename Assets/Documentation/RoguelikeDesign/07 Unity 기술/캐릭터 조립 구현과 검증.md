# 캐릭터 조립 구현과 검증

## 과거 구현 보관 안내 — 2026-10-11

아래 assembly-0.1은 프레임 기반 조립·발행 도구의 당시 실행 기록이다. 사용자 요청으로 해당 코드·에셋·메뉴를 퇴역시켰으므로 아래 사용 순서는 현재 프로젝트에서 실행하지 않는다. 현행 공통 리그와 보관 위치는 [[07 Unity 기술/공통 리그 애니메이션 실험과 전환#현행 구현 정리 — 2026-10-11]]를 따른다. 데이터 계약의 재사용과 리그용 제작자 구현은 후속이다.


## 적용 범위

2026-10-09 사용자의 “보강처리 이후 문서대로 만들어보자” 요청으로 character-1.1의 Atlas 계약을 보강하고 제작자→카탈로그→훈련장 연결을 구현했다. 전체 character-1.1 출하 완료가 아니라 도입 순서 1–3의 첫 훈련 구현이다. 기존 전투 컨트롤러와 피해/비용 계산은 바꾸지 않았다. SPUM 에셋·코드는 이식하지 않았다.

## 사용 순서

1. Unity에서 TrainingGround 씬을 연다. 새 조립 컴포넌트가 훈련장 플레이어에 연결되어 있다.
2. Game → Characters → Character Maker를 연다.
3. 상의/하의 팔레트 neutral·cool·warm을 따로 선택하고 방향/동작을 미리 본다. 현재 색은 임시 기술 시험용이며 최종 콘텐츠 색 규격이 아니다.
4. 초안 ID를 정해 초안 저장을 누른다. 기존 초안은 초안 열기로 읽으며, 새 초안은 새 초안 버튼으로 시작한다. 복제할 때 새 ID를 사용한다.
5. 미리보기 검사 후 훈련 프리셋 발행을 누른다. 조합·발행 리비전이 바뀌면 검사를 다시 해야 한다. 동일 발행 리비전은 덮어쓸 수 없다.
6. 훈련장에 적용을 누른다. 편집 모드에서는 씬 설정이 변경되므로 씬을 저장하고 Play한다. Play 중에는 현재 훈련 세션만 바뀐다. 영구 외형/해금/런 저장을 건드리지 않는다.
7. 출하 검사는 미충족 이유를 표시한다. 현재 자료로 정식 출하 발행은 허용하지 않는다.

현재 선택 가능한 체형/무기는 마네킹/블록아웃 대검 각 하나다. 머리카락·수염·머리/등 장식은 자료 없음으로 표시한다. 자료가 없는 선택지를 가짜 외형으로 채우지 않았다.

생성 카탈로그는 수동 수정하지 않는다. 원본 내용이 바뀌면 기존 카탈로그 덮어쓰기를 거부한다. 현재 임포터는 단일 훈련 카탈로그를 만드는 단계이며, 새 버전 생성/마이그레이션 작업 UI는 아직 없다. 프리셋 리비전 발행은 구현했지만 **원본 변경→새 카탈로그 자동 이관까지 완료한 것은 아니다**.

발행된 훈련 JSON은 제작자 산출물이다. 게임이 폴더를 검색해 자동으로 최신 파일을 적용하지 않는다. 제작 창에서 선택한 해석 결과를 훈련장 컴포넌트에 적용한다. 플레이어 저장/마을 화면은 후속 단계다.

## 그림과 로딩의 실제 동작

기존 Aseprite의 Head/Torso/FarArm/NearArm/Hands/FarLeg/NearLeg/Weapon/Shadow를 8개 조각으로 내보냈다. 양 다리는 한 조각이다. 기본 몸체는 머리·손·그림자, 상의 시험 파츠는 몸통·양팔, 하의 시험 파츠는 다리, 무기는 대검이다. 이는 기존 마네킹을 이용한 조립 시험이며 새 옷 디자인 두 벌이나 새 무기 두 종의 제작 완료가 아니다.

파츠는 432개 포즈의 Sprite 참조와 레이어 순서를 가진다. 상체/무기와 다리는 서로 다른 프레임을 선택할 수 있다. 실제 판정·마나·공격 구간은 기존 전투 상태를 그대로 읽는다. Actor 하나에 현재 8개 SpriteRenderer가 생기고 같은 카탈로그의 Sprite를 공유한다. 캐릭터마다 이미지 복제나 전체 bake는 하지 않는다.

Sprite는 투명 여백을 제외한 사각형으로 임포트하되 원래 셀의 발 기준을 pivot으로 보존한다. pivot이 사각형 밖에 있을 수 있고 원본 좌표는 바뀌지 않는다. Full Rect, 32 PPU, Point, 비압축, mip 없음이다. Atlas는 회전/Tight 없음, padding 4, 최대 페이지 2048을 사용한다. 런타임 GetSprite 호출/복제를 하지 않는다.

**훈련 어댑터의 메모리 한계:** 기존 TrainingHeroAnimationSet과 구형 Renderer 참조를 실패 시 기존 표현 유지 용도로 보존했다. 따라서 새 Atlas 외에 기존 원본 텍스처도 참조한다. 현재 빌드의 전체 메모리가 새 Atlas 페이지 비용과 같다고 주장하지 않는다. 최종 이관은 Sprite 없는 순수 모션 자료 분리·검증된 안전 프리셋 경로를 갖춘 후 구형 참조를 제거해야 한다.

마지막 대여 반환은 논리 캐시 해제다. 씬 카탈로그가 소유한 텍스처를 즉시 언로드하지 않는다. Addressables 스트리밍·지역 단위 언로드는 구현하지 않았다.

조립 시험은 전체 432개의 상/하체 인덱스 조합 샘플, 100회 외형 교체, 공유 원본 불변, 최신 요청 우선과 대여 반환을 확인했다. Play mode에서 기존 플레이어의 대여 4개가 있는 상태로 시작하여 테스트 후 4개로 복귀했다. 표현 샘플 10,000회의 해당 스레드 관리 힙 할당은 0B였다. 전체 프레임/30체·60체 CPU/GPU 성능이나 Unity 네이티브 텍스처 메모리 회수 결과로 확대하지 않는다.

전투 시험은 기존 허수아비가 HP에서 누적 피해 통계로 바뀐 상태에 맞춰 테스트 관측만 TotalDamage/HitCount로 변경했다. 동일 피해량·1회 타격·연격·예약·마나·모으기/회전·대시·미리보기 입력 차단의 기대값을 유지했다. 최초 실행은 Game View가 갱신되지 않아 Idle 타임아웃이 났고, Game View 활성화 후 21개를 통과했다. 전투 코드를 검사에 맞춰 바꾸지 않았다.

## 모션 구조 재검토로 확장 보류 — CH12

후속 사용자 지시로 SPUM과 현재 구현을 다시 비교했다. SPUM의 공통 Transform 리그 모션과 현재 포즈별 Sprite 시트는 다른 제작 방식이다. [[07 Unity 기술/캐릭터 제작과 조립 구조#공통 리그 애니메이션 재검토 — CH12]]를 먼저 해결하며 기존 시험 구현/원본/검증 결과는 비교 근거로 보존한다. 독립 빌드는 성공했지만 실행 시험과 새로 추가한 타임아웃 검사는 실행하지 않았다. 추가 시트/의상/무기 제작을 계속하지 않는다.

## CH12 후속 결과

보류했던 모션 비교는 [[07 Unity 기술/공통 리그 애니메이션 실험과 전환]]에서 실행했다. 기본 제작 방식은 공통 리그로 전환한다. 이 문서의 assembly-0.1은 이전 프레임 기반 시험이며 공통 리그 이관 완료를 뜻하지 않는다.
