# 게임데이터 MOC

## 신화 빌드 Excel 작성 — 2026-10-12

[[05 검증과 확장/신화 빌드 Excel 데이터 계약]] — 실제 Excel 위치, ID 관계, 미정 숫자와 확장 절차, 검사 결과.

수치와 콘텐츠의 다양성은 추후 게임데이터 Excel에서 관리한다. 기획 문서는 동작 규칙과 열의 의미 및 ID 관계를 연결한다.

## 읽는 순서

1. [[05 검증과 확장/게임데이터 작성과 변환 규칙]]: int·enum, 6시트 작성, 열 최소화, 생성·검증·이관의 신규 기준. 근거는 [[05 검증과 확장/공개 게임데이터 사례와 적용 판단]]에서 확인한다.

2. [[05 검증과 확장/Excel과 기획 문서의 연결|Excel과 기획 문서의 연결]]: 관리 책임과 문서 참조 형식.
3. [[05 검증과 확장/게임데이터 열 정의|게임데이터 열 정의]]: 무기, 카드와 태그 및 신성 등 논리 테이블과 열.
4. [[05 검증과 확장/게임데이터 관계와 추가 절차|게임데이터 관계와 추가 절차]]: ID 연결과 새 콘텐츠 추가 및 검증의 흐름.

## 기존 문서와의 연결

- [[05 검증과 확장/콘텐츠 데이터 구조|콘텐츠 데이터 구조]]에서 전체 콘텐츠 관계를 확인한다.
- [[00 MOC/기본 전투 MOC|기본 전투 MOC]]는 공격 시간과 자원 열의 동작을 정의한다.
- [[00 MOC/빌드와 무기 MOC|빌드와 무기 MOC]]는 카드, 태그와 장인 및 신성 참조를 정의한다.
- [[00 MOC/마을과 성장 MOC|마을과 성장 MOC]]는 영구 데이터와 런 정산의 규칙을 정의한다.
- [[기획 진행 현황과 후속 작업|기획 진행 현황과 후속 작업]]에서 규칙 결정과 Excel 작업을 구분한다.

## 현재 상태

2026-10-13 현재 6시트·정수 ID 이관, 스키마/등록표/검증기/생성기, 훈련소 데이터 로딩을 구현했다. 보존 수치 179개 중 175개는 Pending이며 훈련소 임시 수치 38개를 별도 Provisional로 관리한다. Python 검사 23개, Unity 로더 검사 12개, 전투 회귀 26개가 통과했다. 신화 효과·공명·밸런스와 기존 세이브 ID 이관은 후속이다. 실제 계약과 증거는 [[05 검증과 확장/신화 빌드 Excel 데이터 계약]]를 따른다.
