# 재사용 기획 스킬 사용

## 이번 세션에서 재사용할 절차

새 구조 질문을 검토하고, 채택한 규칙을 기준 문서에 반영하고, 해결한 질문을 완료 기록으로 옮기며, MOC·데이터 열·미실시 시험을 연결하는 작업을 반복했다. 이 절차와 연결 점검을 두 스킬로 나눴다. 기존 Obsidian CLI·Markdown은 노트 작업의 도구 스킬로 유지한다.

| 스킬 | 사용할 요청 | 하는 일 |
| --- | --- | --- |
| `roguelike-design-review` | 다음 검토사항, 전투 의문사항, 추천, 채택 반영, 기획 문서 업데이트 | 기존 결정 확인 → 필요한 구조 검토 → 위임·채택한 범위 반영 → 기록·MOC·열·시험 정리 |
| `obsidian-design-audit` | Vault 점검, 연결 확인, 완료 항목·미정 제목 정리 | 읽기 전용 연결·제목·상태 검사 및 문제 위치 보고 |

두 스킬은 `.agents/skills/`에 있다. 스킬 설명과 맞는 요청에는 자동 선택할 수 있으며, 정확하게 지정하려면 아래 예시처럼 이름을 명시한다. 실제 선택·도구 실행 가능 여부는 해당 컴퓨터에서 확인한다.

## 요청 예시

> $roguelike-design-review 현재 전투 규칙에서 아직 답이 없는 연결 조건을 찾아줘. 수치와 실제 플레이 시험은 구조 질문과 구분해줘.

> $roguelike-design-review 방금 채택한 규칙을 기획서에 반영하고 완료 기록·MOC·데이터 열·미실시 시험까지 정리해줘.

> $obsidian-design-audit 이번에 수정한 문서의 연결과 상태를 점검해줘.

> $obsidian-design-audit Vault 전체를 읽기 전용으로 점검하고, 기존 문제와 이번 변경의 문제를 구분해서 알려줘.

점검 요청만으로 기획 규칙을 변경하지 않는다. 검토 요청만으로 제안을 채택하지 않는다. 설계 위임과 명시적 채택 범위는 유지하고 같은 승인을 다시 요구하지 않는다. GitHub에 반영하는 권한은 사용자의 요청과 세션 권한으로 판단하며 스킬 자체가 부여하지 않는다.

## 점검 도구

`obsidian-design-audit/scripts/audit_vault.py`는 Python 3 표준 라이브러리만 사용한다. `--vault`로 실제 Vault 경로, `--files`로 특정 상대 경로들을 주며 `--format json`으로 구조화된 결과를 받을 수 있다. 파일을 수정하지 않는다.

일반 wikilink의 노트·첨부·절·블록, 제목과 속성, 활성 목록의 완료 체크를 확인한다. 코드 예시와 주석을 제외한다. 별칭 및 중복 후보는 제한적으로 지원하며 애매한 연결은 Obsidian에서 확인한다. 외부 링크·모든 YAML 문법·규칙의 의미·사용자 결정 근거와 실제 게임 검증을 자동 판정하지 않는다.

## 생성 시 확인 결과 — 2026-10-07

- 정상 노트·별칭·절·블록 연결 및 코드·주석 예시 제외를 확인했다.
- 없는 노트·없는 절·잘못된 상태·활성 완료 체크를 검출하고, Vault 밖 경로를 거부하는 것을 확인했다.
- 검사 전후 파일 해시를 비교해 읽기 전용 동작을 확인했다.
- 두 스킬의 형식 검사와 참조 파일 확인을 수행했다.
- 초기 전체 점검에서 기존 노트 69개의 연결 오류는 없었으며, 과거 `status` 체계 경고 45건을 확인했다. 운영 기준에 따라 해당 문서를 수정할 때 이행할 항목이며 자동으로 수정하지 않았다. 이 수치는 초기 스냅샷이고 현재 결과는 다시 검사한다.

다른 컴퓨터의 자동 선택과 Obsidian CLI 실행, 실제 기획 판단의 품질 및 게임 구현 결과는 위 검사로 검증된 것이 아니다. 사용하면서 발견한 문제는 해당 절차만 좁게 보강한다.
