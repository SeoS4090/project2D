# 다른 컴퓨터에서 작업 시작

## 최초 준비

1. GitHub에 접근 가능한 계정으로 [비공개 기획 저장소](https://github.com/SeoS4090/roguelike-design)를 원하는 폴더에 내려받는다.
2. 해당 폴더를 Obsidian의 기존 Vault로 연다. 기존 컴퓨터의 `.obsidian/` 개인 설정은 공유하지 않으므로 필요한 표시 설정은 새 컴퓨터에서 지정한다.
3. Codex에 내려받은 저장소 폴더를 프로젝트로 등록하고 그 폴더에서 작업을 시작한다. 별도 ChatGPT 미러 폴더와 실제 Vault를 혼동하지 않는다.
4. 루트 `AGENTS.md`의 지침과 [[06 결정과 기록/프로젝트 기억과 작업 인계]]를 읽게 한다.
5. [[06 결정과 기록/스킬 구성과 유지]]를 따라 프로젝트 스킬의 인식과 Obsidian CLI 실행을 확인한다.

Codex의 저장소 스킬은 `.agents/skills/`에 포함한다. 저장소 안에서 시작할 때 프로젝트 지침과 스킬을 찾을 수 있는 구조다. 스킬이 목록에 나타나지 않으면 새 세션에서 확인한다. [공식 프로젝트 지침 안내](https://learn.chatgpt.com/docs/agent-configuration/agents-md) · [공식 스킬 경로 안내](https://learn.chatgpt.com/docs/build-skills)

## 도구 확인

| 항목 | 확인할 내용 |
| --- | --- |
| GitHub와 Git | 비공개 저장소 접근·인증, 현재 브랜치와 로컬 변경 상태 |
| Obsidian | 실제 Vault 위치·이름, 앱 실행, CLI 기능 활성화 |
| CLI | 해당 컴퓨터에서 발견한 실행 경로, 도움말·Vault 조회·노트 읽기 |
| Codex | 작업 폴더가 실제 Vault인지, 루트 지침과 프로젝트 스킬 인식 여부 |

Obsidian 실행 위치는 컴퓨터마다 발견해 사용한다. 현재 컴퓨터의 사용자명이나 설치 경로를 공통 전제에 넣지 않는다. 앱을 연 뒤 CLI로 도움말을 확인한다. CLI의 `vault=<이름>`을 첫 인수로 지정하고 먼저 읽기 명령으로 올바른 Vault인지 확인한다. [Obsidian CLI 안내](https://help.obsidian.md/cli)

스킬 파일을 내려받아도 앱·CLI·플러그인·연결·로그인이 자동 설치되는 것은 아니다. 일반 ChatGPT에서 작업할 때는 프로젝트 파일과 지침을 직접 제공하고 읽도록 요청한다. `.agents/skills/`를 일반 ChatGPT가 자동 실행한다고 가정하지 않는다.

## 새 대화의 시작 요청

> 루트 AGENTS.md와 프로젝트 기억과 작업 인계, 기획 진행 현황과 후속 작업, 현재 검토할 기획 질문을 읽어라. 현재 기획 기준과 미실시 작업을 먼저 요약하고 해당 주제의 기준 문서를 확인한 뒤 이어서 작업하자. 기존 제안이나 과거 보관 본문을 현재 결정으로 바꾸지 말고, 사용할 프로젝트 스킬과 도구 준비 상태를 확인해라.

읽기 확인에서는 현재 버전, 열린 질문, 미실시 검증, 요청한 작업의 주제 기준 및 사용 스킬을 확인한다. 같은 기억에서 출발한다는 의미는 같은 결정과 제약을 참조한다는 뜻이며 응답 문장이나 판단 결과가 완전히 같다는 보장은 아니다.

## 컴퓨터를 바꿀 때

작업 시작 전 로컬 변경을 확인하고 최신 저장소 내용을 받는다. 작업 종료 시 결정·상태·후속 작업을 문서에 남겨 동기화한다. 두 컴퓨터에서 같은 문서를 동시에 수정했다면 양쪽 결정과 변경 이력을 비교해 충돌을 해결한다. 작업 내용을 폐기하거나 강제 푸시하는 방식으로 맞추지 않는다.

## 이관 범위

기획 문서, 결정 기록, 작업 지침, 프로젝트 스킬과 참조 파일을 공유한다. 개인 메모리 폴더 전체, 다른 게임 프로젝트의 기록, 개인 대화 로그와 인증 자료는 포함하지 않는다. 기존 `80 참고자료/` 보존본은 그대로 유지한다.
