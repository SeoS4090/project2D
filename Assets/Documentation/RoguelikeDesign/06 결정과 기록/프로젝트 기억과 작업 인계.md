# 프로젝트 기억과 작업 인계

## 이 문서의 역할

2026-10-08까지의 사용자 요청과 현재 Vault 문서에서 프로젝트 관련 기억을 정리했다. 다른 컴퓨터와 새 대화가 같은 결정과 작업 방식에서 출발하도록 돕는다. 개인 메모리 전체나 대화 로그의 복제본은 아니다. 실제 기획 원본은 링크된 주제 기준이며, 이 요약과 기준이 다르면 최신 사용자 결정·변경 이력·해당 주제의 현재 적용 기준을 확인한다.

## 기획 의도와 유지할 방향

- 2D 도트 그래픽의 탑다운 전방향 이동과 빠른 액션에 카드·아이템·태그의 연쇄 시너지를 결합한다.
- 2030년 지구와 이세계 신의 검은 탑을 배경으로 마을에서 무기를 선택해 출발하고, 방의 전투와 보상으로 빌드를 만들며 반복 도전한다. 세계관과 런의 세부는 아래 기준을 따른다.
- 시작 무기·덱·속성·전투 스타일을 연결하고, 신화 장인의 강화가 해당 신화의 외형과 전투 성향으로 드러나게 한다. 장인의 양식과 최종 신성의 권능은 역할을 구분한다.
- 훈련장은 전투·빌드 시험을 담당하고, 만신전과 별도 성장 시설은 영구 성장·해금의 역할을 가진다.
- 현존 종교에서 실제 숭배되는 신격을 제외한다는 사용자 콘텐츠 원칙을 유지한다. 신화권 이름만으로 개별 콘텐츠 사용을 확정하지 않는다.

## 사용자가 정한 기본 전투의 기억

- 스태미나와 점프를 도입하지 않는다. 마나는 자연 회복하고 방의 전투가 실제로 끝나면 빠르게 회복한다. 아이템과 권능으로 최대 마나와 회복량을 강화한다.
- 무기별 연격 수와 종료 공백을 가진다. 원거리는 장탄·재장전으로 제한한다. 대검 3회·단검 5회 같은 발언의 숫자는 예시이며 실제 데이터의 확정값으로 취급하지 않는다.
- 누르고 있기와 연타 모두 지원한다. 버튼 해제만으로 현재 타격을 즉시 취소하지 않는다. 다음 타격 예약과 연결 허용 처리를 따르며 중단 후에는 첫 타격부터 시작한다.
- 공격속도는 연격부터 종료 공백까지 전체 사이클을 같은 비율로 축소한다. 사이클의 리듬 비율을 유지한다.
- 조준과 이동은 분리한다. 준비 중 조준을 갱신하고 실행 시 타격별 방향을 고정한다.
- 대시는 충전 횟수와 순차 재충전으로 제한한다. 연속 대시마다 방향을 다시 정할 수 있고, 대시 중 무적을 적용한다. 대시와 공격·특수행동은 별도로 진행한다.
- 공격 취소 버튼은 없다. 검과 방패의 방어, 대검 모아치기, 원거리 수동 재장전, 단검 패링은 플레이어가 특수행동 버튼으로 사용하는 무기 능력이다. 강한 피격 이후에만 가능한 능력으로 해석하지 않는다.
- 일반 공격 중 특수행동 요청은 현재 타격을 마친 뒤 실행한다. 일반 중단은 준비 단계에서만 취소한다. 기절·사망 등의 예외와 밀려남의 처리 범위는 상세 기준을 따른다.

## 현재 진행과 다음 작업

기획 기준은 v0.23이다. 등록한 전투 구조 질문은 해결했고 기초 전투 구현에 착수할 수준의 규칙을 갖췄다. 전투 규칙의 기존 열린 구조 질문은 없다. 현재 Unity 기술 선택 T01–T03을 검토하며 전체 게임의 누락이 없다는 보증은 아니다. 이 상태는 작성일의 요약이며 이후에는 [[06 결정과 기록/현재 검토할 기획 질문]]과 [[06 결정과 기록/기획 진행 현황과 후속 작업]]을 우선 확인한다.

project2D 저장소에는 훈련장과 Hero V2 중간 구현 및 당시 확인 기록이 있다. 실제 게임데이터 Excel·전체 게임 규칙의 검증·새 분리 Prefab 방식의 구현과 시험은 후속이다. 다음 목록은 전체 규칙을 위한 작업이며, 기존 소규모 프로토타입의 동작만으로 완료 처리하지 않는다.

1. 현재 전투 규칙을 개발용 상태 전이표로 연결한다. 공격·대시·피격·특수행동·자원·사망의 병행과 우선순위를 확인한다.
2. Excel의 최소 테이블과 임시 데이터를 작성한다. ID·열·단위·읽는 시점을 기준 문서와 연결한다.
3. 단일 방과 최소 무기·적을 구현해 기본 조작 및 충돌을 검증한다.
4. [[05 검증과 확장/프로토타입 범위와 검증]]의 미실시 시험을 수행하고 결과에 따라 해당 범위만 재검토한다.

## 작업 방식의 기억

한국어로 구체적으로 설명하고, 제안과 채택을 분리한다. 사용자가 채택한 규칙은 이후 문서와 상태 목록까지 반영한다. 검토가 끝난 항목에 미정 제목을 계속 남기지 않는다. 규칙·Excel 수치·실제 검증의 상태를 각각 관리한다. 기존 결정을 변경하면 이유와 영향 범위를 기록한다.

문서 작성은 Obsidian CLI를 우선 사용하고 MOC 및 내부 연결을 유지한다. 수치와 콘텐츠 다양성은 Excel에서 관리하되 문서에 열의 의미·ID 관계를 남긴다. 보존 원본은 변경하지 않는다.

## 기억의 갱신

새 결정은 주제 기준 → 질문·완료 기록 → 영향 MOC → 변경 이력 → 시험 목록 순서로 반영한다. 이 문서는 진행 단계나 공통 작업 방식이 달라졌을 때 갱신한다. 상세 규칙을 계속 복제해 제2의 기준으로 만들지 않는다.

## Unity 기술 진행 추가 — 2026-10-07

당시 기록: 사용자 지정 기술 기준은 Unity 6.3 LTS `6000.3.18f1` + URP 2D이며, [[00 MOC/Unity 기술 MOC]]에 tech-0.1 프레임워크 초안을 추가했다. 이 시점에는 실제 구현이 없었다. 최신 기술 선택과 구현 상태는 활성 목록과 아래 추가 기록을 우선한다.

## 첫 제작의 순서 변경 — tech-0.2

사용자는 첫 제작을 훈련장으로 정했다. [[07 Unity 기술/훈련장 기반 기술 프로토타입]]과 [[07 Unity 기술/기술 검증과 제작 순서]]의 현재 순서를 따른다. 개발용 시험 도구와 플레이어용 해금/과제 기능을 구분하고 기존 R03을 유지한다. 실제 던전의 진행·정산·저장 통합 시험은 후속이다.

## 캐릭터 아트와 분리 제작 추가 — 2026-10-08

사용자는 인체 비율과 32×64 규격을 고정하지 않고 공격의 중요 부위를 중심으로 비율을 재검토하도록 요청했다. 이어 캐릭터와 무기를 각각 생성하고 별도 Prefab으로 장착하는 방식을 제안하고 Vault 정리를 요청했다. [[07 Unity 기술/캐릭터 비율과 픽셀 아트 제작]]과 [[07 Unity 기술/캐릭터와 무기 분리 제작]]을 다음 논의의 기준으로 읽는다. 세부 구현 제안·미실시 시험과 현재 Hero V2를 구분하며, 기존 전투 규칙의 조준·교체·판정 경계는 유지한다.
