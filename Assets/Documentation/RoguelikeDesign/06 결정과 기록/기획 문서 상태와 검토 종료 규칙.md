# 기획 문서 상태와 검토 종료 규칙

## 제목과 상태의 역할

주제 문서는 `조준과 이동`, `마나 자원과 회복`처럼 지속해서 사용할 주제 이름으로 작성한다. 미정·미확정·미검토·설계안은 현재 상태를 나타내므로 일반 주제 문서의 제목에 붙이지 않는다. 과거 제안만 보관하는 문서는 `초기 기획안 검토 기록`처럼 기록임을 제목에 표시한다. 기존 설계안 문서는 현재 기준 안내와 보관 본문을 확인한 후 주제 문서와 통합하거나 기록으로 분류한다. 일괄 이름 변경만으로 제안을 채택하지 않는다.

`status`는 문서 역할을 표시한다: 기준 / 검토 / 현황 / 기록 / 운영 / 목차 / 템플릿 / 참고자료. 기획 문서에는 필요에 따라 `design_status`(미검토 / 검토 중 / 규칙 결정 / 일부 결정 / 해당 없음), `validation_status`(미실시 / 진행 중 / 검증 완료 / 해당 없음)를 별도로 기록한다. 기존 `확정`, `혼합`, `규칙 검토 완료` 등의 값은 해당 문서를 수정할 때 이 체계로 옮기되 사용자 채택과 위임에 따른 설계 결정을 본문에서 구분한다.

숫자·콘텐츠가 후속이어도 구조 규칙이 결정됐다면 `design_status: 규칙 결정`이다. 체크 완료는 해당 질문의 설계 답변 완료이며 구현 또는 플레이 검증 완료를 의미하지 않는다. 검증 완료에는 실제 수행 결과와 근거가 필요하다.

## 목록의 관리 책임

- [[06 결정과 기록/현재 검토할 기획 질문]]: 아직 답이 필요한 구조 질문만 관리한다.
- [[06 결정과 기록/기획 검토 완료 기록]]: 해결한 질문과 현재 기준 문서, 결정 경위를 보존한다.
- [[06 결정과 기록/기획 진행 현황과 후속 작업]]: 위 두 목록과 Excel·제작·검증·확장 작업을 안내한다.
- [[05 검증과 확장/프로토타입 범위와 검증]]: 실제 구현과 플레이 시험을 관리한다.

각 질문에는 고유 ID, 범위, 상태, 완료 조건, 관련 기준 링크를 둔다. 구조 질문·Excel 작업·구현 검증·확장 후보를 같은 미정 체크리스트로 섞지 않는다. 활성 질문의 원본은 현재 검토 목록 하나이며 MOC와 주제 문서는 링크로 안내한다.

## 검토 종료 시 함께 처리할 일

1. 정한 답을 주제 기준 문서에 반영한다. 현재 기준은 한 곳에서 관리하고 다른 문서는 링크한다.
2. 질문의 완료 조건을 충족했는지 확인하고 결정 근거와 적용 범위를 기록한다. 단순 초안 작성만으로 완료 처리하지 않는다.
3. 해결된 질문을 완료 기록으로 옮긴다. 활성 목록에는 미해결 질문만 남기고, 모두 해결되면 `현재 열린 질문 없음`이라고 표시한다.
4. 파일명·title·첫 제목·status·상태 태그·MOC 표시 문구를 함께 갱신한다. 완료된 문서에 현재의 미정 상태를 뜻하는 표시를 남기지 않는다.
5. 예전의 `아직 미정`, `다음 검토` 문장은 현재 안내에서 제거하고 필요하면 날짜·버전이 있는 접힌 과거 기록으로 보관한다. 수치 예시는 실제 데이터로 승격하지 않는다.
6. Excel 작업과 구현 검증은 별도 후속 목록에 유지한다. 규칙 결정만으로 시험 결과를 체크하지 않는다.
7. 변경 이력과 관련 링크를 갱신하고 깨진 링크·상태 불일치·활성 목록의 완료 항목을 확인한다.

## 새 질문과 재검토

완료 이후 발견한 질문은 새 ID로 등록한다. 기존 결정 전체를 미정으로 되돌리지 않고 영향을 받는 절과 추가 질문을 특정한다. 이전 답을 실제로 바꿔야 할 때만 해당 질문을 `재검토`로 표시하고 변경 이유와 이전 결정 링크를 남긴다. 새 질문이 생겼다는 사실이 기존 완료 기록을 무효화하지 않는다.

## 보존과 연결

이름 변경은 Obsidian의 이동 기능으로 수행하고 내부 링크를 확인한다. 기존 이름이 검색에 필요하면 aliases에 보관하되 MOC에는 새 이름을 표시한다. 보존 원본과 동기화 참고자료는 변경하지 않는다. 이 규칙은 문서 정리 때 적용하며 상시 자동 실행을 뜻하지 않는다.
