# Obsidian 플러그인과 작업 관리

## 적용 범위와 원본

2026-10-11 사용자 요청으로 공유 채팅의 제안을 현재 project2D 환경에 적용했다. 실제 Vault 루트는 Unity 프로젝트 루트이며 기획 원본은 `Assets/Documentation/RoguelikeDesign/`이다. 채팅의 `Docs/` 예시는 현재 경로가 아니다. 기존 문서를 이동하거나 복제하지 않는다. 개인 Obsidian_Memo Vault는 이번 적용 범위에서 제외한다.

[[개발 작업 대시보드]]에서 기존 기획 목록과 실행 작업을 연결한다. 게임 규칙의 상태는 [[기획 문서 상태와 검토 종료 규칙]]이 기준이다.

## 플러그인 구성

| 플러그인 | 적용 | 용도와 설정 |
|---|---|---|
| Tray 0.3.5 | 기존 유지 | 기존 창 관리 |
| Templater 2.25.1 | 설치·활성화 | `90 템플릿`을 지정, 생성 시 자동 실행·시작 템플릿·사용자 스크립트 없음 |
| Dataview 0.5.68 | 설치·활성화 | 작업 속성 조회, DataviewJS/인라인 JS 꺼짐 |
| 기본 Templates, Canvas, Bookmarks, File recovery | 기존 유지 | 일반 템플릿·도식·탐색·복구 |
| QuickAdd, Tasks | 보류 | 빠른 등록이나 체크리스트 집계가 실제로 필요할 때 도입 |
| Excalidraw | 보류 | Canvas·Mermaid로 부족한 자유형 도식이 생길 때 도입 |
| Obsidian Git | 보류 | 현재 Unity 저장소 전체의 Git 작업은 기존 개발 흐름으로 관리 |
| Kanban, Homepage, 자동 이동·일괄 서식 플러그인 | 보류 | 상태 중복과 문서 일괄 변경을 먼저 피하고 필요 범위를 정한 뒤 도입 |

## 작업 속성 계약

- `status`: 기존 문서 역할(기준/검토/현황/기록/운영/목차/템플릿/참고자료).
- `task_status`: 초안 → 준비 → 진행 → 검토 → 완료. 검토 실패는 진행으로 되돌린다. 보류 상태에는 이유와 재개 조건을 적는다.
- `verification`: 미실시 / 진행 중 / 통과 / 실패 / 해당 없음. 결과와 실행 근거를 본문에 남긴다.
- `priority`: 1 긴급, 2 보통, 3 후순위. 숫자 오름차순으로 조회한다.
- `task_id`: 문서별 고유 ID. 파일명 변경과 별개로 유지한다.
- `specs`: 기준 문서의 wikilink 목록. 제안은 채택 여부를 명시한다.

작업은 `08 작업 명세`에 두며 한 기능이나 한 관리 작업 단위로 작성한다. 기존 후속 목록을 모두 복제하지 않고, 착수할 항목만 실행 명세로 구체화한다. 작업 상태 원본은 각 명세의 속성이며 대시보드는 읽기 전용 집계다. 완료 조건에 남은 검증이 있다면 완료로 표시하지 않는다.

## 작성과 실행

1. `08 작업 명세`에서 이름이 있는 새 노트를 만든다.
2. 명령 팔레트의 **Templater: Open insert template modal**로 [[작업 명세 템플릿]]을 넣는다. 동적 템플릿은 기본 Templates 명령으로 넣지 않는다.
3. 목표·기준 링크·수정 범위·완료 조건·검증 요청 범위를 채운다. `초안`은 자동 실행 대상이 아니다.
4. 사용자에게 실행 요청을 받은 작업 범위만 구현한다. 템플릿 자체는 테스트 실행이나 외부 전송을 승인하지 않는다. 테스트는 사용자가 요청한 경우 작성·실행한다.
5. 변경과 실제 확인 근거를 작업 문서에 남긴다. 주제 규칙은 해당 기준 문서, 중요한 결정은 [[설계 결정 템플릿]], 결과는 [[작업 결과 템플릿]]으로 연결한다.

## 유지보수와 복구

새 플러그인은 목적·중복 기능·공식 커뮤니티 ID·버전·설정·제거 시 영향을 먼저 기록한다. 업데이트 전 `.obsidian`을 Vault 밖 로컬 백업에 복사하고 한 번에 한 플러그인을 변경한다. 이후 해당 명령·대시보드 표시·오류를 확인하고 버전을 갱신한다. 예약 자동화는 아직 등록하지 않았다.

이번 백업: `%LOCALAPPDATA%/Project2D-Obsidian-Backups/20261011-184407/.obsidian`. 복구는 Obsidian 종료 후 필요한 설정/플러그인 폴더를 백업에서 복사하고 재실행한다. 이번에 추가한 두 플러그인은 이전 백업에 없으므로 제거가 필요하면 Obsidian 설정에서 제거한다. 문서는 일반 Markdown이므로 플러그인을 꺼도 본문과 상태값은 남고 집계·동적 템플릿만 중단된다.

루트 `.obsidian/`와 `.trash/`는 Git에서 제외한다. 설정·플러그인 코드·로그를 저장소에 올리는 대신 이 설치 목록으로 다른 PC에서 재현한다. 자동 커밋/푸시, 문서 외부 전송, 예약 작업은 이번 구성에 포함하지 않았다.
