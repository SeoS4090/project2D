# 기획 Vault 점검

반복되는 문서 정합성 확인을 수행한다. 읽기 전용 검사이며 판단이나 수정은 별도 작업이다.

## 범위 선택

루트 `AGENTS.md`와 `06 결정과 기록/기획 문서 상태와 검토 종료 규칙.md`를 읽는다. 일반 갱신 뒤에는 바뀐 노트만 검사하고 전체 점검 요청에는 전체를 검사한다. 보존 원본·템플릿·숨김 스킬은 검사의 본문 대상에서 제외하지만 노트·첨부 링크의 대상으로는 찾는다.

이 스킬 폴더 기준 `scripts/audit_vault.py`를 Python 3 표준 라이브러리만으로 실행한다. Python과 Vault의 실제 경로를 발견해 명령 배열로 전달한다. 특정 컴퓨터의 설치 경로를 고정하지 않는다.

```text
python <skill-dir>/scripts/audit_vault.py --vault <vault-root>
python <skill-dir>/scripts/audit_vault.py --vault <vault-root> --files "06 결정과 기록/현재 검토할 기획 질문.md" --format json
```

`--files`는 Vault 루트 상대 경로들을 받으며 Vault 밖 파일을 허용하지 않는다. 생략하면 전체 현재 노트를 검사한다. 결과는 stdout, 스크립트는 파일을 수정하지 않는다. 오류가 있으면 종료 코드 1, 경고만 있거나 문제가 없으면 0이다. 전체 결과의 오류 수와 경고 수를 분리해 읽는다.

## 결과 해석

- 연결 오류: 존재하지 않는 노트·첨부 또는 절·블록 참조. 중복 이름·별칭 후보는 경고이므로 Obsidian의 실제 연결 대상으로 확인한다.
- 문서 경고: title·파일명·첫 H1 불일치, 과거 `status` 값, 기준 노트의 미정 제목, 활성 질문 목록의 완료 체크. 과거 상태는 운영 규칙상 수정할 때 이행하므로 일괄 오류로 처리하지 않는다.
- 속성 오류: 현재 역할 체계의 노트에서 잘못 지정한 `design_status`·`validation_status` 값.

검사는 일반 YAML 문자열·aliases 목록과 표준 wikilink·헤딩·블록을 지원한다. 코드 예시와 주석을 제외한다. 외부 Markdown 링크, Obsidian의 모든 경로 해석, 사용자 채택 근거, 의미상 충돌, 검증 근거는 자동 판정하지 않는다. 애매한 결과는 노트 원문과 Obsidian에서 확인한다.

## 후속 처리

점검 요청만 받았으면 문제 위치·영향·권장 수정과 검사 한계를 보고하고 끝낸다. 정리나 수정도 요청받았다면 현재 결정 근거와 연결 대상을 확인해 해당 범위만 고친다. 이름 변경은 Obsidian에서 하고 주변 링크를 확인한다. 보존 원본을 수정하지 않는다. 문서의 상태만 보고 규칙을 채택하거나 시험을 완료하지 않는다.

수정 후 바뀐 노트만 다시 검사한다. 전체 점검에서 발견한 기존 문제는 새 변경으로 생긴 문제와 구분해 보고한다. 게임 플레이 검증과 다른 컴퓨터의 자동 스킬 인식은 이 검사 결과로 보장하지 않는다. Git 커밋·푸시는 해당 세션의 사용자 권한을 확인한다.
