# 연결 조건 검토

미검토 사항 찾기 또는 여러 전투 규칙을 연결할 때만 필요한 항목을 확인한다. 질문 수를 채우기 위한 목록이 아니다. 현재 주제 기준과 완료 기록에서 답을 먼저 찾는다.

| 접점 | 확인할 질문 |
| --- | --- |
| 입력·상태 | 누르고 있기·연타·해제·중립·예약 만료가 겹쳐도 하나의 실행 계약인가? 준비·실행·후딜·공백의 경계는 무엇인가? |
| 병행 행동 | 이동·조준·대시·공격·특수행동·밀려남은 병행하는가? 취소 가능한 단계와 방향 고정 시점은 무엇인가? |
| 비용·능력치 | 예약·실행·취소 때 비용과 반환이 한 번인가? 값은 언제 고정하며 보유량·예약량·사용 가능량을 구분하는가? |
| 피해·방어 | 동일 타격 재접촉, 복수 충돌체·패링·무적·대상 상한, 같은 시간의 사망·회복을 일관되게 처리하는가? |
| 효과 연쇄 | 논리적 출처·실행 ID·대상 ID·root의 역할과 수명은 무엇인가? 상태 갱신·지속 틱이 연쇄 제한을 우회하는가? |
| 적·판정 | 준비 후 시야·거리·경로 변화, 경직·패링, 벽·관통·폭발과 발생원 소멸의 계약이 있는가? |
| 방·런 전환 | 방 완료·보상·저장·불러오기 때 충전·장탄·쿨타임·버프·예약·RNG 중 무엇이 유지되는가? |
| 데이터·시험 | 구조 공백인가, Excel 값·콘텐츠 선택인가, 구현 후 시험인가? 후속 상태를 잘못 미정으로 표시한 것은 아닌가? |

새 질문에는 충돌하는 기준 링크, 실제 발생 순서의 예시, 결정이 필요한 범위와 완료 조건을 적는다. 사례 한 개의 특수 해결책을 전체 규칙으로 일반화하지 않는다. 기존 사건 처리·비용·출처·전환 계약을 연결하면 해결되는 질문은 새 규칙을 늘리지 않는다.

사용자에게 제안할 때는 선택지와 조작감·일관성·데이터·개발 영향으로 비교한다. 다른 게임이나 버전별 동작을 근거로 쓸 때는 공식 자료를 확인하고 확인된 사실과 설계 추론을 구분한다.
