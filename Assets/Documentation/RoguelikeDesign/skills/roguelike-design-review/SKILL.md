# 로그라이크 기획 검토와 반영

새 논의를 현재 기준에 연결하고 결정·데이터·검증 상태를 함께 정리한다. 이 스킬은 기획 Vault에 한정하며 게임 규칙 원본을 자체 보관하지 않는다.

## 시작과 작업 범위

Vault 루트의 `AGENTS.md`, `06 결정과 기록/기획 문서 상태와 검토 종료 규칙.md`를 읽고 해당 주제 기준과 현재 질문을 찾는다. 진행 상태는 `기획 진행 현황과 후속 작업.md`, 과거 답은 `기획 검토 완료 기록.md`에서 확인한다. 이전 보관 본문과 현재 적용 기준을 구분한다. 문서에 기록된 버전·질문 상태를 읽으며 v0.23이나 특정 ID를 영구 기본값으로 고정하지 않는다.

- **검토·추천 요청**: 현재 결정 → 남은 구조 질문 → 선택지와 영향 → 추천 순서로 답한다. 조사나 추천만으로 채택 처리하지 않는다. 사용자가 설계를 위임한 범위에서는 판단 근거를 남겨 기준을 완성한다.
- **채택·문서 갱신 요청**: 최신 사용자 답과 기존 위임을 확인해 결정한 범위만 반영한다. 과거 질문의 재답변·재승인을 요구하지 않는다. 결과가 필수 입력에 의존하면 그 항목을 질문하고 나머지 독립 작업을 진행한다.
- **미검토 사항 찾기**: [연결 조건 검토](references/edge-review.md)를 필요한 범위만 읽고 기존 완료 조건과 대조한다. 실제 규칙 공백·충돌만 새 ID로 등록한다. 값이 아직 없거나 시험이 미실시인 것만으로 구조 질문을 다시 열지 않는다.

## 기준 문서에 반영

결정에 플레이어가 보는 행동, 발동 조건, 처리 순서·실패·중단, 비용 지불·반환, 저장·전환의 경계를 필요한 만큼 포함한다. 일반 규칙과 명시적 예외를 연결한다. 기존 주제 기준을 먼저 수정하고 새 문서는 독립적으로 바뀌는 주제일 때만 만든다. MOC와 인계 요약에서 상세 규칙을 복제하지 않는다.

실제 값·콘텐츠 행은 Excel 후속으로 둔다. `05 검증과 확장/게임데이터 열 정의.md`와 `Excel과 기획 문서의 연결.md`를 확인해 기존 열을 재사용한다. 필요한 추가 열은 논리 테이블·열 이름·고정 ID 관계·자료형·단위·읽는 시점·유효 조건을 설명한다. 런타임 상태와 정적 Excel 열을 구분하고 설명용 숫자나 행 번호를 실제 데이터 ID로 바꾸지 않는다.

## 검토 종료

질문의 원래 완료 조건이 충족됐는지 확인한다. 충족한 항목은 ID·조건·근거·기준 링크를 보존해 완료 기록으로 이동한다. 열린 목록에는 미해결 질문만 남긴다. 새 질문은 기존 모든 기록에서 ID 중복을 검색해 등록한다. 기존 결정 변경일 때는 이전 답과 영향을 명시한다.

관련 주제·MOC·진행 현황·변경 이력·시험 시나리오를 함께 갱신한다. 주제 제목과 문서 역할 `status`, `design_status`, `validation_status`를 분리한다. 실제 실행 근거 없이 시험 체크를 완료하지 않는다. 예전 미정 설명은 현재 안내에서 제거하거나 버전 있는 과거 기록으로 구분한다. 오래된 템플릿 예시보다 현재 운영 규칙을 우선한다.

## 작성과 확인

프로젝트의 `obsidian-cli`·`obsidian-markdown` 스킬을 사용해 노트를 작성하고 읽어서 확인한다. CLI는 Vault를 첫 인수로 지정하고 명령 배열로 호출한다. 일반 파일 도구는 스킬·검사 도구에 사용한다. CLI가 unavailable이면 프로젝트 지침의 대체 절차를 따른다. 보존 원본은 변경하지 않는다.

변경 문서의 연결·제목·상태는 `obsidian-design-audit` 스킬 또는 이에 준하는 읽기 전용 점검으로 확인한다. 검사 성공을 게임 동작 검증으로 표현하지 않는다. Git 작업은 사용자 요청이나 유지 중인 동기화 권한에 따르며 이 스킬 자체는 푸시 권한을 부여하지 않는다.

사용자에게 결정·반영 문서·확인 결과·남은 데이터와 실제 시험을 간결히 보고한다. 논의만 했으면 문서를 갱신했다고 보고하지 않는다.
