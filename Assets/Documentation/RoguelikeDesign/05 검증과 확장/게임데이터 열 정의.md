# 게임데이터 열 정의

## v0.18 현재 적용 기준

행동 규칙은 v0.18 보강 기준을 따른다. 아래 열 이름은 후속 Excel 제작의 연결 명세이며 실제 콘텐츠 값과 게임 로더 구현이 완료되었다는 뜻은 아니다. 동일 의미의 기존 열이 있으면 재사용하고 표시 이름으로 연결하지 않는다. 입력 단위는 기존 `_sec`·`_ratio`·`_count` 규칙을 유지한다.

| 열 또는 관계 | 자료형·단위 | 필수·허용값·참조와 읽는 시점 |
| --- | --- | --- |
| CombatConfig.dash_buffer_window_sec | 실수·초 | 필수, 양수, 대시 요청 입력 시 실시간 만료 계산 |
| CombatConfig.action_buffer_window_sec | 실수·초 | 필수, 양수, 다른 특수행동 중 새 요청에 적용; 현재 일반 타격에 묶인 요청은 해당 타격 완료까지 유지 |
| HitResponseConfig.damage_protection_sec | 실수·초 | 기존 열 재사용, 음수 금지, 유효 직접 피해 후 시작 |
| AttackStep.knockback_units | 실수·월드 단위 | 기존 의미 재사용, 음수 금지, 0은 밀려남 없음 |
| AttackStep.knockback_duration_sec | 실수·초 | 거리가 양수면 필수·양수, 실제 밀려남 발생 시 읽음 |
| AttackStep.knockback_direction_mode | 열거형 | 밀려남 있으면 필수, radial 또는 attack_forward |
| AttackStep.blockable / parryable | 참거짓 | 직접 공격이면 필수, 판정 시 방어·패링 허용 검사 |
| AttackStep.parry_response_id | 텍스트 ID | 정예·보스 패링 가능 공격이면 필수, ParryResponse의 존재 ID |
| AttackStep.hit_mode / tick_interval_sec | 열거형 / 실수·초 | single 또는 periodic; periodic일 때 주기 필수·양수; 한 주기를 새 적중 단위로 사용 |
| EnemyArchetype.stagger_profile_id | 텍스트 ID | 필수, StaggerProfile 참조; 일반·정예·보스 구간별 저항 |
| StaggerProfile.stagger_profile_id / phase / weak_stagger_policy | ID / 열거형 / 열거형 | 복합 키 ID+phase, phase는 windup·active·recovery, policy는 allow·immune |
| EnemyArchetype.heavy_attack_condition_set_id | 텍스트 ID | 강공격 적이면 필수, 기존 ConditionSet 참조 |
| EnemyArchetype.telegraph_resource_id | 텍스트 ID | 강공격 적이면 필수, Resource 참조 |
| Room.heavy_attack_budget_id | 텍스트 ID | 전투 방 필수, HeavyAttackBudget 참조 |
| HeavyAttackBudget.max_concurrent_count / start_interval_sec | 정수·개수 / 실수·초 | 각각 양수·음수 금지, 강공격 준비 시작 허가 시 검사 |

| WeaponAction.guard_angle_deg / guard_damage_ratio | 실수·각도 / 실수·배율 | guard일 때 필수, 각도 0 초과 360 이하·피해 배율 0 이상 1 이하 |
| WeaponAction.parry_window_sec / cooldown_sec | 실수·초 | parry일 때 필수·양수, 실제 패링 시작 시 고정 |
| WeaponAction.charge_max_sec | 실수·초 | charge_attack일 때 필수·양수; 피해·범위 곡선은 별도 ChargeCurve 참조 |
| ReloadProfile.capacity / automatic_reload / manual_reload | 정수 / 참거짓 | 기존 열 재사용, capacity 양수; 기본 활·석궁은 자동·수동 모두 지원 |

| ManaConfig.room_clear_regen_rule | 열거형 | max_of_natural_and_ratio, 완료 상태에서만 읽고 합산하지 않음 |
| Effect.trigger_event / target_rule | 열거형 | 지원 목록에서 선택, 추가 효과 적중 수신 여부와 대상 종류를 구분 |
| CombatConfig.proc_max_depth | 정수·깊이 | 양수, 같은 root 연쇄 상한; 실제 값은 Excel 후속 |
| DivinityStage.activation_event / condition_set_id | 열거형 / 텍스트 ID | discovered는 select, 이후는 shrine_use, 요구량은 ConditionSet으로 참조 |
| RunSettlement.result_type / retain_ratio | 열거형 / 실수·배율 | death·abandon·clear, 0 이상 1 이하; 실패 두 유형은 같은 정산 정책 참조 |

ParryResponse·ChargeCurve·HeavyAttackBudget·StaggerProfile은 행동별 추가 논리 테이블이다. ID는 텍스트이며 활성 행의 없는 참조·중복 키·미지원 열거값은 오류로 처리한다. 조건의 요구량·기술 비용·곡선 값·단계별 보상량과 프리셋 콘텐츠 목록은 Excel 작업에서 작성한다. 준비 비용 예약, 현재 충전, 피격 보호 남은 시간, root ID·공격 실행 ID, 기절 종료 시각과 정산 ID는 실행·저장 상태이며 Excel의 고정 콘텐츠 값으로 넣지 않는다.

## 정의의 상태와 읽는 방법

아래는 실제 Excel 제작을 위한 열 정의 초안이다. 테이블 하나를 시트 하나로 만드는 구조를 우선 제안하되, 논리 테이블과 실제 파일 배치는 구분한다. 열 이름을 확정하기 전에는 게임과 자동 연결되지 않는다. 실제 수치와 콘텐츠 행은 이 문서에 작성하지 않는다.

이름은 영어 소문자와 밑줄로 통일하고 단위를 열 이름에 포함한다. `_sec`는 초, `_ratio`는 배율이며 1은 100%다. `_per_sec`는 초당 값, `_count`는 개수다. 확률을 배율로 표현하면 0~1을 사용하며, 확률의 퍼센트포인트 변화와 곱하는 배율은 별도 열로 구분한다. Excel에 50과 0.5를 섞어 같은 50%를 뜻하게 하지 않는다.

## 공통 열

| 열 | 형식 | 의미와 제약 |
| --- | --- | --- |
| 각 테이블의 주 ID | 텍스트 | 고정 식별자, 중복과 빈 값 금지 |
| name_key | 텍스트 | 표시 이름의 참조 키, ID와 분리 |
| enabled | 참거짓 | 게임에서 사용 여부, 참조 검증과 별개 |
| design_ref | 텍스트 | 대응하는 Obsidian 문서의 vault 상대 경로, wikilink를 읽는 도구를 가정하지 않음 |
| note | 텍스트 | 입력 및 검토 메모, 게임 동작을 정의하는 코드로 해석하지 않음 |

연결용 ID는 앞의 0이 유지되도록 Excel에서도 텍스트로 작성한다. ID와 표시 이름은 따로 변경할 수 있어야 한다. 연결 행에는 복수 키를 사용할 수 있으며 모든 테이블에 개별 ID를 억지로 추가하지 않는다.

## 열별 명세를 작성하는 기준

아래 형식으로 열별 명세를 확장한다. 자료형, 단위, 필수 여부, 참조 대상과 읽는 시점을 분리한다. 아직 결정하지 않은 기본값은 임의로 넣지 않는다. 시간 배율 고정은 v0.18 C16을, 피해용 능력치 고정은 v0.19 D09를 따른다. 비례 축소라는 기존 확정 규칙을 유지한다.

| 열 | 자료형과 단위 | 필수 여부와 참조 | 뜻과 읽는 시점 |
| --- | --- | --- | --- |
| Weapon.weapon_id | 텍스트 ID | 필수, Weapon 내 고유 | 무기 식별, 선택 및 장착 시 |
| Weapon.attack_pattern_id | 텍스트 ID | 필수, AttackPattern.pattern_id | 사용할 공격 패턴, 기본 공격 시작 시 |
| Weapon.reload_profile_id | 텍스트 ID | 재장전 방식이면 필수, ReloadProfile.reload_profile_id | 장탄과 재장전 규칙, 무기 장착 및 재장전 시 |
| AttackStep.pattern_id | 텍스트 ID | 필수, AttackPattern.pattern_id | 타격이 속한 패턴, 연격 구성 시 |
| AttackStep.step_index | 정수, 순번 | 필수, pattern_id와 복수 키 | 연격의 몇 번째 타격인지, 다음 타격 선택 시 |
| AttackStep.windup_sec | 실수, 초 | 필수, 음수 금지 | 실행 전 준비 시간, 해당 타격 시작 시 |
| AttackPattern.combo_end_gap_sec | 실수, 초 | 연격 방식이면 필수, 음수 금지 | 완주 공백과 중단 대기, 연격 종료 또는 중단 판정 시 |
| ManaConfig.regen_per_sec | 실수, 마나/초 | 필수, 음수 금지 | 자연 회복 속도, 회복량 계산 시 |
| CardEffect.effect_id | 텍스트 ID | 필수, Effect.effect_id | 카드가 주는 효과, 장착 변경 시 효과 등록 후 발동 규칙에 따라 사용 |
| ConditionTerm.number_value | 조건에 따른 숫자 | 수량 비교 조건이면 필수 | 요구량, 조건 검사를 수행하는 사건에서 사용 |

전체 열의 필수 여부와 허용값 목록은 관련 행동 규칙이 확정되는 순서대로 이 형식을 사용해 보강한다. 이 문서의 주요 열 목록은 모든 열의 명세가 완성되었다는 뜻이 아니다.

## 무기와 기본 공격

| 테이블 | 주요 열 | 문서에서 정의할 의미 |
| --- | --- | --- |
| Weapon | `weapon_id`, `family_id`, `attack_pattern_id`, `reload_profile_id`, `attack_move_speed_ratio` | 무기 분류, 사용할 공격 패턴, 선택적 재장전, 공격 중 이동 배율 |
| WeaponFamily | `family_id` | 무기 분류의 고정 ID와 이름, 실제 태그 부여는 TagGrant에서 관리 |
| AttackPattern | `pattern_id`, `attack_mode`, `combo_end_gap_sec` | 연격 또는 탄창 또는 단발 재장전 방식, 연격 종료 공백 |
| AttackStep | `pattern_id`, `step_index`, `windup_sec`, `active_sec`, `recovery_sec`, `damage_coefficient_ratio`, `attack_shape_id` | 타격 순서, 각 구간의 기본 시간, 기본 공격력 대비 계수, 범위 형태 |
| AttackShape | `attack_shape_id`, `shape_type`, `range_units`, `width_units`, `angle_deg` | 범위의 모양과 거리 및 각도, 거리 단위는 프로젝트 공통 단위를 추후 결정 |
| ReloadProfile | `reload_profile_id`, `capacity`, `reload_sec`, `reload_move_speed_ratio`, `automatic_reload`, `manual_reload`, `cancel_policy` | 장탄, 재장전 시간, 이동과 자동 및 수동 처리, 취소 시 진행 처리 |

`AttackStep`의 키는 `pattern_id`와 `step_index`의 조합이다. 순서는 1부터 시작하고 중간 번호가 비지 않도록 한다. 연격 횟수는 해당 패턴의 타격 행 수에서 계산한다. `Weapon`에 별도 연격 횟수를 중복 저장하지 않는 방식을 제안한다.

`combo_time`과 `cycle_time`, 평균 DPS는 입력 열이 아니라 계산 결과다. 기본 사이클은 타격별 세 시간의 합과 종료 공백의 합이다. 공격속도 적용 후 시간은 확정한 비례 축소 규칙으로 구한다. `attack_mode`에 따라 재장전이 쓰이지 않으면 `reload_profile_id`는 비워 두고, 재장전 방식이면 존재하는 프로필을 연결한다.

## 공통 전투와 마나

| 테이블 | 주요 열 | 문서에서 정의할 의미 |
| --- | --- | --- |
| CombatConfig | `config_id`, `combo_input_window_sec`, `attack_buffer_capacity`, `attack_speed_min_multiplier`, `attack_speed_max_multiplier` | 기본 입력 시간, 예약 개수와 공격속도 적용 범위 |
| DodgeConfig | `dodge_config_id`, `base_charge_count`, `recharge_sec`, `duration_sec`, `distance_walk_time_sec` | 기본 최대 충전 횟수와 재충전 시간, 대시 동작 전체의 무적, 평상시 이동 시간으로 표현한 거리 |
| HitResponseConfig | `hit_config_id`, `damage_protection_sec`, `interrupt_policy` | 피해 보호 시간과 경직 및 중단 처리 방식 |
| ManaConfig | `mana_config_id`, `max_mana`, `regen_per_sec`, `room_clear_regen_ratio_per_sec`, `room_clear_regen_rule` | 최대치, 자연 회복과 전투 종료 후 회복 계산 |
| Skill | `skill_id`, `mana_cost`, `motion_id`, `cooldown_sec` | 기술의 비용, 동작 참조와 재사용 대기 |
| MotionProfile | `motion_id`, `windup_sec`, `active_sec`, `recovery_sec`, `move_speed_ratio` | 능동 기술 동작의 준비와 판정 및 후딜, 이동 배율 |

`interrupt_policy` 같은 정책 열은 문서에서 정한 선택지 중 하나를 넣는다. 임의 문장이나 새로운 명령을 넣어 동작을 만들지 않는다. `room_clear_regen_rule`은 C15의 자연 회복과 빠른 회복 중 큰 값 기준을 사용한다. 실제 회복값은 후속 작업이다.

`attack_buffer_capacity`는 현재 확정 규칙상 1이어야 한다. 연결 시간의 기본 0.2초는 채택한 초기값의 출처를 유지한다. 공격속도 상한과 대시 및 마나의 구체적 값은 Excel 작성 시 후속 작업으로 정한다.

| CardEffect | `card_id`, `effect_id`, `order_index` | 카드가 제공할 여러 효과와 적용 순서 |
| SkillEffect | `skill_id`, `effect_id`, `order_index` | 기술이 제공할 여러 효과와 적용 순서 |

`AttackStep.damage_coefficient_ratio`는 무기 기본 타격의 계수다. `Effect.damage_coefficient_ratio`는 추가 피해 효과가 쓰는 계수로 구분한다. 능력치 효과는 `stat_id`와 적용 연산 및 `amount_value`를 사용한다. 해당 효과 종류가 쓰지 않는 열은 비워 두고 종류에 따른 필수 열을 검증한다. 효과별로 아직 표현하지 못하는 수치가 있으면 의미가 명확한 열 또는 전용 효과 테이블을 먼저 설계한다.

카드에 `effect_id_1`, `effect_id_2` 같은 열을 계속 늘리지 않는다. `CardEffect`에 연결 행을 추가한다. 능동 기술이 없는 카드의 `skill_id`는 빈 값으로 둔다. 표시 문구를 바꿔 실제 효과가 바뀌는 구조로 만들지 않는다.

## 태그와 조건

| 테이블 | 주요 열 | 문서에서 정의할 의미 |
| --- | --- | --- |
| Tag | `tag_id`, `tag_group` | 무기, 속성, 상태 이상, 행동 또는 신화 양식 분류 |
| TagGrant | `source_type`, `source_id`, `tag_id`, `points` | 어느 무기, 카드 또는 강화가 어떤 태그 점수를 주는지 |
| ConditionSet | `condition_set_id`, `group_join_mode` | 여러 조건 그룹을 모두 만족할지 하나 이상 만족할지 |
| ConditionGroup | `condition_group_id`, `condition_set_id`, `term_join_mode` | 그룹 안의 개별 조건을 AND 또는 OR로 묶는 방식 |
| ConditionTerm | `condition_term_id`, `condition_group_id`, `value_source`, `subject_id`, `compare_op`, `number_value` | 태그 및 장착 수 또는 보스 처치 등 요구 대상과 비교값 |

`TagGrant`의 키는 출처 종류, 출처 ID와 태그 ID의 조합이다. `source_type`에 따라 `source_id`가 Weapon, Card 또는 Upgrade를 가리키는지 검증한다. `subject_id`도 `value_source`에 맞는 테이블을 가리키도록 한다. 한 셀에 여러 태그를 쉼표로 나열하지 않는다.

`value_source`, `compare_op`와 AND 및 OR의 선택지는 별도 허용값 목록에서 관리한다. 지원하는 조건을 조합해 콘텐츠를 추가하고, 새 조건 종류가 필요하면 문서와 처리 규칙을 먼저 보강한다.

## 장인과 강화 및 신성

| 테이블 | 주요 열 | 문서에서 정의할 의미 |
| --- | --- | --- |
| Culture | `culture_id`, `content_review_status` | 신화 양식과 콘텐츠 채택 검토 상태 |
| Artisan | `artisan_id`, `culture_id`, `upgrade_pool_id` | 장인이 제공하는 양식과 강화 후보 풀 |
| Upgrade | `upgrade_id`, `weapon_family_id`, `stage_index`, `condition_set_id`, `cost_currency_id`, `cost_amount` | 호환 무기, 단계, 조건과 비용 |
| UpgradeEffect | `upgrade_id`, `effect_id`, `order_index` | 강화가 제공할 효과 |
| Divinity | `divinity_id`, `condition_set_id`, `card_pool_id`, `content_review_status` | 신성 진입 조건, 전용 카드 풀과 콘텐츠 검토 |
| DivinityStage | `divinity_id`, `stage_index`, `activation_event`, `condition_set_id`, `effect_id` | 성장 단계, 판정 시점, 조건과 단계 보상 |

`stage_index`의 의미와 최초 단계의 번호는 각 성장 문서에서 정한다. 장인의 제작 단계와 신성 성장 단계는 같은 번호여도 서로 다른 체계다. 비용이 없는 단계는 금액을 0으로 넣고 재화 ID의 필요 여부를 명시한다.

신격 이름이 채택되지 않은 행은 검토 상태를 유지한다. 실제 숭배 신격 제외 원칙에 맞춰 사용 가능한 콘텐츠를 확인하며, 데이터 행을 추가했다는 이유만으로 채택이 끝난 것으로 보지 않는다.

## 보상과 던전 및 영구 성장

| 테이블 | 주요 열 | 문서에서 정의할 의미 |
| --- | --- | --- |
| RewardPool | `pool_id`, `selection_count`, `duplicate_policy` | 선택 후보 수와 중복 처리 |
| RewardEntry | `pool_id`, `entry_id`, `content_type`, `content_id`, `weight`, `condition_set_id` | 카드 또는 강화 또는 재화 후보와 등장 가중치 및 조건 |
| Stage | `stage_id`, `map_pool_id`, `boss_id` | 스테이지의 맵 후보와 보스 |
| Map | `map_id`, `room_sequence_id` | 맵이 사용할 방 진행 구조 |
| RoomSequence | `room_sequence_id`, `node_index`, `room_pool_id` | 방 진행 구조의 노드와 후보 풀 |
| RoomEdge | `room_sequence_id`, `from_node_index`, `to_node_index`, `condition_set_id` | 같은 진행 구조 안의 다음 방과 분기 연결 |
| Room | `room_id`, `room_type`, `enemy_pool_id`, `reward_pool_id`, `facility_profile_id` | 방 종류, 적과 보상 및 시설 연결 |
| FacilityProfile | `facility_profile_id`, `facility_type`, `offer_pool_id`, `recover_hp_ratio` | 시설 종류, 제시할 후보 또는 회복량, 종류에 필요한 열만 사용 |
| Enemy | `enemy_id`, `archetype_id`, `hp`, `attack_power`, `appearance_id` | 기존 적 행동을 이용한 종류와 수치 및 외형 변형 |
| EnemyArchetype | `archetype_id`, `behavior_type`, `attack_pattern_id` | 지원하는 적 행동과 공격 패턴, 새 행동은 규칙을 먼저 기획 |
| Resource | `resource_id`, `resource_type`, `asset_key` | 외형 등 게임 리소스의 참조 키, 실제 연결 방식은 후속 구현 |
| Currency | `currency_id`, `persistence_type` | 런 내 또는 영구 재화 분류 |
| RunSettlement | `settlement_id`, `result_type`, `retain_ratio`, `bonus_pool_id` | 사망과 클리어 및 포기의 정산 |
| PermanentUpgrade | `permanent_upgrade_id`, `effect_id`, `effect_value_field`, `max_level` | 영구 성장의 효과와 단계, 단계별로 달라지는 효과 열 |
| PermanentUpgradeLevel | `permanent_upgrade_id`, `level`, `cost_currency_id`, `cost_amount`, `effect_value` | 단계별 비용과 효과값 |

`map_pool_id`, `room_pool_id`, `enemy_pool_id`는 같은 RewardPool 구조를 임의로 섞어 쓰지 않고 MapPool, RoomPool과 EnemyPool의 별도 후보 목록을 연결하는 안으로 둔다. 후보 목록은 각각 pool ID, 콘텐츠 ID, 가중치와 조건의 같은 형태를 사용한다. `boss_id`는 Enemy의 존재하는 ID를 가리키고 `appearance_id`는 Resource의 존재하는 resource ID를 가리킨다. RoomEdge의 시작과 도착 번호는 같은 진행 구조 안에 존재해야 한다.

`PermanentUpgradeLevel.effect_value`는 연결한 Effect 중 `effect_value_field`로 지정한 한 수치 열의 단계별 값이다. 예를 들어 능력치 변화량을 다르게 하는 성장이라면 `amount_value`를 가리킨다. 단위는 해당 효과와 StatDefinition의 정의를 따른다. 여러 수치 열이 동시에 달라지는 성장은 별도 연결 행을 설계하고 한 값으로 임의 해석하지 않는다.

공용 `weight`는 확률 그 자체가 아니다. 해당 상황에서 조건을 통과한 후보들의 가중치 합으로 나누어 추첨 비중을 계산한다. 수급량과 비용은 Excel에서 작성하고 보상 보장, 조건 검사와 중복 처리 규칙은 문서에서 정한다.

## 값과 참조의 검증

필수 열과 ID의 빈 값, 중복 키, 없는 대상 참조, 비활성 또는 미채택 콘텐츠를 사용하는 활성 행을 확인한다. 초 단위 시간과 비용 및 계수는 음수가 아니어야 한다. 대시 무적 구간은 대시 동작 전체와 일치해야 하고 장탄과 슬롯은 양의 정수여야 한다. 설정된 예약 개수는 확정 규칙을 충족해야 한다.

선택 참조의 빈 값은 기능 없음으로 해석한다. 필수값이 비면 오류로 처리하며 임의의 0으로 메우지 않는다. 값 0, 빈 값과 사용 안 함을 같은 의미로 섞지 않는다. 실제 검증 및 Excel에서 게임으로 읽어오는 방식은 후속 구현 작업이다.

## 조준과 이동 규칙의 연결

`Weapon.attack_move_speed_ratio`는 평상시 속도 대비 기본 공격 준비·판정·후딜의 이동 배율이다. 실제 값은 Excel 후속 작업이다. 연결 대기와 중단 및 종료 공백에는 정상 이동을 적용하고 재공격 대기는 유지한다. 조준 갱신과 실행 순간의 방향 고정, 근접 판정의 위치 추종 및 기본 투사체의 독립적인 진행은 [[02 전투/조준과 이동 설계안|조준과 이동 규칙]]에 따라 처리하며 감속 값으로 해당 규칙을 변경하지 않는다.

## 대시 충전 데이터의 연결

충전 횟수와 재충전 제한 및 빌드 증가는 채택했다. 열 이름과 상세 자료형 및 읽는 시점은 연결 초안이다.

| 열 | 자료형과 단위 | 의미 |
| --- | --- | --- |
| DodgeConfig.base_charge_count | 정수, 횟수 | 기본 최대 충전 횟수, 실제 값은 Excel에서 작성 |
| DodgeConfig.recharge_sec | 실수, 초 | 순차 충전으로 1개를 회복하는 시간, 실제 값은 Excel 후속 작업 |
| Effect.stat_id | 텍스트 ID | 최대 충전 횟수 증가 능력치를 StatDefinition에 연결 |
| Effect.operation | 허용값 | 증가량 적용 연산, 중첩 규칙과 함께 후속 정의 |
| Effect.amount_value | 해당 능력치 기준 숫자 | 빌드에 의한 최대 충전 횟수 증가량 |

현재 충전 횟수와 남은 시간은 실행 중 상태다. Excel의 설정 열과 혼동하지 않는다. 충전은 타이머 하나로 1개씩 순차 진행하고 추가 사용으로 타이머를 초기화하지 않는 방식으로 확정했다. 최대 횟수에 도달하면 충전을 멈춘다. recharge_sec는 1개당 충전 시간이며 전체 충전 시간으로 해석하지 않는다. 남은 충전 횟수가 있으면 재충전 중이라는 이유만으로 대시를 금지하지 않는다.

## 대시와 기본 공격 독립 실행의 데이터 연결

`Weapon.attack_move_speed_ratio`는 일반 이동의 공격 중 감속이다. 대시 이동에는 이 배율을 곱하지 않고 `DodgeConfig`의 대시 이동 설정을 사용한다. `AttackStep`의 준비·판정·후딜과 `AttackPattern.combo_end_gap_sec`는 대시와 독립적으로 진행한다. `CombatConfig.attack_buffer_capacity`는 기존대로 공격 예약 하나를 뜻하며 대시 예약과 공유하는 개수가 아니다.

동시 실행과 상대 예약 삭제 금지는 기획 규칙이며 수치 행을 추가하여 선택적으로 켜는 기능으로 정의하지 않는다. 대시 예약은 C02, 재장전은 C14, 능동 기술 전환은 C11과 D07을 따른다. 실제 유지 시간은 후속 데이터다.

## 적 강공격의 데이터 연결 초안

Enemy와 EnemyArchetype의 행동 연결 및 AttackPattern·AttackStep·AttackShape의 동작과 범위 구조를 사용한다. 준비 시간은 AttackStep.windup_sec, 공격 후 빈틈은 해당 타격의 recovery_sec와 패턴의 종료 공백에서 읽으며 중복된 총 시간을 입력하지 않는다. 적의 시간과 반복 공격 규칙이 플레이어 연격 규칙과 같다고 가정하지 않는다.

| 연결 초안 | 주요 열 | 의미 |
| --- | --- | --- |
| EnemyAttackOption | archetype_id, attack_option_id, pattern_id, condition_set_id, telegraph_id | 적 행동 유형의 공격 후보와 시작 조건 및 예고 |
| Telegraph | telegraph_id, resource_id | 준비 자세와 범위 등 예고 리소스 |
| EnemyStaggerRule | archetype_id, attack_option_id, phase, resistance_mode | 일부 강공격 준비의 약한 경직 저항과 적용 단계 |
| AttackStep 추가 열 | knockback_units | 대상에게 주는 밀려남 거리, 단위는 프로젝트 거리 단위 후속 정의 |

각 참조는 EnemyArchetype·AttackPattern·ConditionSet·Resource 및 해당 공격 후보의 존재하는 ID를 연결한다. 열과 테이블 이름은 제안이며 실제 Excel은 아직 작성하지 않는다. 필수 여부와 저항 허용값 및 예고 표현, 밀려남의 처리 우선순위는 행동 규칙을 확정한 뒤 보강한다. 플레이어를 공격 취소시키는 효과는 강공격 후보라는 이유만으로 자동 부여하지 않는다.

## 대시 무적과 밀려남 유지의 데이터 연결

대시 무적 구간은 실제 대시 시작과 종료에 연결한다. 기본 대시의 invulnerability_sec를 duration_sec와 별도 입력해 서로 다른 구간을 만들지 않는 방식으로 열 정의를 수정한다. duration_sec의 실제 값은 Excel에서 작성하고 실제 대시 동작 시간이 변경되면 무적도 해당 동작 전체를 따른다. 무적 상태가 적의 피격을 무시하는 규칙과 밀려남이 진행 타격을 취소하지 않는 규칙은 수치 열이 아니라 기획 규칙이다. knockback_units와 타격 시간 열은 기존 의미를 유지한다. 바닥·지속 피해는 C08, 기절은 C07·D06, 입력과 예약 경계는 D02·D04를 따른다.

## 밀려남 입력과 대시 탈출의 데이터 연결

밀려남 중 입력 허용과 공격 예약 유지, 충전이 있을 때 즉시 대시로 밀려남을 종료하는 처리는 기획 규칙이다. DodgeConfig.base_charge_count와 recharge_sec, AttackStep.knockback_units 및 기존 타격 시간의 의미는 유지한다. 밀려남 거리와 시간의 실제 값은 Excel에서 작성한다. 일반 이동 입력과 대시 탈출을 구분하고 충전 0개에서 새 대시 입력을 저장하지 않는 조건을 검증한다. 별도 기절·사망은 C07·D06, 연속 피격은 C05·C06을 따르고 이전 잔여 밀려남을 합산하지 않는다.

## 연속 피격 갱신의 데이터 연결

밀려남 갱신은 기획 규칙으로 고정한다. 새 유효한 밀려남 판정이 발생할 때 새 공격에 정의된 방향·거리·시간을 읽어 현재 위치에서 적용하며 이전 잔여량을 더하지 않는다. AttackStep.knockback_units는 밀려남 거리의 의미를 유지한다. 지속 시간과 방향 열은 knockback_duration_sec와 knockback_direction_mode를 쓰고 C06을 따른다. 실제 값은 후속 Excel에서 작성한다. 남은 거리·남은 시간·현재 밀려남 방향은 실행 중 상태이며 Excel의 고정 콘텐츠 값과 구분한다. 동일 공격 중복·피격 보호·동시 순서는 C04·C05 및 D04·D05를 따른다. 실제 보호 시간은 후속 데이터다.

추가 테이블은 다음 참조 열로 연결한다. `AttackStep.damage_profile_id`와 피해 Effect의 `Effect.damage_profile_id`는 DamageProfile을 참조한다. 상태 부착 Effect의 `Effect.status_profile_id`는 StatusProfile을 참조하고, 투사체 AttackStep의 `AttackStep.projectile_profile_id`는 ProjectileProfile을 참조한다. 지원하지 않는 행동의 참조는 빈 값이며 해당 행동을 사용하면 존재하는 ID가 필수다. `pierce_count`는 첫 대상 이후 추가 통과 수로 정의한다. 기존 EnemyStaggerRule의 약한 경직 구간 설정은 StaggerProfile로 통합하며 같은 구간의 저항을 두 테이블에서 이중 입력하지 않는다.

공격 실행 ID·대상별 치명타 결과·실제 HP 감소량·출처 root·상태 종료 시각·첫 틱 시각·강공격 허가 점유·비용 예약·사망 사건 ID는 실행 중 상태다. 정적 Excel의 입력값으로 저장하지 않는다. 열의 필수 여부는 해당 종류의 사용 조건에 따라 검사하고 없는 참조·중복 ID·미지원 허용값은 오류로 처리한다.

## v0.23 사건과 자원 및 유지 상태 연결

아래는 기존 필드의 의미 보강과 필요한 연결이다. 실제 Excel 값·종류별 행은 아직 작성하지 않는다. 데이터의 허용값만으로 공통 기획 규칙을 바꿀 수 없게 한다.

| 필드·관계 | 의미·제약·읽는 시점 |
| --- | --- |
