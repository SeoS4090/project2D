# Excel과 기획 문서의 연결
## 정한 관리 방향

게임 수치와 콘텐츠의 종류 및 변형은 추후 게임데이터 Excel에서 작성한다. Obsidian은 규칙, 수치가 뜻하는 것, 데이터 연결과 제약을 관리한다. 이전 문서의 미확정 수치는 설명과 비교를 위한 제안 기록이며 실제 게임데이터의 기준값으로 사용하지 않는다. 이미 채택한 연결 허용 시간 기본 0.2초는 기존 결정 기록에 남기고, 추후 Excel을 만들 때 초기값의 출처로 반영한다.

현재 실제 Excel 파일은 아직 만들지 않았다. 아래 논리 테이블명, 열 이름과 연결 방식은 검토안이며, 파일명과 시트 구성은 Excel 작성 시 확정한다. 문서만으로 Excel과 게임 사이의 자동 동기화가 된다고 가정하지 않는다.

## 문서와 Excel의 역할

| 내용 | 관리 위치 | 기획 문서에서 다룰 내용 |
| --- | --- | --- |
| 연격 연결과 준비 중 취소 | 기획 문서 | 처리 순서, 상태와 예외 |
| 준비 및 판정 및 후딜의 실제 시간 | Excel | 각 열의 뜻과 단위, 공격속도 적용 여부 |
| 무기와 카드 및 신성의 종류 | Excel | 분류 기준, 허용된 효과와 관계 |
| 마나의 회복 및 소비 규칙 | 기획 문서 | 회복 시작과 종료, 소비 시점 |
| 최대 마나와 회복량 및 소비량 | Excel | 참조 열과 계산 방식 |
| 덱 슬롯과 장탄 및 성장 조건의 수치 | Excel | 값에 따른 행동과 제약 |
| 새로운 행동과 발동 규칙 | 기획 문서에서 먼저 설계 | 기존 데이터 표현으로 가능한지 판단 |

예약 입력을 하나만 저장한다는 확정 규칙처럼 숫자 자체가 행동 규칙인 경우에는 Excel로 값을 옮겨도 문서의 제약을 유지한다. 값 변경으로 규칙을 바꾸려면 기획 결정도 함께 갱신한다. 초안의 슬롯 수, 대시 시간, 피해 계수와 보상률은 별도 Excel 작업 대상으로 둔다.

## 연결 식별자의 제안

문서는 파일, 논리 테이블, 고정 행 ID와 열 이름을 사용해 데이터를 가리킨다. 행 번호와 셀 주소는 정렬 및 행 삽입에 따라 바뀌므로 내용의 식별자로 사용하지 않는다.

| 연결 수준 | 표기 방식 | 용도 |
| --- | --- | --- |
| 규칙과 열 | `AttackStep.windup_sec` | 모든 공격 준비 시간의 의미 |
| 규칙과 특정 콘텐츠 | `Weapon.weapon_id`의 특정 ID | 개별 무기의 기획 연결 |
| 복수 키로 된 행 | `AttackStep(pattern_id, step_index)` | 한 연격 안의 특정 타격 |
| 실제 파일 | 파일명과 버전 또는 revision | 어느 Excel의 데이터를 보는지 확인 |

실제 파일이 정해지면 각 기획 문서에 파일 위치를 한 번 연결한다. 작업 수치는 문서에 반복 복사하지 않고 필요한 콘텐츠 ID 또는 열을 표시한다. 보고용 수치표를 출력하는 경우에는 데이터 버전을 함께 적고 해당 표가 Excel에서 갱신되는 사본임을 표시한다.

## 각 문서에 추가할 데이터 참조 형식

| 항목 | 적을 내용 |
| --- | --- |
| 데이터 원본 | 실제 Excel 파일과 버전, 현재는 작성 예정 |
| 테이블 | 관련 논리 테이블명 |
| 행 식별자 | 콘텐츠 ID 또는 설정 ID |
| 사용 열 | 열 이름의 목록 |
| 읽는 시점 | 연격 시작, 타격 실행, 장착 변경 등 |
| 계산 규칙 | 비례 축소, 합산, 최대값 선택 등 |
| 연결 대상 | 다른 테이블을 가리키는 ID 열 |
| 검증 | 허용 범위, 존재하는 참조, 확정 규칙의 제약 |

Obsidian 속성에는 `data_status`, `data_tables`, `data_fields`를 사용한다. 실제 파일이 생기기 전 `data_status`는 Excel 작성 예정으로 두고 존재하지 않는 파일에 wikilink를 만들지 않는다.

## 앞으로 기획할 순서

먼저 행동과 연결 규칙을 결정하고 그 규칙이 요구하는 열을 정의한다. 이후 Excel에서 종류, 수치와 변형을 추가한다. 입력한 데이터가 기존 규칙으로 동작하는지 검증한 뒤 시험한다. 값만 바꾸는 밸런스 작업과 새로운 열 또는 행동을 요구하는 기능 변경은 구분해서 이력을 남긴다.
