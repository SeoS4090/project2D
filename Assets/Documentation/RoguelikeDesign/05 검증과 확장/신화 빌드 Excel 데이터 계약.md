# 신화 빌드 Excel 데이터 계약

## 파일과 적용 범위

[MythBuildData.xlsx](../09%20게임데이터/MythBuildData.xlsx)는 [[03 빌드와 무기/신성 테마와 무기 성장 계보]] build-0.3의 작성용 데이터다. 7신, 1차 7종, 2차 10종, 3차 18종, 성장 연결 28개, 효과 프로필 46개, 카드 후보 14개를 포함한다. 효과 프로필은 기본 기능 28개와 신성 공명 18개로 분리한다. 개별 콘텐츠 채택이나 플레이 검증 완료를 의미하지 않는다.

기존 Unity 로더가 사용하는 CommonInstant·Item·Hero와 별개이며 자동 가져오기는 연결하지 않았다. 모든 콘텐츠의 enabled는 false다. 이번에 세부 밸런스 값을 임의로 확정하지 않았다.

## ID와 연결

- 고정 문자열 ID를 기본 키로 사용한다. 이름은 Text의 name_key로 연결하고 행 번호나 표시 이름을 참조 키로 쓰지 않는다.
- WeaponFamily → Weapon → ProgressionEdge → Upgrade로 성장 계보를 구성한다. Upgrade.stage는 정수 2 또는 3이다. 인접 단계·같은 무기 종류·도달 가능성과 순환 여부를 검사한다.
- UpgradeEffect는 Upgrade와 Effect를 연결한다. 기본 기능과 조건부 신성 공명을 별도 행으로 관리한다. 신성 공명만 divinity_id와 최소 신성 단계를 갖는다.
- 강화의 기본 기능은 replace_parent_base로 교체한다. 이전 단계 효과를 자동 누적하지 않는다.
- CardCandidate는 카드 방향 후보다. 정식 카드 효과와 태그 부여 테이블을 완성한 것으로 간주하지 않는다.
- 전체 열과 자료형은 Schema 시트 및 저장소 루트 Tools/GameData/myth_schema.json을 따른다.

## 숫자 계약

NumericValue의 복합 키는 (owner_table, owner_id, parameter_id)다. ParameterDefinition에서 자료형, 단위, 허용 최솟값·최댓값, 0 허용 여부를 정의한다. 숫자 셀에는 단위 문자열을 붙이지 않는다.

| 항목 | 표현 |
| --- | --- |
| 미정 | value를 비우고 value_status=pending |
| 가설 수치 | 실제 숫자와 provisional, 근거 기록 |
| 확정 수치 | 실제 숫자와 fixed, 결정 근거 기록 |
| 비율 | ratio의 1이 100% |
| 시간 | sec, 초 단위 |
| 횟수·순서·단계 | 정수 |
| 거리 | world_unit; 실제 월드 축척은 후속 확정 |

0은 실제 0이며 미정 대용으로 쓰지 않는다. 현재 총 179개 중 175개는 pending으로 비어 있다. 4개의 0 마나 소비 항목만 기존 규칙의 근거와 함께 fixed다. 빈 값을 런타임에서 0으로 자동 변환하지 않는다. 수치가 필요한 기능은 확정·변환·검사를 완료한 뒤 활성화한다.

## 확장 절차

1. 기존 ID를 유지하고 새 콘텐츠에 새 ID를 부여한다. 삭제·대체 시 참조를 먼저 확인한다.
2. 관련 Text, 성장 연결, 기본/공명 Effect 및 UpgradeEffect 행을 함께 추가한다.
3. 새 종류의 숫자는 ParameterDefinition을 먼저 추가하고 NumericValue의 자료형·단위·상태를 입력한다.
4. Excel 표 범위와 유효성 검사 범위를 새 행까지 확장한다. 요약 수식은 각 테이블의 2~1001행을 참조하므로 1,000개 초과 시 범위를 늘린다.
5. Lineage와 Audit은 새 경로·검사 행을 명시적으로 추가한다. 여러 부모를 가진 성장 연결은 데이터 구조상 가능하지만 현재 계보 표시 수식은 단일 부모 기준이므로 표시 로직도 확장한다.
6. 검증기를 실행하고 Pending을 확인한다. 콘텐츠 추가가 실행 가능한 효과 구현까지 자동으로 만들어 주지는 않는다.

## 실제 검사 결과 — 2026-10-12

- 저장된 XLSX를 다시 읽어 기본/복합 키, 외래 키, 계보 단계·무기 종류·순환·도달 가능성, 효과 계층, 수치 자료형·범위·미정 상태, build-0.3의 35개 계보 포함 여부를 검사했다. 오류 0개.
- 저장된 Excel 수식 오류 0개. 작성 엔진에서 8번째 신격을 잠시 추가했을 때 요약 수식이 8로 변하고 복원 후 7로 돌아옴을 확인했다.
- 누락 참조·중복 키·순환·다른 무기 종류·미정 셀의 0·잘못된 숫자·음수 입력을 복사 데이터에 주입해 각각 탐지했다. 유효한 확장 사례도 통과했다.
- 21개 시트를 이미지로 출력해 가독성을 확인했다. 네이티브 Excel 앱 조작이나 Unity 플레이 테스트는 실시하지 않았다.

재검사: 저장소 루트에서 `python Tools/GameData/validate_myth_workbook.py "Assets/Documentation/RoguelikeDesign/09 게임데이터/MythBuildData.xlsx"`를 실행한다. 현재 작성 계약은 콘텐츠 enabled=false를 요구하므로 런타임 전환 시 계약도 명시적으로 개정한다.

## 남은 작업

원자 효과의 trigger_event·target_rule·operation 분해, 신성 성장 조건, 태그 부여, 공격 단계/판정 모양, 장인과 비용 재화 연결, 실제 밸런스 수치, Unity 가져오기와 플레이 검증이 남아 있다. 세부 항목은 Excel Pending 시트를 따른다. 기존 [[05 검증과 확장/게임데이터 열 정의]]와 [[05 검증과 확장/게임데이터 관계와 추가 절차]]는 전체 게임 설계를 위한 후속 범위를 포함한다.
