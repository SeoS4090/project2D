사용자 승인 범위: 기존 이동·대시·공격 규칙을 유지하고 대시 경과 시간과 물리 이동 기준을 일치시킨다. 공격 시간/전이 로직, 데이터 수치, 충전 회복의 Update 갱신은 변경하지 않았다.

### 변경 내용

- `DashMotionClock.cs`: 실제 물리 스텝이 실행될 때만 남은 대시 시간을 소비한다. 한 스텝을 기존 대시 시간·연결 대시 시간·일반 이동 시간으로 나누고 합이 스텝 시간과 같게 유지한다.
- `TrainingPlayerController.FixedUpdate`: 각 구간의 속도 × 시간을 더한 변위를 스텝 시간으로 나누어 Rigidbody2D.linearVelocity에 적용한다. 예를 들어 0.02초 중 대시가 0.015초 남으면 나머지 0.005초에만 일반 이동을 적용한다. Transform 직접 이동이나 전역 물리 시뮬레이션 설정은 사용하지 않는다.
- 새 입력은 계속 Update에서 읽는다. 대시 중이 아니면 즉시 시작 상태로 만들고 첫 물리 스텝부터 시간과 이동을 함께 소비한다. 이 방식으로 buffer=0의 즉시 입력도 유지한다.
- 대시 중 예약 입력은 FixedUpdate의 대시 종료 경계에서 검사한다. 유효하면 그 스텝의 남은 시간을 다음 대시에 사용한다. 다음 대시 방향은 이 실행 시점의 이동 입력 → 마지막 이동 방향 → 조준 방향 순서로 결정하며 충전은 한 번만 차감한다.
- 예약 만료는 계속 unscaled 초다. FixedUpdate가 처리하는 구간은 fixedUnscaledTimeAsDouble - fixedUnscaledDeltaTime부터 해당 스텝 끝까지로 매핑한다. DashInputBuffer에 입력 시각을 추가해 과거 물리 구간이 미래의 입력을 소비하지 않게 했다.
- ResetTrainingState는 물리 대시 시간과 예약을 함께 비운다. 공격과 차지를 취소하지 않는 기존 동시 실행 구조는 그대로다.

- Rigidbody에 스텝당 평균 속도 하나를 넣으므로 한 스텝 안에서 반대 방향으로 연결되면 왕복 구간이 하나의 순변위로 합쳐진다. 최종 위치와 시간은 보존하지만 물리 엔진이 중간 경유점까지 따로 검사하는 것은 아니다. 벽 근처 방향 전환/타격의 정확한 경로 검증은 남아 있다. 충돌 없는 같은 방향 4.16 결과를 반대 방향 경로 길이 보장으로 해석하지 않는다.
- 실제 입력은 렌더 프레임에서 관측하고 이동은 다음 물리 스텝부터 반영되므로 입력 관측 지연까지 FPS와 무관하다는 주장은 하지 않는다. 일시정지/시간 배율 변경 중 실제 Unity 시계 매핑도 후속 플레이 항목이다.
